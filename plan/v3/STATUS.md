## 已做的代码改动

- 冷启动不再请求上游 GitHub 检查更新；AI、云同步、更新检查默认关闭（R01）。模拟器上按 UID 看内核流量：fork 冷启动→设置→后台→deep link 全程 0 条，原版冷启动即有（BAS02）。
- 选了代理就必须经代理，配置无效或代理失败一律报错，不静默直连（R03）；终端输出不再因切包乱码；断线恢复不重跑启动命令。
- 连接前一次算好不可变的路线（R05）：矛盾、循环、超 3 跳、非法地址端口都在拨号前拒绝；保险库格式不变，仍能和桌面端同步。
- SOCKS5 加固（R06）：配了口令不降级为无认证、回复严格校验、失败码逐个说清、取消即关、各阶段有期限。顺带绕过 dartssh2 2.22.5"SSH 版本行被拆包就断开"的缺陷。
- 代理入口 + 跳板（R07）：目标上同时配代理和跳板时，代理只用于连第一跳；每一跳失败都报出哪台机器、哪一步；服务器指纹变了一律阻断（只能删除旧指纹后重连重新核对）。
- 连接代次与资源所有权（R08）：每个标签一次只有一个有效的连接尝试，取消、关标签、应用退出都会让它失效，迟到的结果一律关掉；断线、失败、取消都把已建好的连接连同跳板释放干净。真实 OpenSSH 上 100 轮（另跑 500 轮）连接/取消/恢复/关闭/销毁，fd 和服务器侧连接都不增长。连接回写不再冲掉用户中途的编辑、不再复活已删主机。取消后不再误弹「已连接」。
- 凭据与入口统一（R09）：终端、SFTP、监控、系统管理、端口转发经代理/跳板/直连都只用这一条已验证连接（真实 OpenSSH 验证）；私钥在拨号前解析并自签自验（能识别密文被改）；keyboard-interactive 不再把密码填给验证码之类的提问；信任按主机名规范写法比对；主机对象的调试输出和导出不再含明文凭据；凭据解不开时不再拖垮整个保险库；连接瞬间失败不再让 App 被系统杀掉（上游就有）；SFTP 握手 10 秒期限；备份和换机迁移排除全部数据。
- 连接路径编辑器与最小 SSH 闭环（R10）：编辑器里直连 / 经代理 / 经跳板机三选一，「先经代理再走跳板」是显式高级开关；实时显示连接时会怎么走，矛盾配置不让保存；「测试连接」按未保存的配置核对指纹、登录，只检查远端 PTY（`/dev/pts/N`），不开 shell、不执行启动命令；失败页显示实际路线和下一步。模拟器上全程用界面走通了新建主机、经 SOCKS 代理、导入私钥、密码填错、正式连接敲 `tty`。顺带修了上游「选一次跳板机就红屏」。
- 只读 Tailscale 目录的 HTTP 适配（R11，还没有界面）：只发换 token 和列设备两种请求，只要 `devices:core:read`，不跟随任何重定向，401 只受控刷新一次，429/403 不重试。粘贴的 token 读完即丢、一律「范围未验证」；自己的 OAuth client 只在你要求且服务器确认只读时才存，存在和保险库分开的加密文件里。没有 Tailscale 账号，全部用本机假 API 验证（模拟器上也跑过，私有目录和日志里搜不到任何凭据）。
- 目录缓存（R12）：每个来源的设备记录存本机，刷新只加、只改、只标「不见了」，从不删；不完整、空列表、出错都不动已有记录。导入的主机只有地址会跟着目录变，而且只在你没改过地址时；用户名、端口、路由、指纹信任一概不碰。两个来源即使都写 `-` 也不合并。
- 目录页与批量导入（R13）：「设置 → Tailscale 设备目录」读设备列表（粘贴 token 读一次，或自己的 OAuth client、可选保存），显示缓存时间、列表是否完整、最近失败原因；设备只说 Tailscale 控制面「已连接 / 未连接 / 不知道」，不说在线。勾选设备批量导入为主机：用户名必填不默认 root，路线可选直连 / 代理 / 跳板，不写指纹、不连接。编辑器里看得到来源、目录状态、地址是否跟随，可断开关联。模拟器上用真实界面 + 本机假 API 走通，导入的主机真 SSH 进测试环境；连接失败按网络 / 代理 / 指纹分别报出。
- UU 远程（X06）：按冻结的官方协议（提交 be7d8109）做了绑定和全屏/小窗远控。请求只发给已核对证书的官方包名；回调只认一次性的 state/nonce，重放、迟到、伪造都不算数，UU 在前台时本 App 被杀、回调冷启动也能对上；绑定回来要你确认挂到哪台主机，之后从不自动远控；全屏只写「已交给 UU」，小窗只写 UU 报告的结果，不说「已连接」；主机 SSH 经代理/跳板时先说明 UU 走它自己的网络。加密设备标识只存本机加密存储，不进保险库和导出。手机上有别的 App 也声明了本 App 的回调地址时（它能截走、冒充 UU 的回报），绑定和小窗不发，已到的绑定结果不采用。官方 4.42.0 APK 的证书已固定进代码，官方包不用手动批准。模拟器上用假 UU 把本 App 这一侧都走通了；真实 UU 只在没登录的状态下试过：它停在登录页、不给任何回报（官方文档说 180 秒后回超时，实测 6 分钟没有），所以等待到 10 分钟会自己作废。**登录真实账号之后的绑定和远控一次都没走过**（UUR03/04/05/07 BLOCKED）。
- Tailscale SSH（R14）：编辑器里明确选「Tailscale SSH」才用，不看 100.x、不看目录导入。这种主机只发 none 认证，存着的密码、私钥不发、私钥不解密。check 链接只在指纹确认后才认，只认 `https://login.tailscale.com/a/…` 一种样子，卡片只显示域名、写明来源节点和截止时间，用户点了才交给浏览器，回到 App 不算通过；不合规的（别的域名、http、多条、夹控制字符，以及 Headscale 的链接）不给打开。等 check 最多 10 分钟；拒绝、超时、取消都有准确的说法（Tailscale 拒绝时只发 banner 就断 TCP，原来会被说成「对方可能不是 SSH 服务」）；自动恢复碰上 check 停下、不再重试。普通模式下 dartssh2 自动补发的 none 被放行时断开，碰上 check 链接立刻断开。真 tailscaled（Headscale 控制面）上实测：check 批准/拒绝、来源节点就是 SOCKS 出口那台。**官方 Tailscale 的 check 网页没走过**；**普通模式填错密码连 Tailscale SSH 的 22 端口也能进**（tailscaled 不看密码），App 分不出来。
- 计划外修复（R14 时发现）：保险库密码曾会写进 UU/RustDesk/目录的加密存储文件，重启后报「无法解密」（flutter_secure_storage 9.2.4 Android 端切了文件名不切回来，X05 起就有）。保险库存储现在显式写默认文件名；已写错地方的不搬。
- RustDesk（X07）：给主机填 RustDesk ID，点「用 RustDesk 远控」交给手机上的 RustDesk 去连。只发一种链接 `rustdesk://connect/<ID>`：ID 只收纯数字或字母开头的自定义 ID，带服务器、密钥、强制中继、IP、整条链接的都拒收；平台层发送前按同一条白名单再核一次，绕过 Dart 直接调也发不出带密码或改配置的链接（模拟器上实测 19 种）。只发给官方包名 + 核对过的证书（GitHub 发行版、F-Droid 各一张，从安装包读出）；别的证书、改了包名的自建客户端要用户看过包名和证书后明确信任，换签就停。RustDesk 不回报任何结果，页面只写「已交给 RustDesk」和交给了哪个包哪个版本，从不写已连接或已断开；SSH 经代理/跳板的主机先问。版本按冻结的 1.4.9 源码分段：1.2.3 及更早不发，1.4.6 及更早提醒它会执行别的 App 发来的改密码/改服务器链接，高于 1.5.0 写明没核对过。真实 RustDesk 1.4.9 在模拟器上冷启动、已开着两条路都实测过（连一个不存在的 ID，它自己报「离线或不存在」，本 App 这边不变）；**真连上一台电脑没做**。RustDesk 自己会把收到的链接（含 ID）打进 logcat。
- Tailscale 目录接入插件体系（X05）：成了和内置 SSH 一样的内置 provider `builtin.tailscale`，每个目录操作先向注册表要能力；HTTP、缓存、导入规则没动。目录这边只看得到主机的 id、名字、地址和目录绑定，碰不到密码、代理口令。设备关联就是主机上的目录绑定（在保险库里，重启不丢），没另存一份。新增两条修复路径：「关联到已有主机」（只记关联，地址不跟随、不连接）和「在本机恢复」被移除的来源（按原来源 ID，读一次就重新对上）。模拟器上走通了重启、移除来源后照常 SSH、恢复后重新对上；目录凭据和粘贴的 token 在私有目录和日志里搜不到。
- 插件管理（X04）：插件页开着就跟踪包的安装、更新、卸载，系统一报告就重新核验证书和描述符：普通更新仍可用、多申请能力回到待批准、API major 变了不兼容、换签被拒，不自动扩大批准；确认框开着时包变了就拒绝批准。详情页写全来源、证书、两种版本、能力、路线、权限；停用跨重启保留、启用不用再批；插件可声明自己的设置页，宿主查出组件后显式打开、不带 extras。模拟器上逐项实测。
- 插件会话（X03）：终端字节走宿主建的 socketpair，不经 Binder；每一段都有上限（宿主最多压 5 块 × 16 KiB 输出、替插件排 1 MiB 输入），插件不读宿主就不写。会话句柄和代次由宿主生成，两边逐事务核对；迟到的事件不能让已关的会话复活。插件不理关闭时如实记「停止未确认」。模拟器上实测：强杀插件只影响它自己的会话（SSH、SFTP、另一个插件照常），强杀宿主后插件清掉宿主开的会话。echo 只是测试插件，不是 Mosh。
- Android 独立插件（X02）：「设置 → 插件（实验）」列出声明了本 App 插件接口的 App，批准前不启动它们；批准时核对证书。插件和宿主在每次 Binder 调用里互相核对对方的 UID 和证书——模拟器上实测：流氓 App 拿到 Binder 也调不动插件，拿到转交来的宿主回调也调不进宿主；同包名换签、冒用内置 ID、调试证书签的插件进 release 宿主都被拒。echo 只是测试插件，不是 Mosh。
- 插件契约 v1 落成 `packages/plugin_api`（X00）。
- 主 App 接入轻量插件注册表（X01）：内置 SSH/路由构造时即可用，不等任何插件发现；外部包冒用内置 ID、自称内置、同 ID 抢位都被拒；停用/撤销/换签/卸载只关该插件自己的会话。顺带补了契约漏洞：单独安装的包自称 `bundled` 原先能跳过用户批准和证书核验。

- 官方 Tailscale 的 check（可选）：需要一台开着 Tailscale SSH、策略设 check 的机器，手机上开官方 Tailscale 或 TailSocks；你在模拟器里点开链接自己登录确认。清单见 evidence/R14.md「还差什么」。
- 真实 Tailscale 验证（可选）：要测真实 scope 回报、限流、共享设备可见性，需要你提供一个只含 `devices:core:read` 的 OAuth client；不提供就一直只有 fixture 证据。
- 应用锁与凭据租期（SEC07）：现在没有应用锁，凭据启动时读进内存、整个进程都在，断线自动恢复用的是建连时冻结的凭据。要不要加生物识别/应用锁、锁定后后台恢复还能不能用内存里的凭据，需要你定策略。
- flutter_secure_storage 9.2.4 在 Keystore 密钥失效时会静默换一份存储（R09 已能识别并提示）。是否在后续升级到 10.x（存储格式变化、需迁移），按 docs/12 需要你同意再动依赖。
