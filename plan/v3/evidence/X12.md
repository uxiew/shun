## 结论先说

- **作者入口** `docs/plugin-authors/README.md`：八步从零做出插件（环境 → 复制样例 → 自己的密钥 → 宿主证书 → 构建 → 安装 → 批准 → 连接测试/会话测试），
  另有接口约定（contract.md）、出错对照（troubleshooting.md）、版本兼容（compatibility.md）、许可（licensing.md）。不需要宿主源码和宿主私钥。
- **样例** `plugins/example`（Hello 终端，包名 `example.xwshun.hello`、pluginId `example.hello_terminal`）：独立 Gradle 工程、自带 wrapper，只依赖 `provider-sdk`；
  复制到仓库外、换一把新密钥照样 6 秒编出来。模拟器上走通授权 → 版本协商 → 字节流 → 改尺寸 → 关闭（宿主关、插件自己关）→ 设置页 → 停用/启用 → 卸载重装，
  正式版（release）宿主下照样可用。
- **宿主为此改了三处**：插件页底部显示本 App 的签名证书和插件 API 版本（作者要抄进插件）；详情页加「会话测试」（第三方终端插件原来没有任何界面能开会话，
  作者只拿宿主 APK 走不完流程）；修了一个崩溃——**插件在握手里抛 `IllegalStateException` 以外的异常，宿主整个闪退**（模拟器上先复现、再验修复）。
- 读生成代码发现：**旧插件不认识新追加的 AIDL 方法时 Binder 不报错**（void 方法看着像成功），原注释写反了。改了注释和文档，行为没改，留给以后加方法时按 minor 判断。
- 许可按现状写清：宿主、SDK、样例都按仓库的 GPL-3.0-or-later，SDK 和样例全是本 fork 新写的（git blame 核对），要不要放宽由所有者定；不声称独立 APK 规避 GPL/AGPL。

## 发现的问题

1. **插件握手时抛约定外的异常，宿主整个闪退**（已修 b06d7bb，见上）。X08 只补了 `callPlugin`，握手走的是另一条路。
2. **旧插件不认识新追加的 AIDL 方法时调用「静默成功」**：生成的代理代码不看 `transact` 的返回值，空回复读出来就是没异常。原注释说「Binder 报未实现，宿主当作不支持」，不对。
   只读了生成代码，没在设备上构造（v1.0 的插件都实现了全部方法）。改了注释和 compatibility.md；以后追加方法时，宿主要先看插件描述符的 `apiMinor`。
3. **会话测试页离开时先断开再等关闭**，插件的 closed 被当成「连接已关闭」丢掉，事件里像出了错（已修 6aa4304）。
4. 插件卸载后详情页「插件自己的设置页」一栏写「这个插件没有声明设置页。」——卸载后宿主拿不到设置页信息，说法不准。X04 起就是这样，没改。
5. 插件进程没有会话、被系统冻结时，宿主死亡通知要等它下次被唤醒才到（重装宿主后插件日志里两条「宿主已退出，关闭 0 个会话」晚到）。有会话时插件被宿主绑着、不会被冻结，没观察到影响。
6. **`xwshun.mosh` 没有绑定证书**：`AdmissionPolicy.reservedOfficialIds` 是空的，Mosh 连接只按 pluginId `xwshun.mosh` 找插件。别的包自称这个 ID、用户又批准了它的证书，
   就能拿到 Mosh 会话的一次性 key 和 UDP 目标。靠的只有用户在批准框里核对证书。正式签名定下来之后应把这个 ID 绑到正式证书（见「需要所有者定的」）。
7. 第三方终端插件除了会话测试没有任何入口（主机列表里没有「用某插件连接」）。文档第一节写明了，不是 bug，是产品范围。
