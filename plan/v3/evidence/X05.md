## 做了什么

R11–R13 的 HTTP、缓存、合并、导入规则一行没改，只是接进插件体系：

- **内置 provider**：`BuiltinPlugins.tailscale = builtin.tailscale`，只声明 `device-catalog`，路线只有 `system-default`（控制面 API 不借任何 SSH 主机的代理或跳板），权限只有 `own-provider-state`。和内置 SSH 一样构造即可用、不能停用，外部包冒用这个 ID 被拒。插件页「随 App 提供」里列出它。没有为它单独出 APK。
- **能力门**（`lib/application/tailscale_catalog_provider.dart`）：目录的每个操作（加来源、三种读取、删凭据、移除/恢复来源、关联、列关联）先向 registry 要 `builtin.tailscale` 的 `device-catalog`。拿不到就在发请求、读凭据、碰主机之前抛 `PluginUnavailable`。目录页全部改经这里调用。
- **只访问本来源控制面凭据**：
  - 目录凭据本来就在独立安全存储、按来源 ID 分键；来源 ID 的规则原先在缓存仓库和凭据存储里各写一份，收成 `isValidCatalogId` 一处（只允许字母数字和连字符，拼不出路径、别的来源的键或引用分隔符）。
  - 目录原先拿到的是整条 `HostProfile`（含登录密码、自定义代理口令、启动命令）再整条写回。现在经 `CatalogHosts` 访问保险库：读的是只有 id/名字/地址/目录绑定的 `CatalogHost`，写只能经 `CatalogHostChange` 改地址和绑定两个字段。
- **设备关联的持久化**：关联就是主机上的目录绑定（`xwshunCatalogSource`，R12 起就存在保险库里）。`catalogDeviceLinks` 从绑定算出 plugin_api 的 `DeviceLinks`，引用是（来源 ID:设备 ID）。**没有另存一份关联文件**：两处都存，迟早一处说关联着、另一处说没有。绑定在保险库里，所以重启不丢、跟着保险库导出和同步。
- **两条修复路径**（DEV02「缺 provider 的配置可保留修复」）：
  - 关联已有主机：目录页设备下面「关联到已有主机」，只列还没关联目录的主机。只写绑定、不写 `appliedAddress`，所以刷新永远不改它的地址；用户名、端口、认证、路线、指纹不碰，不连接。一台主机对一台设备，检查和写入在保险库同一次串行写里做（新增 `VaultController.updateHostChecked`），规则最后由 `DeviceLinks.linkByUser` 把关。
  - 恢复来源：来源被移除、或主机从别的手机同步来时，目录页列出「主机里引用了、本机没有的来源」；「在本机恢复」按原来源 ID 建空来源，不发请求、不改主机，之后读一次同一个 tailnet 就重新对上。更新版本写的缓存不算缺失，恢复也不覆盖它。
- **落点和计划的差别**：计划写的是 `infrastructure/plugins/tailscale_catalog`。provider 要调刷新器和保险库（都在 application 层），而本仓库 infrastructure 从不反向依赖 application，所以放在 `lib/application/tailscale_catalog_provider.dart`；设备引用的规则放在 `lib/domain/device_references.dart`（和 X01 的 SSH 主机引用一起）。

## 过程中发现并修掉的

- **模拟器上看，「关联到已有主机」对话框里的主机行只有两行字，看不出能点**：加了主机图标和右箭头（5a713bf）。同一对话框按钮区上方的空白是 Material 3 对话框本来的间距，和「移除来源」确认框一样，没改。
- 「恢复」在英文翻译表里原有的译法是 Resume（进程管理用的），所以恢复按钮写「恢复来源」（Restore source），不借用它。

## 未测与局限

- 没有真实 Tailscale：假服务器证明的是 App 发了什么、怎么处理响应，不证明 Tailscale 的真实响应。
- 能力门拿不到能力的那条路径只有单测：内置 provider 在正式 App 里不可能缺席，模拟器上造不出来。
- 目录页英文界面只有 widget 测试，没上设备；只测了 API 35；没有真机。
- 关联只覆盖 SSH 主机 ↔ 目录设备。目录设备 ↔ UU/RustDesk、SSH 主机 ↔ UU/RustDesk 的关联要等 X06/X07 有了这些引用再定存法；`DeviceLinks` 的通用规则已在 plugin_api 里。
- 恢复来源用的是用户断言：读的若是另一个 tailnet，设备 ID 对不上，主机只显示「缓存里没有这台设备」，不会被改——这条有单测，没在模拟器上演示。
- 最后一次提交只给对话框加了图标；设备上装的那版多了一行 ListView 内边距（后来发现不是原因，撤了），界面上看不出差别，没有再上设备复看。
