## 改成了什么样

```text
SSH / Telnet ──原始字节──> GhosttyTerminalAdapter.feed ──> flterm TerminalController.write   （不转字符串）
SSH / Telnet <──字节────── onOutput（用户输入、协议回应）只交给当前代次
设置「终端引擎」──> terminalAdapterFactoryProvider（建终端时才读设置）──> 新标签用哪个引擎
终端页 ──terminalViewFor──> GhosttyTerminalView ──> flterm TerminalView（同一时刻只挂一个）
```

| 文件 | 作用 |
|---|---|
| `lib/infrastructure/terminal/ghostty_terminal_adapter.dart` | 先接回调再喂；写入期间再来的数据排队；换代次时补一个 CAN 打断旧连接没写完的控制序列；效果回调一个不接；资源上限；视图挂着时推迟释放原生控制器 |
| `lib/presentation/terminal/ghostty_terminal_view.dart` | flterm 视图单挂和交接；画中画不抢焦点；有选区或全屏程序里给「复制」 |
| `lib/infrastructure/terminal/terminal_session_adapter.dart` | 共用规矩加两条：尺寸 0 不发、连着的变化合并（100 ms）；`lineAt/lineCount` 换成 `recentLines(count)` |
| `lib/application/terminal_engine.dart`、设置页、`session_controller.dart` | 按设置建终端；Ghostty 起不来时连接如实失败，不换引擎凑合 |
| `third_party/libghostty`（fork） | 加 `TerminalController.tailRows`：一次格式化一段行范围，带折行标记 |
| `tool/build-release.sh`、`android/app/build.gradle.kts` | 发布包：丢缓存从核对过的源码重编、查 16 KiB 对齐和库是不是这次编的；只带 arm64-v8a |

## 验收

| 验收项 | 结果 | 证据 |
|---|---|---|
| 先接 onOutput 再 feed，无重入 | 是 | 构造时先接回调；远端的光标查询、DA 查询一到就有应答，只交给当前代次。回调里同步再喂数据：排队等这次写完、顺序不乱（`test/ghostty_terminal_adapter_test.dart`）。把排队去掉，这条挂 |
| 单 controller 单 view | 是 | flterm 第二个视图来挂直接抛 StateError。视图做了交接：新视图拿到显示权就通知旧视图卸下，旧的还挂着时新的先空一帧（`test/ghostty_terminal_view_test.dart` 4 条）。GST02 的页面测试两个引擎各跑一遍，全程无异常、flterm 视图个数对 |
| 代次失效停止发送 | 是 | 旧代次收不到应答和输入；旧连接断在没结束的 OSC 里，新 shell 的输出照常显示（补 CAN）；去掉 CAN，这条挂 |
| 初始化失败状态真实 | 是 | 建终端挪进连接的 try：Ghostty 起不来时不拨号，等待卡片标失败，错误写「终端引擎 Ghostty 无法启动：原因」，提示改回 xterm2（`test/terminal_engine_test.dart`）。不偷偷换成 xterm2。把建终端挪回 try 外，这条挂 |

停止条件「native crash 不能承诺无缝 catch 回退；缺资源清理证据不进入默认」：不做任何 catch 后回退；Ghostty 不是默认；
资源清理证据见下面 LIFE06（引擎部分）。

## 关标签时的 use-after-free（R16「给 R17 的话」）

会话控制器关标签时立刻释放终端，视图下一帧才卸下；flterm 的绘制路径（`lib/src/rendering`）完全不查控制器是否已释放，
这一帧里画就是读已释放的原生内存。做法：适配器释放时如果还有 flterm 视图挂着，只做标记、通知视图重建；
视图卸下 flterm 视图后（等这一轮同步工作做完，因为停用顺序是先父后子），才真正释放原生控制器。
单元测试核对「挂着不放、卸下才放、卸下又挂回不放」；页面测试、设备测试核对关标签后控制器最终都释放了。

## 发现的问题

1. **横屏 + 软键盘时终端被挡住，远端尺寸还算着被挡住的行**（两种引擎都有）。见 TER06，交 R18（「键盘/候选不遮挡」）。
2. **系统返回手势把 Activity 结束了，所有会话一起没了，前台保活服务和「SSH 会话」常驻通知却还在**（两种引擎都有）。
   在模拟器上从屏幕左边缘拖动选字时误触了返回手势撞上的；sshd 上没有残留连接，说明 socket 都关了。
   Ghostty 的原生内存这时有没有释放（Dart 的 Finalizer 在 isolate 退出时不跑）没核实。归 R22。
3. **模拟器冷启动后第一次往刚连上的终端注入文字，丢了中间 6 个字符**（`cat /etc/os-release` 收到 `c/os-release`）。
   之后两种引擎各试两次（新连上就注入）、稳定后连注 3 次，全部完整，没能复现。推测是输入法冷启动时吃掉了注入的按键，记一笔不作结论。
4. 默认的 Ghostty 设置不适合手机：滚动区默认只留约 10 KB、Kitty 图像 64 MiB、APC 65 MiB。已改成 5000 行 / 8 MiB / 0 / 0（R04 问题 7）。
5. 两种引擎的列数差 2 列（同一屏 45 对 47），是字体度量不同；不影响正确性，记着。
