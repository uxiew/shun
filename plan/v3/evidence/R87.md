## 2. 首页迁移

参照 FlClash 固定版本：设置类页面的分组卡片（`DecorationListItem`，R86 已用）、代理页的卡片（Prism `Card`，`AppCorner.lg`）、配置页的空状态和顶栏、`SearchField` 放在卡片那一层底色上。首页按这些改写，项、分组、顺序、key、行为照旧。

| 部位 | 迁移前 | 迁移后 |
|---|---|---|
| 视图切换 | Material 弹出菜单 | Prism `PopupAnchor` + `PopupMenu`，当前视图打勾（读屏「已勾选」），按钮挂 `vault-view-mode` |
| 搜索 | Material `TextField` | Prism `SearchField`（胶囊，有字时右边 ⓧ 清空），挂 `vault-search`；提示文字不变 |
| 分组筛选 | `ChoiceChip` | 照 Prism Chip 画的胶囊（见下），36 高不变 |
| 最近 AI 工作 | Card + ListTile | 单行 `ShunListRow`（分组卡片），key 不变 |
| 列表视图 | 每台一张 Card + ListTile | 一组连在一起的分组卡片，`prism.generateSliverSection` 只建可见行（主机可能几百台） |
| 网格视图 | Card + InkWell | Prism `Card`（lg 圆角）；地址 footnote、分组 caption1，比 subheadline 少截字 |
| 树形视图 | Card + ExpansionTile | 每个分组一组卡片，组头 `ShunListRow`（文件夹、名称、台数、展开箭头），点了收起 / 展开 |
| Tailscale 分节 | 每个来源一张 Card | 每个来源一组卡片，第一组带「Tailscale 设备」小标题；组头、主机行、设备行都是 `ShunListRow` |
| ⋮ 菜单面板 | ListTile 列表 | 顶上一行这台主机（不能点），下面一组分组卡片，key `host-menu-<动作>` 不变 |
| 空状态按钮 | Filled/Outlined/TextButton | `ShunButton`，key 不变 |
| Tailscale 目录两页 | Card + ListTile | 来源列表、状态块、设备列表换成分组卡片；「在本机恢复」「填 API key 读设备列表」换 `ShunButton` |
| 编辑器里的「目录来源」 | Card | `ShunSection`（小标题 + 一块 `ShunSectionItem`），key `catalog-source-section`、`catalog-unlink` 不变 |

公共层（`ui/components.dart`）为此给 `ShunListRow` 补了三个可选项，原来的行为不变：

| 参数 | 作用 | 读屏 |
|---|---|---|
| `onLongPress` | 主机行长按出菜单（迁移前 ListTile/InkWell 就有） | 长按动作挂在卡片那一个节点上，不另起节点 |
| `describeLeading` | 左边图标带信息时（系统、Telnet/Mosh 角标）把它念进这一行 | 默认仍当装饰不念 |
| `expanded` | 点了展开 / 收起的行（树形组头、Tailscale 来源组头） | 报「已展开」「已收起」 |

长按的做法：Prism 卡片是语义边界，外面套的 `Semantics` 会落到上一层节点。所以「长按」动作标在卡片里面（并进卡片节点），手势由卡片外层的 `GestureDetector` 收（整行都能按）。Prism 卡片只在里面有带 onTap 的部件时才让出点按，只挂长按不影响点一下。

分组 chip 没直接用 Prism 的 `Chip`：它只在选中时报「已选中」，没选中的不报选中状态，读屏听不出这是一组单选。照它的样子用 Prism `Card` 画，给没选中的补「未选中」。第一版两种都标，选中的那个和卡片自带的选中冲突，读屏拆成了两个节点（清点时抓到），改成只给没选中的标。

### 2.1 清点：迁移前后逐项对照

方法同 R86：一份临时 widget 测试装起整个 App（ShunApp），在空数据、列表 / 网格 / 树形、⋮ 菜单、搜到目录设备、搜不到、选分组、全部隐藏、Tailscale 来源列表和两个来源页这些状态下，按顺序导出读屏节点（名字、按钮/选中/展开状态、点按/长按）和所有带 key 的部件。原始输出 `home-before.txt`、`home-after.txt`，探针源码 `home_inventory_probe.dart.txt`（没留在仓库里）。

- 迁移前的 key 迁移后全在、上下顺序一样。在测试数据（置顶、分组、Telnet、Mosh、两个来源同名同 IP、一个来源旧且读失败）上，迁移前三种视图都是同一串 38 个 key：把 lib 临时退回 HEAD 录下来，写成常驻测试「迁移前首页的入口一项不少、顺序不变」（三种视图各一条），录完 lib 已恢复。
- 新增的 key：`vault-view-mode`、`vault-search`、`vault-tree-group-<分组>`、`vault-loading`（缓存读不出来时的转圈）、`catalog-source-<来源>`。
- 读屏变化：网格卡片以前只有点按 / 长按、不是按钮，现在是按钮节点；「Tailscale 设备」「设备」小标题成了标题节点；树形组头以前多一个只念「已展开」的空节点，现在展开状态在组头本身；Tailscale 来源组头以前不报展开状态，现在报；ListTile 那个无意义的「未选中」没了。所有主机行（三种视图、Tailscale 分节）仍是一行一个按钮节点，带点按和长按，系统、协议角标、名字、地址都念在里面。
- ⋮ 菜单顶上那一行不能点，念的顺序从「系统、名字、地址」变成「名字、系统、地址」（不在分组里的行先念标题）。

### 2.2 顺带修的：有 Tailscale 来源时搜不到是一片空白

迁移前就有：本机有 Tailscale 来源时，搜一个什么都匹配不上的词，列表一片空白，不说「没有匹配的主机」（迁移前清点的 `search-none` 段可以对上）。原因是首页的空状态只看「有没有来源」，不看来源在这次搜索下还有没有行。图库出图时撞到。现在把分节的过滤抽成 `catalogSectionGroups`，分节和首页共用：这次一行都没有就说「没有匹配的主机」，仍不摆「添加主机」。没在搜时和以前一样（每个来源都列）。
