## 做了什么

- **连接路径三选一**：主机编辑器里「直连 / 经代理 / 经跳板机」；「先经代理连第一台跳板机」是跳板模式下单独的高级开关。
  以前「跳板机」「代理」是两个独立区块，可以不知不觉同时设上。保存时只保留当前方式的设置，切回直连就真的去掉代理。
- **实时路线预览**：按表单当前内容用和连接时同一个函数算路线，逐段显示「手机 → 代理 → 跳板… → 目标」；
  配置矛盾时显示原因且**不让保存**（docs/02）。代理端口填 22、或代理与目标完全相同时提示可能填混（不拦）。
- **端口不混**：字段叫「SSH 端口」「代理地址」「代理端口」；路线里目标写 `SSH 用户@地址:SSH端口`，代理写代理自己的地址端口，并注明「代理之后怎么走由代理决定，App 看不到」。
- **测试连接**：按还没保存的配置走一遍，和正式连接共用逐跳建连和指纹核对；登录后只带 PTY 执行 `tty` 拿到远端终端设备名，
  不开交互式 shell（不触发 .bashrc 里的自动 tmux），从不执行启动命令。逐段显示阶段、成败和下一步；可随时停止。
- **失败页诊断**：显示这次实际走的路线，外加按真实失败类型给的一句下一步（比如「对方在登录前断开」提示可能把代理端口填成了 SSH 端口）。
- **不列没实现的功能**：Mosh 在新建时不可选（插件还没有）；Telnet 注明只能直连。
- **顺带修上游崩溃**：「添加跳板机」下拉框选一次后仍记着那一项而它已不在候选里，debug 版红屏。

## 这台机器上的坑

- 模拟器里用 `10.0.2.2` 连宿主机上 OrbStack 转发的测试环境端口，TCP 能连上但一个字节都收不到（`nc` 实测，宿主机上同一端口正常）；
  App 如实报「对方在登录前断开」。改用 `adb reverse tcp:22201 tcp:22201` 后在模拟器里连 `127.0.0.1` 正常。手册已写。
- 为了不让系统通知权限弹窗打断自动化操作，测试时在模拟器上预先授予了通知权限，测完已撤销并清掉 App 数据。
- 用 `adb shell input text` 往 Flutter 输入框里打字时，键盘会挡住下方的框，点击落在键盘上会把文字输进上一个框——每填一个框先收起键盘。

## 未测项与局限
