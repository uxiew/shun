## 做了什么

- **导入规则**（`lib/application/tailscale_catalog_import.dart`）：选中的设备按同一套设置生成新主机，只写保险库。
  - 用户名不填一台都不导，不默认 root；用户名带空格、端口越界、私钥认证没选私钥都拒绝。
  - 路线：直连 / 已保存的代理配置 / 自定义代理 / 保险库里的跳板机（可加代理入口），用和连接时同一个 `resolveRoutePlan` 检查。设置本身不成立整批拒绝；只和某台地址有关的只跳过那台。
  - 没有所选种类地址的、最近完整列表里不见了的、已导入过的都跳过并写明原因；地址不回退到别的种类。
  - 新主机带 `CatalogBinding`（appliedAddress = 写入的地址），R12 的「地址跟随目录」对它生效；不写任何指纹记录。
  - `VaultController.addHosts` 在写入队列里按此刻的保险库再查一遍，只新建、不改已有主机。
- **目录页**（设置 → Tailscale 设备目录）：来源列表；来源页显示缓存时间、列表是否完整、最近一次失败原因、是否保存了 OAuth client；设备只显示「Tailscale 控制面：已连接 / 未连接 / 不知道」，没有「在线」「SSH 可用」；写明目录不知道手机能不能连到设备、tailscale#16911。粘贴 token、OAuth secret 的输入框遮挡、关联想，只在用户点读取时发请求。
- **导入页**：用户名、端口、地址种类、路线、认证、分组；下方实时显示每台会怎么建、为什么跳过、连接时走哪条路线。导入后提示「还没有连接过」。
- **主机编辑器**：来自目录的主机显示来源、设备、目录状态、缓存时间、控制面状态、地址是否还跟随目录，写明「目录状态不代表能连上」；可断开关联（主机保留）。

## 过程中发现并修掉的

- **全新安装时一打开目录页就报 Cannot modify an unmodifiable list**：缓存目录还不存在时仓库返回 const 空列表，页面原地排序。widget 测试的内存假仓库返回的是可修改列表，所以没抓到；模拟器第一次打开就撞上（2f32ba2，回归测试去掉修复即失败）。
- **对话框关闭动画还在用输入框时控制器已释放**：widget 测试抓到，改为对话框自己持有控制器，销毁前先清空。
- **缓存还没读出来时对 const 空列表排序**：同类问题，widget 测试抓到。
- **最近一次失败要比较时间先后才显示**：手机时钟往回调时会藏起刚发生的失败。`lastAttempt` 本来就是最近一次，改为直接看它。
- 模拟器上看到的四处界面问题（45a5e84）：说明文字压住输入框标签、用户名提示压住下一栏、OAuth 少填一项时「读取」按了没反应、「不完整」说两遍。

## 未测与局限

- 没有真实 Tailscale：目录 API 是本机假服务器，证明的是 App 发了什么、怎么显示，不证明 Tailscale 的真实响应（scope 回报、限流、共享设备可见性）。
- **模拟器网络的限制**：连到不了的地址（100.64.0.10）时，模拟器的用户态网络先替设备接下 TCP 再关掉，App 报「登录完成前连接被对方关闭」（SSH 握手阶段），不是「连不到」。从 Mac 上连同一地址是超时。App 如实报告了它看到的阶段，但「设备离线 → 网络层失败」这条路径要真机才能看到。
- 没有真机；只测了 API 35 和中文界面（英文界面有 widget 测试，没上设备）。
- 批量导入不填密码：密码导入后到各主机编辑器里填（设计如此）。
- 手机端没有新建「代理配置」的界面；导入页的「已保存的代理配置」只有从桌面端导入的才有，平时用「自定义」。
- 移除来源的确认框没有在设备上点过（逻辑在 R12 单测里）。
