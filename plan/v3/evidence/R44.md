# R44：带秘密的页面防截屏，密码框不让输入法学习

日期：2026-10-21（模拟器）、10-22（真机）。结论：**R44 IN_PROGRESS，SEC13 BLOCKED**。

- 模拟器上能验的都验过、都通过（下面前半部分）。
- 10-22 在所有者的 Pixel 9 Pro（Android 17，微信输入法）上做了真机部分，见文末[真机](#真机pixel-9-proandroid-17微信输入法10-22)。
  截屏、录屏、最近任务、终端页都对；**输入法学没学判断不了**：对照组（普通框里的新词）微信输入法也不联想，所以密码框里的词没被联想出来说明不了什么。
  这一项没法继续的原因不在 App，记 BLOCKED；要有一个在普通框里会学的输入法（或微信输入法开了学习）才做得了有效对照。

## 环境

- Flutter 3.47.7，OrbStack / Docker 29.8.2，arm64 Mac。
- 模拟器 `shun-r39-a30`：Android 11（API 30），arm64，1080×2340，Gboard 9.4.11（系统自带）。装的是 debug 包 `top.xdwa.shun.debug`，从 `e2d0e8e` 编（小眼睛标签那一项从 `1edf1e6` 编）。
- 主 SSH 测试环境（`tool/fixture-environment/up.sh`，`selfcheck.sh` 8 项全过），`adb reverse tcp:22201` 让模拟器连边缘 sshd。
- 截图、录屏在仓库外 `../.toolchain/artifacts/r44-e2d0e8e/`。

## 怎么判断「挡住了」

- 窗口有没有标志：`adb shell dumpsys window windows` 里 App 窗口的 `fl=` 带不带 `SECURE`。
- 截屏：`adb shell screencap -p` 对带标志的窗口直接失败（退出码 1、0 字节）；系统截屏键（`input keyevent 120`）在 logcat 里报 `SurfaceControl: Failed to take screenshot`，`/sdcard/Pictures/Screenshots` 里不出文件。
- 录屏：`adb shell screenrecord --time-limit 4`，用 ffmpeg 逐帧算 App 区域（去掉状态栏和导航栏）非黑像素的比例。
- 输入法收到什么：点进框以后看 `adb shell dumpsys input_method` 的 `mInputEditorInfo`。`imeOptions` 带 0x1000000 就是 `IME_FLAG_NO_PERSONALIZED_LEARNING`（「别学」）。

| 测试 | 代码 | 结果 |

| R18 回放 `integration_test/r18_ime_replay_test.dart` | `e2d0e8e` | 通过。远端逐字节核对：微信语音、拼音、改写、emoji、空退格、只 finish、回车、回车换行 8 段，字节和以前一致 |

这个 AVD 没有硬件键盘设备，脚本里 `hw:` 开头的段会跳过；R18 回放这个文件不用硬件键。

**R25 那次失败**：`resize-composeFocus: 2 次`。点「大输入框」弹键盘时，远端收到两次尺寸变化（20 行、再 19 行），测试要求最多一次。之后 HEAD 上 3 次、基线上 3 次，这一步都只收到一次（19 行）。R44 没改终端布局和键盘处理，所以判断是这台 API 30 模拟器上偶发的键盘高度分两步报，不是 R44 引起的；但一共只跑了 7 次，偶发率没法给准数，基线上也没复现过。以后在这台模拟器上再碰到，先看是不是这一步。

**R18 第一次跑失败**（`sessions.single` 报 Too many elements），是测试环境被我弄脏了：测试直接用 App 的真实保险库，前面手动测试存的主机和它开着的终端标签在启动时被恢复回来，多出一个会话。`flutter test` 跑完会卸载 App，数据跟着清掉，重跑就过了。在同一台模拟器上先手动测、再跑这些设备测试的话，先 `adb shell pm clear top.xdwa.shun.debug`（App 没装时这条会报 Failed，不碍事）。

## 单元测试

`e2d0e8e` 上全量 `flutter test --no-pub -j 4`：1325 过、199 跳过、0 失败（跳过的是对应测试环境没起）。`flutter analyze` 无问题。`test/secret_content_test.dart` 17 条，包括 `ShunApp` 端到端（设置开关、IndexedStack 里藏着的设置页不触发、被新页面盖住时撤标志）和两条源码扫描（打码框漏写三个输入法选项、有打码框的文件没包 `SecretContent` 都会红）。改坏输入法选项、改坏可见性判断、拆掉接线这三种，都试过测试会红。

## 边界和没测的

- **进页面那一下会漏 2 帧**：标志从 Dart 经平台通道过去，比页面第一帧晚。录到的是空表单或打码的密码，没有秘密；但录屏能看出用户在编辑哪台主机（名称、地址）。要彻底堵住得在推页面之前同步开标志，这轮没做。
- **输入法到底学没学没验**。验了的是 App 把「别学」发出去了。Gboard 对密码类型的框本来就不学，从外面看不出这个标志有没有用；模拟器上也没有可做对照的、不打码却带「别学」的框。微信输入法要真机，**NOT_RUN**。
- **只在设备上点过**编辑连接、编辑代理两页。AI 服务商页、云同步卡片和六种密码对话框（私钥口令、登录提问、sudo、Tailscale token / OAuth）只有单元测试覆盖，没在模拟器上点过。
- 投屏没单独测（和录屏是同一个机制）。
- 只在 API 30 上测过，别的系统版本、厂商系统上截屏失败时长什么样没看。
- iOS：系统不让 App 拦截屏，`PlatformWindowSecurity` 在 iOS 上什么都不做，N/A。
- 终端页按停止条件不加标志，终端里 `cat` 出来的密钥不受保护（使用手册第 12 节写了）。

## 真机：Pixel 9 Pro、Android 17、微信输入法（10-22）

所有者当次同意装调试包、本人操作手机。装的是 e7e9813 编的 `top.xdwa.shun.debug`；手机上的 `top.xdwa.shun` 没动（`lastUpdateTime` 2026-10-21 09:38:33）。
打字、点击都是所有者自己做的；我只读：`dumpsys window`（标志）、`dumpsys input_method`（输入框参数，只留 shun 自己的）、前台是 shun 时的 `screencap` / `screenrecord`。
开始和结束各记一次默认输入法、子类型、启用的输入法、无障碍服务，两份一样。证据在仓库外 `../.toolchain/artifacts/sec13-ux02-e7e9813/`。

一个失误：第一次跑探查脚本时没先看前台，截到了手机当时前台的别的 App。只算了非黑比例、没看画面，当场删了图和那段日志，
脚本改成前台不是「shun 调试」就不截屏、不读输入法。录屏也只算数，算完手机上和本机的文件都删了。

**结论**：「敏感页面截不到」「终端页能截」在真机上成立，只是 Android 17 的「截不到」是存一张黑图、不报错（手册第 12 节、security.md 1.5 节按这个改了，fb55edd）。
「密码框不进输入法个人词库」只能说没观察到进了；对照组也不学，证明不了是 App 的标志挡住的。「终端输入行为不变」只做了一句拼音，没重跑 R18 的逐字节真机测试（`tool/r18-real-device.sh`）。
SEC13 记 BLOCKED，卡在「没有有效对照」。要解开：所有者看微信输入法设置里有没有学习 / 个性化开关；或者换一个在普通框里会学的输入法做对照。
也可以由所有者决定按「没观察到泄露 + 标志已发出」接受。
