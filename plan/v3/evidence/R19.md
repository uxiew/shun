## 结论先说

- **默认引擎 xterm2 上有两个远端越权，修了**：终端视图挂着、有焦点时，远端 `printf '\e]52;c;?\a'` 能把手机剪贴板读走
  （实测回的是 `ESC]52;c;cGhvbmUtc2VjcmV0 ESC\`，即 base64 的 `phone-secret`），`\e]52;c;…` 能静默改写剪贴板；
  远端先设标题、再发 `CSI 21 t`，xterm2 把标题回进 shell 的输入行。R16/R17 的 SEC09 测试只测了不挂视图的适配器，所以没发现：
  适配器把剪贴板回调留 null，xterm2 的 TerminalView 挂上时见 null 就接上自己的实现。原版 Netcatty 用的是同一个库、同样的视图，也有这两个问题。
- **粘贴和打字分开了**：快捷键栏「粘贴」、硬件 Ctrl+V、命令片段都走 `paste`（远端开了 bracketed paste 就包标记，没开把换行换成 CR，
  末尾不加回车）；多行、末尾换行、控制字符、看不见的排版字符、超过 4096 字的先弹可编辑的预览，照实写远端开没开 bracketed paste、
  会不会逐行执行；回车只有点「粘贴并回车」才发。目标认的是动手那一刻的连接对象：断线、恢复成新 shell、关标签都不发，也不补发。
- **手势**：普通 shell 滑动翻本地历史；全屏程序没开鼠标时滑动什么都不发（原来 Ghostty 发 ↑↓，tmux 没开 mouse 时等于翻 shell 历史）；
  开着鼠标只发滚轮，点按、长按不发鼠标点击（原来 Ghostty 会发）。两个引擎在模拟器上逐字节核对过。
- **链接（Ghostty）**：认 OSC 8 和 http/https 网址，点了只弹确认框，只把 http/https 交给浏览器；拖动、长按不触发。
- **停止条件**：预览文案、接口注释、测试名都写的是「清洗」「远端约定」「App 保证不了」；真 bash 上还专门测了
  「伪造的结束标记被挡掉，但按了回车照样执行」。没有一处把 bracketed paste 或库清洗当成不会执行的保证。

## 原来是什么样（先看清楚再动的）

| 地方 | 原来 | 实测后果 |
|---|---|---|
| 快捷键栏「粘贴」 | `Clipboard.getData` 后按打字（`sendText`）发 | 多行内容每个换行都是回车，逐行执行；末尾带换行的命令一粘就执行；快捷键栏亮着的 Ctrl 套到粘贴的第一个字上 |
| 硬件 Ctrl+V | 两个引擎各自直接把剪贴板粘进终端（flterm `controller.paste`、xterm2 `terminal.paste`） | 不经任何预览 |
| 命令片段 | `sendToSession` 按打字发，「自动运行」才补 `\r` | 没勾「自动运行」的多行片段也逐行执行 |
| AI 插入的命令 | 按标签 id 发 | 助手开着时断线恢复，命令进的是新 shell |
| xterm2 的剪贴板回调 | 适配器留 null，视图挂上时替它接上真读写 | 见上：远端能读走、改写剪贴板（`test/terminal_remote_effects_test.dart` 修前挂） |
| xterm2 的 `CSI 21 t` | 无条件回 `ESC ] l <标题> ESC \` | 远端设的标题进 shell 输入行（xterm、Ghostty 默认都不回） |
| Ghostty 备用屏滚动 | flterm 默认开着 1007 | less/vim/没开 mouse 的 tmux 里一滑就发 ↑↓；tmux 里 ↑ 到了 shell，翻出上一条命令 |
| Ghostty 鼠标报告下的手指 | 点按发成鼠标点击，长按被程序拿走 | tmux mouse on 时点一下就换窗格，长按选不了字 |
| Ghostty 链接 | R17 关掉了识别（`LinkSettings(types: {})`） | 不认链接 |

| 验收项 | 结果 | 证据 |

## 发现的问题

1. **xterm2 挂着视图时远端能读写手机剪贴板**（默认引擎，原版也有）：修了（c42bd2c）。

### 「别的 Ctrl+字母有没有被本地吃掉」

模拟器打开硬件键盘（`hw.keyboard = yes`，测完改回 `no` 并重启核对过），用 sendevent 写真实扫描码，远端 dd 逐字节收（`integration_test/r18_keys_test.dart`）：

|---|---|---|
| Ctrl+K、Ctrl+A | `0b 01` | `0b 01` |
