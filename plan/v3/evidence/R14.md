## 做了什么

- **登录方式**（`lib/domain/tailscale_ssh.dart`）：主机上 `xwshunSshLogin: tailscale` 才算 Tailscale SSH。不复用 `authMethod`（桌面端也读写它）；不看 100.x，不看目录绑定。
- **SSH 层**（`lib/infrastructure/ssh/ssh_login_watch.dart`、`ssh_service.dart`）：每一跳一个 `SshLoginWatch`。
  - Tailscale 模式不给 dartssh2 私钥、密码、键盘交互回调，它只剩 none 可发；`loadHopIdentities` 直接返回 null，私钥不解密；解不开的密码也不拦这一跳。
  - 普通模式：接 dartssh2 的 `printDebug`，只认 `SSHClient._authWithNone` 这一句；登录成功后若试过 none 就关连接、报错。不 vendor、不打补丁（docs/12）。
  - banner 在指纹确认前一律丢弃；分三类（无链接 / 合规 check 链接 / 不合规链接）。普通模式收到带链接的 banner 立刻断开。
  - Tailscale 模式的期限从指纹确认后按「认证超时」算，收到链接换成 10 分钟（`SshService.tailscaleCheckWait`），到点关连接。
  - 认证阶段被断开时，Tailscale 模式报「Tailscale 拒绝了这次登录，服务器说：<最后一条无链接 banner>」；没有 banner 时说「可能被拒，也可能是网络」。
  - 自动恢复（`ConnectionPurpose.restore`）碰上 check 立刻停，`ActiveTerminalSession.autoRestoreBlocked` 让这个标签之后不再自动重试。
- **界面**：编辑器「身份认证」加「普通 SSH / Tailscale SSH」，选后者收起密码私钥栏（保存的不删）并按当前路线写出来源节点；连接等待页和「测试连接」共用 `TailscaleCheckCard`：主机（注明指纹已核对）、`login.tailscale.com/a/…`（不显示 token）、用途、来源节点、截止时间、服务器原话（链接换成 `[link]`），只有点「在浏览器中打开」才 `launchUrl(externalApplication)`；不合规链接卡片变红、没有按钮、写原因和指向的域名。主机详情的「认证」栏写「Tailscale SSH（不发密码和私钥）」。失败提示对 Tailscale 拒绝单独给一句（指向 ssh 规则和来源节点）。
- **测试设施**：`tool/tailscale-ssh-fixture`（Go，照 tailssh 认证结构、用同版本 x/crypto，控制面换成本机 HTTP 开关，用户名选场景，只绑回环）；`tool/tailscale-ssh-fixture/headscale`（Headscale 0.29.4 + 官方 tailscale v1.102.5：ts-socks 扮演 TailSocks，ts-server 的 22 是 Tailscale SSH、2222 是普通 OpenSSH）；`plugins/fixture-fakebrowser`（假浏览器，没有联网权限，只记收到的链接）。

## 过程中发现并修掉的

- **登录期限把看指纹的时间也算进去**（7b64c21）：模拟器上在指纹框停了 30 多秒，点「接受」就报「30 秒内没有等到登录结果」。
- **主机详情「认证」栏对 Tailscale SSH 主机写「自动 / 交互式」**（a8771ba）。
- **保险库密码写进了别人的存储文件**（7302be1，计划外，X05/X06 起就有）：冷启动后「保存的凭据中有 2 条无法解密」，正好是刚存的两台主机的密码。flutter_secure_storage 9.2.4 Android 端只在调用带非空文件名时切换文件、从不切回默认（S69）；保险库没写文件名，同一次运行里先碰过 UU/RustDesk/目录的存储，之后保险库的写入都进了它们的文件（设备上 `xwshun_uuremote.xml` 里多出的两条，而 `FlutterSecureStorage.xml` 自 15:39 起没变过）。修后设备上：先打开主机详情（读 UU 存储）再重填密码，新密码进了 `FlutterSecureStorage.xml`；强制重启后提示消失。已经写错地方的不搬（本 fork 没装到任何真实设备）。第一版回归测试走插件的 Dart 层，在 macOS 上跑时插件按 `Platform.isMacOS` 发 macOS 选项、Android 选项根本不出现，去掉修复照样过；改成直接拿代码里的 `AndroidOptions` 参数喂给按插件规则建的模型后才会红。
- **测试环境自己的问题**（写进各自 README 的「撞墙时」）：Headscale 0.29 不许 DERP 表为空；tag 已由 authkey 带上时再 `--advertise-tags` 会被拒；没有 DERP 时空闲后直连路径失效，第一次经 SOCKS 拨号报「状态码 1」（加了保温 ping）；单独重建节点容器要可复用的 authkey。

## 还差什么

- **官方 Tailscale 的 check**：没有账号，`login.tailscale.com` 的网页、批准后服务器回什么一次没见过。要测：所有者提供一台开着 Tailscale SSH、策略设 check 的机器，手机上开官方 Tailscale 或 TailSocks，在模拟器里点开链接自己登录（不经手密码）。
- **普通模式连 Tailscale SSH 的 22 端口**：tailscaled 收下密码不看，填错也能进（真 tailscaled 实测）。App 只能从版本行 `SSH-2.0-Tailscale` 看出对面是 Tailscale SSH。要不要在普通模式下对它提示或直接拒绝（改用 Tailscale SSH 模式），**请所有者定**；现在只写进了手册。
- **真机**、真的 TailSocks App（这里用容器里的 userspace tailscaled SOCKS 代替）、经跳板机到 Tailscale SSH 主机（只有来源说明的单测，没有设备上的跳板实测）。
- dartssh2 升级时 none 钩子依赖的调试文字可能变，`tailscale_ssh_login_test.dart` 会红（docs/12 已要求升级时重跑）。
