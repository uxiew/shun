## 本轮实现

- 模型增加内存态 `HostProtocol.unknown`，明确但未知、空字符串、大小写不匹配、错误类型的 protocol 都不视为 SSH；缺省/null 保持旧 SSH 兼容。没有改写原值、迁移保险库或扩大支持协议。
- RoutePlan 在构造目标跳之前拒绝 unknown；跳板仍必须是明确支持的 SSH，嵌套展开沿用同一规则。未知协议没有新增拨号入口。
- 列表显示不支持的类型和中性图标，不尝试读取其端口等 SSH 专属字段；详情进入 `UnsupportedConnectionPage`，无保存、测试连接或类型切换。HostEditor 不为未知数据初始化 SSH 表单，也不自动发现插件。
- `ConnectionEndpointFields` 只拥有地址/用户名/端口呈现和校验；HostEditor 仍拥有草稿，RoutePlan 仍是路线唯一来源。Telnet 不显示、不要求其运行路径没有使用的 SSH 用户名，地址和有效端口仍必填；隐藏的旧用户名留在草稿中，不自动删除。
- SSH/Mosh 间保存保留 Mosh UDP 范围，重开后可恢复。未知桌面字段、SSH 身份和 R40 路由字段继续保留；Telnet 原有显式保存去掉代理/跳板、插件不隐式忽略路线、Mosh 仅直连的规则未改变。

## 接下来的实施顺序（已授权，未实现）

1. **独立条目与解析**：把连接类型与 RoutePlan 分开；RustDesk/UU 的名称、本地条目 ID 与关联信息存于本机加密域，敏感 provider ID 不进入 HostProfile、普通导出/同步/诊断。复用 RemoteControlHost 所需的有限信息，控制器不能再要求真实 SSH 主机存在。保留现有 provider 存储 namespace、签名信任及有效绑定，不生成假 SSH 主机。
2. **一次性迁移事务**：为旧关联确定稳定的新条目 ID；写入新记录并验证可读后，才完成迁移并切换入口。失败或进程在阶段间退出可重试，不覆盖源记录；重复执行不重复建条目。损坏、重复或歧义记录明确报告，不按名字/IP 合并。源 SSH 被删除的关联仍须有可管理的独立条目。旧入口在迁移交付时整体移除，不作为永久双轨入口。
3. **UU 待回调与 DeviceLinks**：保存旧所有者到新条目的确定映射，使升级前 pending 在原到期窗口内仍只能交给对应连接；保留 state/nonce、单请求、冷启动、重复/过期拒绝规则。不重发授权或自动发起远控。已建立的跨 provider 关联保持身份，不隐式新增关联。
4. **类型选择与表单接入**：SSH、Mosh、Telnet、RustDesk、UU 和合规终端插件逐项显示实际可用状态。缺安装/批准时说明原因，不安装、不自动授权；外部 App 只做现有本地探测。Mosh 单列但复用 SSH 表单，仍 `protocol: mosh`。列表图标按连接类型显示，未知类型继续原样保留。
5. **验收**：补齐每类型创建/保存/重开、SSH↔Mosh 字段、插件卸载/撤权、纯远控无 SSH 字段、旧绑定与 pending 迁移、写入/读回失败、重复迁移/进程中断、秘密不导出，以及 Android 模拟器回归。远控假平台只证明调用和拒绝逻辑，不能当真实设备控制成功。
