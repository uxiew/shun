## 做了什么

- `plugins/provider-sdk`：宿主与插件共用的一份契约（纯 Java + AIDL）：`IXwshunProvider.handshake/ping`、宿主回调 `IXwshunHost.onProviderEvent`（oneway），
  以及两个认人工具：`SignerDigests`（系统读出的**当前**签名证书，API 28+ 用 `getApkContentsSigners`，不含轮换历史）、`CallerVerifier`（每个事务用 `Binder.getCallingUid()` 核对包名 + 证书，每次重读证书不缓存）。
- 宿主 `PluginBridge.kt`：`<queries>` 只加插件 action，合并后的清单没有 `QUERY_ALL_PACKAGES`（`aapt2 dump permissions` 核对）；描述符从插件清单 meta-data 指向的 raw 资源读，**批准前不绑定、不执行插件代码**；
  连接前再核一次证书仍是批准那张，显式组件绑定；握手返回的 pluginId 与批准不符即断开；宿主回调每个事务核对调用方。
- Dart：`AndroidPluginBridge`（通道）、`PluginApprovalStore`（批准记录：pluginId + 包名 + 证书 + 能力，只含公开摘要）、`PluginDiscovery`（把桥报告的事实交给 X01 的 `PluginRegistry` 判定）。
  注册表新增：描述符自称的服务类必须等于实际声明 action 的服务；平台层问题（没导出、一个包多个服务、描述符超 16 KiB）判不兼容；只有 debug 构建放行 Android 调试证书签的插件（仍需批准）。
- 「设置 → 插件（实验）」最小页面：列出、批准（弹窗显示完整证书 SHA-256、能力和权限边界）、撤销、连接测试、某包为何不可见的诊断、事件记录。完整插件管理是 X04。
- 测试 APK（`plugins/`，用法见 `plugins/README.md`）：作者自签 echo 及冒牌/转交/调试证书三个变体、rogue。测试密钥在仓库外 `.toolchain/plugin-keys/`。

## 发现的问题（已修）

- **插件换签后用户没法重新核对**：「已拒绝」的条目没有撤销按钮，作者正常换密钥时只能卸载重装。现在只要有批准记录就能撤销（678550b，有单测）。
- 契约层的 bundled 冒充漏洞在 X01 已修（33872f4）；本批的真实 rogue 冒用 `builtin.ssh` 走的是另一条规则（保留 ID）。

## 未测与局限

- **没有真机**；Android 7–10（API 24–29）上的发现与证书读取路径（`GET_SIGNATURES`、无包可见性限制）没测：模拟器镜像按省空间要求已删。
- 连接前「证书仍是批准那张」的二次核对（防判定与绑定之间换包）只有代码，没有构造出竞态来测。
- 多证书共同签名的插件暂不给批准；签名轮换历史不认，作者换密钥即视为换签。
- 会话打开/关闭、FD 数据面、provider 死亡与更新时的会话处理：X03/X04。
- 插件页不是完整管理界面（没有启停、更新检测、设置入口）：X04。
