## 做了什么

- **所有入口一条路线（RTE04）**：全仓只有 `SshService` 一处造 `SSHClient`、一处拨 TCP，都按 RoutePlan；SFTP、服务器监控、系统管理、端口转发都借用这条已验证的目标连接。没有 SSH 的「连接测试」入口（「测试连接」只存在于 S3 同步，不涉及 SSH）。
- **服务器间直传改为先征求同意**：以前跨服务器复制会自动先在源服务器上执行 `sftp` 连目标——不经手机为目标选定的路线，目标身份用的是源服务器的 known_hosts，且探测本身就是一次这样的连接。现在弹窗让用户选「手机中转」或「服务器直传」，选了直传才探测。同服务器内部复制不受影响。
- **私钥在拨号前解析（SEC06）**：口令错 / 没存口令 / 格式不对 / 设成只用私钥但私钥被删，都在拨号前按那一跳说人话，报错不带私钥原文。解出来后自签自验：OpenSSH 新格式私钥用 aes256-ctr、无完整性校验，实测翻转一个字节 dartssh2 照样「解密成功」，现在会被拦下。
- **keyboard-interactive**：没有界面时只对「恰好一个、明确问密码、不是新密码/验证码/PIN」的提问填一次保存的密码；零个提问回空列表。有界面时仍由用户手填（上游行为未变）。
- **信任按逻辑名的规范写法比对（SEC04）**：大小写、结尾的点、IPv6 方括号和缩写视为同一台；不做 DNS 解析，同一 IP 的另一个名字、换端口仍要重新核对。
- **凭据脱敏（REG03）**：`HostProfile.toString` 不再输出整份 JSON（以前含明文密码）；导出不含密码、私钥、代理口令（上游原测试断言导出里有明文密码，这里有意反转）；导入时同一条目、登录目标没变才沿用本机凭据。
- **解不开的凭据（SEC06）**：逐条读，解不开的记下、其余照常；用到它的连接在拨号前拒绝并说明；保险库页顶部提示；无关保存不删那条密文。另记「存过凭据的键名」清单（只有键名），用来认出 Keystore 失效后插件「静默读成空」的情况。
- **SFTP 握手期限**：dartssh2 的 `sftp()` 不看子系统请求的回复，服务器没开 SFTP 时无限等待；现在 10 秒报原因。
- **连接瞬间失败不再让 App 被杀**：保活前台服务还没 `startForeground()` 就被 `stopService()`，Android 12+ 直接杀进程（上游就有，任何拨号前失败都会触发）。现在延迟到服务进前台后自停。
- **备份排除（SEC05）**：加 `dataExtractionRules`，云备份和设备间迁移每个数据域都 `exclude path="."`。

## 发现并修掉的上游/依赖问题

| 问题 | 怎么发现的 | 后果 |
|---|---|---|
| `HostProfile.toString` 是整份 JSON | 读代码 | 主机对象进报错/日志即带出明文密码 |
| 导出是解锁后的完整保险库 | 读代码 + 上游测试断言 | 导出文件里明文密码、私钥 |

## 未测项与局限

- 没有真机；模拟器是 AOSP，不代表厂商 ROM（尤其 D2D 迁移和 Keystore 行为）。
- 真正的 Keystore 密钥作废（比如去掉锁屏）没有做，是用改坏密钥集模拟的。
- 服务器间直传的命令本身没改：它仍用源服务器自己的公钥和 known_hosts（StrictHostKeyChecking=yes），用户选了直传就按这个走。
- 有界面时的 keyboard-interactive 仍每次手填，不会预填保存的密码（上游行为）。
- 同步（默认关闭）上传的是带凭据的保险库，本批没动；属于同步功能本身的授权范围。
- 端口转发断线后条目不自动撤、SFTP 页不提示「连接已换代」：R24。
- 用户在指纹确认弹窗打开时取消，弹窗不随之关闭（R08 记录过）：未处理。
