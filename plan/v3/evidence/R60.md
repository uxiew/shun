## 实测发现的

**系统文件选择器覆盖旧文件时不截断。** 用 file_picker 10.3.10 写，879 字节盖 680579 字节的旧文件，读回来还是 680579 字节（`wrote=879 read=680579`）。改成自己用 `"wt"` 写后 `wrote=879 read=879`。不修的话，加密备份盖到不含密码的 JSON 上，尾部就是明文主机名。原来的明文导出也有这个问题，短文件盖长文件后 `jsonDecode` 会报错，一起修了。

**算口令的耗时**（PBKDF2 60 万次，模拟器 AOT）：加密 2837–2904 ms，解密 2714–2793 ms；机器忙的时候到过 7418 ms。所以放后台 isolate，界面转圈。云同步现在是在主线程算的，R61 要看。

**测试工具的坑**（后面写设备脚本用得上）：API 30 的文件选择器列表不理 `input tap`、`input swipe`、`input motionevent`，按钮理；键盘 Tab 到列表项再 Enter 能选中。只 `rm` 文件不删媒体库条目，选择器会列出打不开的旧文件。

## 没测的

- **手机**：上面是 API 30 模拟器。所有者的手机系统更新，文件选择器的界面不同，存和选要实际走一遍。
- **云盘存储服务**（Google Drive、OneDrive 的 App 作为选择器里的目的地）：没有账号，没测。不认 `"wt"` 会退回 `"w"`，尾巴读的时候不理。
- **设置页从头到尾**：页面测试到口令框为止，设备测试从服务层开始。口令框之后接存文件、选文件之后接确认框这两个接头只有代码、没有测试。
