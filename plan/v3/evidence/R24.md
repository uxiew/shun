## 做成了什么样

文件页、端口转发、性能监控、系统管理都不拨号，借标签上已登录的那条 SSH（`SshLease`）。一个会话对象就是一代连接：断了、标签关了、切到 Mosh 了，借用者几秒内报错，标签恢复成新连接以后也不接上去，要用就从新连接重新打开。报错分两种：

- 「……的 SSH 连接已断开，这一步没有执行」（`ConnectionGone`）：什么都没发。
- 「……：请求发出后连接断了，不知道服务器上有没有做成」（`OutcomeUnknown`）：只有会改服务器的一步（写文件、改名、删除、发信号、停 / 删容器、拉镜像、保存 Caddy 站点……）才会报，不重发。

各自断线后的样子写在使用手册第 7 节，传输的三种结果和临时文件在第 11 节，这里不重复。

## 验收逐条

| 验收 | 怎么验的 | 结果 |
|---|---|---|
| 借用 client 同一目标 / 代次 | 单测：借不到断开的标签；`SshLease.reuse` 连着时是同一个借用、断了报 `ConnectionGone`。真实 OpenSSH：三条路线断线后标签自己恢复，旧的文件服务、监控仍报 `ConnectionGone`，`forwardsOn(新连接)` 为空；模拟器上同样（下节） | 过 |
| 关闭 SSH 后借用者失效 | 真实 OpenSSH「REG01 关标签」：文件页、转发、监控开着时关标签，各报 `ConnectionGone`，转发原因「标签已关闭」、本机端口连不上，ss-edge 内核连接表里 22 端口的 ESTABLISHED 归零，之后 1 秒没有新拨号。「REG01 经跳板」：终端 + 文件页开着时只杀目标上的会话，旧一代的目标和跳板 client 都关了、跳板上只剩新一代的 1 条连接。释放顺序单测 4 条 | 过 |
| 不自动重传有副作用请求 | 真实 OpenSSH 三条路线：断线时在路上的原地写报 `OutcomeUnknown`，覆盖 `keep.txt` 的上传报 `TransferInterrupted`，都在 5 秒内；恢复后从新连接读 `keep.txt` 仍是 `original`。断了以后的 `signalProcess` 报 `ConnectionGone`（没发）。单测：发出去以后断的 `signalProcess` 报 `OutcomeUnknown`，并写明「进程信号「4242 TERM」」 | 过 |
| 路由无旁路 | 真实 OpenSSH 三条路线：`RecordingDialer` 记下的所有拨号（含自动恢复）只有入口一个地址：Direct 和 Jump 是 ssh-edge，SOCKS 是 dante。转发、监控、系统管理、文件都在这条连接上跑 | 过 |
| 预览有上限，不把大文件读进内存 | 单测：`readBounded` 对 10 MiB 的文件只读到上限多 1 字节就停；列表里的大小过时时同样停。真实 OpenSSH：1 MiB + 1 字节报 `PreviewTooLarge`。模拟器：三条路线点它都只弹「文件太大，不在这里打开」、没开编辑器 | 过 |
| 取消 / 代次变化 / 覆盖结果未知可区分；断线不重传写 | 真实 OpenSSH 三条路线：取消报 `TransferCancelledException`、目标不出现；断线分别报 `TransferInterrupted` / `OutcomeUnknown`；换代后旧的报 `ConnectionGone`。界面的三种提示和替换 / 续传框在 widget 测试里。模拟器：断线后文件页写「……的 SSH 连接断开了，这一栏换成了别的来源」 | 过 |

停止条件「未审查入口可明确禁用，不留可点击的失效菜单或默走 Direct」：四个借用者这次都审了。断开的 SSH 标签上，终端快捷栏的「端口转发」「系统管理」变灰，端口转发面板的「启动」、监控的「刷新」「重试」点不了，系统管理整页变灰并写明原因（widget 测试）；主机 ⋮ 菜单里的文件 / 转发 / 监控本来就只在有连着的 SSH 标签时出现（R43）。没有任何借用者自己拨号，上面 RTE04 那条按拨号记录验了。

## 顺手修掉的问题

都是这次先写测试、在真实 OpenSSH 或模拟器上撞出来的：

- 终端 + 文件页开着时断线，`abort()` 抛 `SSHStateError`，跳板不关、标签不进自动恢复（dartssh2 关 client 时每个没发过 EOF 的通道都抛一次）。
- 断线时还在等回复的 SFTP 请求永远不返回：上传进度条断线后 15 秒仍挡着，之后列目录也卡。
- 取消上传：dartssh2 的 `SftpFileWriter` 订阅数据流时没挂 onError，取消变成未捕获错误、远端句柄不关（三条路线都复现）。
- dartssh2 的 `rename` 走 posix-rename，会悝悝替换已有文件：改名前再查一次目标。
- 监控的 `start()` 先采样后建定时器：断开的标签上采样当场 `stop()`，返回后又建了每 3 秒的定时器。

## 没验的

- 真机、API 35、iOS。iOS 上传走另一条写法（`_writeSftpStreamWithLimitedConcurrency`），取消时还在路上的块写没有专门测。
- 设备上的上传、下载、中途取消、替换 / 续传框：要走系统文件选择器，没放进设备测试。调的是同一个 `writeStreamAtomically` / `transferEntry`（真实 OpenSSH 上测了），弹框和提示只有 widget 测试。
- 设备上的端口转发、性能监控、系统管理断线后的样子：只有 widget 测试（假连接）和真实 OpenSSH 的服务层测试。模拟器上自动恢复 1 秒内就完成，变灰的那一下不好截。
- 系统管理里「发出去以后断」只用假连接测了发信号一种；Docker / 服务 / Caddy 的操作走同一个 `_changing`，但没在有这些服务的真实机器上断过。
- 编辑器保存前的核对只看大小和修改时间（秒）：打开后同一秒内被改、大小又没变的，看不出来。设备测试里故意改成了不同长度。
- 「最后再查一次」到改名之间有一次来回的空当，这时别人放进来的同名文件仍会被替换（dartssh2 没有不覆盖的改名）。手册写了。

## 留给后面的

- 上面三个 dartssh2 的问题（SFTP 断线不回复、writer 不接错误、关 client 逐个抛错）可以报给上游；现在是在我们这边绕开的，升级 dartssh2 时要重跑 R24 的两组测试。
- 编辑器顶栏在「保存中…」时文件名被挤成「…」（1080 宽的屏幕上，截图 `jump-03-changed-on-server.png`）。不影响功能，可以并进 R25 的界面整理。
- 「已停止」的转发只能去掉、不能一键在新连接上重开（故意的：本机端口对手机上别的 App 开着）。所有者想要「重开」按钮的话再加，仍然要用户自己点。
