# R16 实施证据：Session 与 xterm2 解耦

状态：DONE。连接层、会话控制器、终端页都不再认识 xterm2；中间是一层很薄的 `TerminalSessionAdapter`，
xterm2 退成"旧引擎适配器 + 它的视图"两个文件，仍是默认引擎和对照基线。R17 接 Ghostty 只需加一个适配器、一个视图，再改一处默认值。

任务ID / 执行者 / 时间：R16 / Claude（Opus 5.5）/ 2026-10-04
提交：5de6e88（解耦）、f9fd435（测试）
设备：没上模拟器或真机，界面靠 widget 测试（用的是真的 xterm2 `TerminalView`），字节通路靠本机 Docker 里的真实 OpenSSH（`tool/fixture-environment`）

## 改成了什么样

```text
SSH / Telnet ──原始字节──> TerminalSessionAdapter.feed        （连接层不再转字符串）
SSH / Telnet <──字节──── bind(input, resize)                   （同一时刻只有一个有效绑定 = 当前代次）
SessionController：按标签创建终端（terminalAdapterFactoryProvider）、关标签时释放；恢复沿用同一个
终端页 ──terminalViewFor(adapter)──> 各引擎自己的视图（现在只有 XtermTerminalView）
```

| 文件 | 作用 |
|---|---|
| `lib/infrastructure/terminal/terminal_session_adapter.dart` | 接口 + 各引擎共用的规矩：代次绑定、视图占用、释放后一律忽略 |
| `lib/infrastructure/terminal/xterm_terminal_adapter.dart` | 旧引擎。整条流共用一个 UTF-8 解码器；换代次时丢掉上一代残留的半个字符；xterm2 的剪贴板/链接/通知等效果回调一个不接 |
| `lib/infrastructure/terminal/terminal_text.dart` | 画中画、AI 上下文取文本，只用适配器的逐行接口（原来直接读 xterm 缓冲区） |
| `lib/infrastructure/terminal/terminal_input_controller.dart` | 快捷键栏一次性修饰键，从 ssh_service 挪来；归终端，恢复时跟着终端走 |
| `lib/application/terminal_engine.dart` | 默认引擎只在这里选（R17 改这一处） |
| `lib/presentation/terminal/terminal_view.dart`、`xterm_terminal_view.dart` | 按适配器类型挑视图；xterm2 的选区手柄、复制、`TerminalView` 原样搬进来 |

终端归属：`SshService.connect` 的 `terminal` 改成必填，连接层从不创建或释放终端。新开连接由会话控制器创建，
没进标签（失败、取消、迟到的成功）就地释放；关标签、控制器销毁时释放；`ActiveTerminalSession.close()` 只断连接，不碰终端
——恢复途中被放弃的新连接和标签共用同一个终端，原来的 `close()` 会把它一起销毁。

## 验收

| 验收项 | 结果 | 证据 |
|---|---|---|
| SSH 层不依赖 xterm2 具体类型 | 是 | `test/terminal_layering_test.dart`：`lib` 里只有适配器和它的视图导入 xterm2；连接层、传输层、application、终端页、部件里出现引擎专用类型就失败（选默认引擎、挑视图的两个文件除外） |
| 字节不按包 String 转换 | 是 | 连接层 `session.stdout.listen(terminal.feed)`、Telnet `terminal.feed(...)`；`decodeTerminalText` 已删。`test/terminal_output_decoding_test.dart` 4 组素材 × 20 个随机切包 + 逐字节，经适配器后终端状态、光标、DA 回应都和整块输入一致；真实 sshd 输出 2000 遍中文+emoji 无替换符（TER01 用例，沿用） |
| UI 重建不控制 SSH 生命周期 | 是 | `test/terminal_view_ownership_test.dart`：在真实 TerminalScreen 上切标签、开分屏、横竖屏旋转、进出画中画、整页卸掉再装回，`connect` 调用 0 次，两个终端都没被释放、内容还在、没被关；每一步核对显示权在该在的视图上；只有关标签才释放该标签的终端 |
| legacy baseline 仍可用于对比 | 是 | xterm2 仍是默认引擎，走同一个接口；R17 把同一份 `test/fixtures/vt/vt_samples.dart` 喂给两个适配器，对比 `allText()` / `lineAt()` 即可 |

停止条件"不能只换 import 却保留大量 xterm 专用访问穿透"：改前 3 个 `lib` 文件导入 xterm2（ssh_service、画中画服务、终端页），终端页和会话控制器里 36 处直接用 xterm 的 Terminal、缓冲区、`CellOffset`；
改后只有适配器和它的视图 2 个文件，终端页、会话控制器一处都没有，并由分层测试守住。

## 测试

- 全量（Docker SSH 测试环境开着）：**811 通过、1 跳过、0 失败**；之后加的恢复窗口大小测试单独跑通过。`dart analyze` 无问题，格式无改动。
- 新增 17 条：适配器 11、分层 4、视图所有权 1、真实 OpenSSH 恢复窗口大小 1。
- 现有测试只做了适配：`connect` 补上 `terminal:`、`Terminal()` 换成 `XtermTerminalAdapter()`、写终端改成 `feed`。

变异验证（每次改坏一处，跑对应测试，再改回）：

| 改坏什么 | 结果 |
|---|---|
| 旧视图释放显示权时不查代次 | 视图所有权测试失败 |
| 旧绑定释放时不查代次 | "旧代次晚到的释放不会把新代次也解掉"失败 |
| 换代次不补发尺寸 | 适配器测试失败；真实 OpenSSH 测试失败，恢复后 `stty size` 是 `24 80` |
| 换代次不清解码器 | "半个字符不和新 shell 拼成乱码"失败 |
| 关标签不释放终端 | 视图所有权测试失败 |
| 终端页销毁时顺手释放终端 | 视图所有权测试失败 |
| 接上 xterm2 的剪贴板查询回调 | SEC09 测试失败 |

## 顺带修的旧 bug：恢复后远端窗口停在 80x24

新 shell 的 PTY 按 80x24 打开（`SSHPtyConfig`），靠终端的 resize 通知改成真实尺寸。xterm2 在尺寸没变时不通知
（`Terminal.resize` 源码），恢复连接沿用同一个终端、尺寸当然没变，于是远端一直是 80x24，直到屏幕尺寸再变一次，
期间 vim、htop、tmux 排版是错的。现在绑定新代次时，终端已经量过尺寸就立刻补发一次。真实 OpenSSH 上：终端 132x43，
断线恢复后新 shell 里 `stty size` 是 `43 132`；去掉补发是 `24 80`。用户手册第 7 节已写。

## 没做的

- 模拟器、真机上没跑主 App 的终端页（R17 上设备时一起做：旋转、切后台、分屏）。
- Ghostty 适配器和视图（R17）。

## 给 R17 的话

- 关标签时会话控制器**立刻**释放终端，视图下一帧才卸下。xterm2 纯 Dart 无所谓；Ghostty 的视图每次碰 controller 之前都要先看
  `lease.isActive` / `isDisposed`，否则就是 native 释放后使用。
- 修饰键现在在 xterm2 适配器里对 `onOutput` 的字符串做；Ghostty 应该走它自己的按键编码（`sendKey` 带修饰），别把方向键当文本。
- 和 xterm2 对齐要逐项核对的功能：选区手柄和复制、备用屏长按复制快照、鼠标模式（tmux 滚动不变方向键）、`deleteDetection`、
  敏感键盘（visiblePassword）、主题色和字号、透明背景、画中画文字、AI 上下文、自动聚焦。
