## 做了什么

- `lib/infrastructure/tailscale/tailscale_api.dart`：只发两种请求——`POST /api/v2/oauth/token`（表单，`scope=devices:core:read`）和 `GET /api/v2/tailnet/{tailnet}/devices`（默认字段集、无查询参数）。
  生产 origin 写死 `https://api.tailscale.com`；测试入口只接受本机回环地址。
- 不跟随任何重定向；401 只做一次受控刷新（仅 OAuth 模式）；403/404/429/5xx 不重试，429 带回 Retry-After；没有定时器、没有后台轮询。
- token 权限以服务器返回的 scope 为准：只有 `devices:core:read`/`devices:read` 才算「只读设备」；带任何非 `:read` scope 的 token 直接丢弃、一次都不用；粘贴的 token 一律「范围未验证」。
- `catalog_secret_store.dart`：OAuth client 存在**另一个**加密偏好文件（`xwshun_tailscale_catalog`，iOS 另一个钥匙串账户），不和保险库混放；只存 client id/secret 两项，不存 access token。
- `lib/application/tailscale_catalog_access.dart`：三个入口（粘贴 token 读一次 / OAuth 读一次，可选持续刷新 / 用已保存 client 刷新）。
  持续刷新只在用户要求、且服务器确认 token 只读设备时才落盘；范围未验证或偏大都不存。刷新遇 401 不删已保存的 client。
- `tailscale_device.dart`：只留目录用得到的 15 个字段，丢掉 machineKey、nodeKey、tailnetLock*、clientVersion 等；缺字段或类型不对记为不知道；缺 id、重复 id 让快照标为不完整（R12 据此不推断删除）。
- 报错文本里抹掉服务器回显的凭据原文；凭据对象的 toString 不含 secret；所有报错在英文界面下能译完。
- 界面不在本任务：目录页和导入流程是 R13。

## 外连与副作用

- 调研官方口径时，调研代理用明显的假凭据向 `api.tailscale.com` 的 token 端点和列设备端点各发过几次请求，只为看失败响应的形状（记录在 docs/05 的「实测」处）。没有使用任何真实凭据。
- 模拟器上的种子入口覆盖了 App 数据（该模拟器上本来就没有保险库数据），验完已装回正式版 debug 包。
- 设备验证全程只连本机 fixture，没有连 Tailscale。

## 未测与交接

- 真实 Tailscale 账号下的行为（真实 scope 回报、真实 429、tailnet 名大小写、共享设备可见性）都没测，需要所有者提供一个只含 `devices:core:read` 的 OAuth client 才能做。
- 官方 issue tailscale#16911：OAuth token 看不到共享进来的设备。R12/R13 要在界面上说明，不能把「这次没看到」当成设备被删。
- R12（缓存与非破坏合并）依赖已满足。R13 加粘贴 token / client 的界面后复测 TSC09 的剪贴板部分。
