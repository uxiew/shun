## 改成了什么样

| 问题（来源） | 现在 |
|---|---|
| 微信输入法语音一句话整段发 9 次（R04 问题 8，TER02 FAIL） | flterm 提交后不再清空编辑区，记下已发的字；输入法改写时按差异补发：先退格删掉改了的部分，再发新尾巴。组字中只发组字区之前确定的字，组字区里和已发相同的那段留在远端，其余当预编辑显示 |
| 输入法用 finishComposingText 结束组字，组字区的字要拖到下一次改文字才提交（R18 在设备上发现） | 组字中收到空编辑列表就当组字结束。根因在 Flutter 引擎：Android 的 delta 模式只为 replace 和 setSpan 记编辑，finishComposingText 只删 span（`engine/.../ListenableEditingState.java`），平台通知框架时带的编辑列表是空的 |
| 软键盘回车键后紧跟一次提交，整条命令被重发（8711b1a 引入的回退，设备上发现） | 清空编辑区后、平台跟上前，oldText 对不上的编辑只按它自己的增量处理；软键盘回车键也参与回车去重 |
| 快捷键栏方向键写死 `ESC [ A`，vim/less 打开应用光标键后乱跳（R17「没做的」） | 终端接口加 `sendKey`：Ghostty 交给 flterm 编码；xterm2 自己的按键表编修饰键有错（Alt+↑ 编成 Ctrl 的 `ESC[1;5A`、Alt+Tab 丢 Alt），按 cursorKeysMode 挑前缀、修饰键照旧由 consume 套 |
| 「安全键盘」对 Ghostty 不起作用（R17「给 R18 的话」） | flterm 加 secureTextInput，开了输入框是可见密码 |
| 分屏时快捷键栏固定发给当前标签，Ctrl 挂到另一格上 | 快捷键栏跟着有焦点的那一格，那一格描边；换格时上一格的修饰键清掉 |
| 切到后台再回来，快捷键栏的 Ctrl 还亮着 | 退后台清掉所有标签的修饰键（切标签走换格那条路） |
| 横屏弹键盘时整列溢出 64dp，终端 0dp，远端停在 5 行（R17 发现的问题 1，TER06 FAIL） | 剩余高度 < 480dp 快捷键栏收成一行（操作按钮进「更多」），< 260dp 再收起标签条 |
| 快捷键实际只有约 20dp 高能点到；操作按钮 40dp；标签 chip 38dp；终端区没有无障碍标签 | 48dp；终端区报「终端：主机名」 |

## 输入法回放（TER02 的模拟器部分）

真机上的语音输入没法自动化。`plugins/fixture-replayime` 是一个只认 adb 广播的测试输入法，按脚本对输入连接做真实输入法那样的调用，
走真实的 Flutter 引擎 → 终端 → SSH；远端在 raw 模式下用 dd 逐字节收，再按 PTY 行编辑规矩（退格删一个码点）还原。
跑法 `tool/ime-replay.sh emulator-5580`。微信语音脚本照 R04 真机日志：每次更新先「文字不变地结束组字」、2 ms 后把组字区圈回刚出现的字、
紧接着改写。

| 脚本 | Ghostty 远端收到（十六进制、还原后的行） | xterm2（对照） |
|---|---|---|
| 微信语音（6 版识别结果） | `你` `好，` `你谁` 7f×3 `啊，你谁` 7f `是谁？` `在一` → 「你好啊，你是谁？在一」，退格 4 个 | 「你你好，你好，你谁你好啊，你谁…」整段重复，0 个退格（和 R04 真机一样） |
| Gboard 拼音：nihao 选「你好」、ceshi 删光、退格、混排 | `你好` 7f ` ok` → 「你 ok」 | 同 |
| 圈回已上屏的 ab 改成 ac | `ab` 7f `c` | `abac` |
| a👍 后删 emoji | `a👍` 7f（一个退格） | 同 |
| 空编辑区退格两次 | 7f 7f | 同 |
| finishComposingText 结束组字 | `你好` | 同（xterm2 不用 delta 模式） |
| 回车键后马上打 x | `echo R18-ENTER` 0d `x` | 同 |
| 回车键后输入法补一个换行 | `echo R18-N` 0d | 多一个 0a |

修 b63c843 之前在设备上实测：回车键后的提交把整条命令重发（`echo R18-ENTER` 0d `echo R18-ENTER` 0d）；finishComposingText 后远端什么都没收到。

开发途中查到的两件事：
- 平台报上来的编辑逐条打出来看过（只在本机临时加打印，没提交），形状和单元测试里的假输入法一致；finishComposingText 那一步确实没有编辑。
- 第一次回放时 Ctrl-C 和最后几个字同一次到达，tty 收到中断字符把还没被读走的字清掉了，看着像 App 丢字；
  另外交互式 shell 见前台命令被 SIGINT 杀掉会放弃后面整串命令。采集改成 noflsh、dd 包在接住 SIGINT 的子 shell 里。

## 真机复测（TER02，2026-10-06）

所有者当天同意并本人操作。Pixel 9 Pro（Android 17，接在 xdwmbp 上，经 `tool/remote-device` 在本机用），手机自己的微信输入法
（`com.tencent.wetype/.plugin.hld.WxHldService`），Ghostty 引擎，debug 包。手机连 22201 经 adb reverse 落到 xdwmbp，再经 ssh -R 回本机的测试环境（7330cd5）。
跑法 `tool/r18-real-device.sh`，测试 `integration_test/r18_voice_device_test.dart`：说明打在手机终端里，人照着做、按回车结束一项，远端逐字节收，回车后再收 3 秒。
整轮 3 分 36 秒。

| 项 | 所有者做的 | 远端还原出的行 | 字节里看到的 | 结论 |
|---|---|---|---|---|
| 拼音候选 | nihao 选「你好」、shijie 选「世界」、回车 | 你好世界 | 12 字节汉字、`0d` | 过 |
| 拼音删字 | jintian 选「今天」、退格一次、ming 选「明」、回车 | 今明 | `今天` `7f` `明` `0d 0d 0d 0d` | 字对、退格 1 个。多 3 个回车是所有者连按了几下（所有者确认），测试因此判了失败，见下 |
| 撤销拼音 | 打 zhongwen 不选、退格删光、回车 | （空） | `0d 0d` | 拼音字母一个都没发出去。多 1 个回车同上 |
| 中英混排 | ceshi 选「测试」、英文 abc、yixia 选「一下」、回车 | 测试abc 一下 | 空格 `20` 在 abc 后 | 过；空格是输入法打完英文自动加的 |
| 语音一句 | 说一句话、回车 | 你好啊，今天天气不错，我们出去走走 | 0 个退格、1 个回车 | 所有者确认是原话、只出现一遍 |
| 语音两句 | 说两句、中间停顿、回车 | 现在是什么时间呢？大概晚上 9:10 吧 | 0 个退格、1 个回车 | 同上 |

- R04 时同一台手机、同一个输入法，语音一句话整段发了 9 次；这次两段语音都只发一遍。
- 这次两段语音远端都是 0 个退格：微信输入法是先组字再一次提交，还是边说边改，远端字节看不出来（测试没记输入法的调用）。
  「边说边改」的调用顺序由模拟器回放覆盖（上一节，照 R04 真机日志）。
- 多出来的回车：按完回车屏幕要等 3 秒才换下一项，所有者以为没按上又按了几下。按一次的四项都正好一个回车。016166d 让远端收到回车马上在屏幕上提示，没有重跑这两项。
- 麦克风：这次装的包只声明 INTERNET、ACCESS_NETWORK_STATE、WAKE_LOCK、POST_NOTIFICATIONS、FOREGROUND_SERVICE、FOREGROUND_SERVICE_SPECIAL_USE，
  外加 Android 构建自动加的 `top.xdwa.xwshun.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`，没有 RECORD_AUDIO，App 申请不了麦克风；语音由输入法自己录。
- 现场：开始和结束时默认输入法都是微信输入法，没被改动；flutter test 结束时卸掉了 App（`pm list packages top.xdwa` 为空）；
  手机上的反向转发、xdwmbp 上的 22201 端口都撤了。为了不让「允许通知」挡住键盘，测试期间给被测 App 预授权了通知，App 卸掉后随之没了。

## 发现的问题

1. **Flutter Android 的 delta 模式丢掉 finishComposingText**（引擎问题，上游 flterm 一样受影响）：fork 已绕过，没给 Flutter 报。
2. **xterm2 的按键表编修饰键有错**：`keyInput(arrowUp, alt: true)` 出 `ESC[1;5A`（Ctrl 的参数），`keyInput(tab, alt: true)` 丢 Alt。没用它。
3. **快捷键实际可点区域只有约 20dp**（上游就有）：已改。
4. **Ghostty 不跟系统字体大小**：终端字用设置里的字号。要不要跟，留给 R25。
5. 设备测试里撞的墙（通知权限框挡键盘、adb root 清端口转发、假时钟下 flterm 空闲任务遇上按钮动画让 pump 死循环、
   pkill 误杀别的 worktree 的测试）写进了本机手册第 7 节。
