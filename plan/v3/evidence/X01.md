## 做了什么

- 主 App 以 path 依赖接入 `packages/plugin_api`（没有拆新 package）。
- `lib/domain/plugins/builtin_plugins.dart`：内置 `builtin.ssh`（SSH + Telnet 终端与保险库主机）、`builtin.route`（直连/SOCKS/跳板）。
  Telnet 不单列 provider：它和 SSH 共用 SshService 和主机列表，拆开的话改一下协议设备引用就换了主人。
- `lib/application/plugin_registry.dart`：`PluginRegistry`（Riverpod `StateNotifier`）。
  - 内置 provider 在构造时同步登记，不等任何发现或 IO：一个外部包都没有时 SSH 已是 Ready。
  - 把「系统报告装了哪些包 + 用户批准 + 用户停用」合成每个 provider 的状态：ready / needsApproval / rejected / incompatible / disabled / missing。准入判定全部交给 plugin_api 的 `AdmissionPolicy`，这里不另写一套规则。
  - 同一 pluginId 两个包：有匹配批准的先评估，另一个因「已被占用」被拒——结果与安装先后无关（测试两种顺序都跑）。
  - 插件会话登记在 registry：登记时 provider 必须 Ready 且声明了对应能力，否则当场关掉。停用、撤销批准、换签、卸载只关该插件自己的会话。内置 SSH 会话不进这张表，仍由 SessionController 管（R08 的代次规则在那里，旧路径不动）。
  - `require(pluginId, capability)`：不可用抛 `PluginUnavailable`，没声明抛 `UnsupportedCapability`，不返回空结果。
- `lib/domain/device_references.dart`：保险库主机的设备引用只认主机 id（改名、换地址、换协议不变）；`availabilityOf` 区分 provider 缺失 / 装着但不可用 / 可用，只读、不删任何引用。
- plugin_api 新增 `DeviceLinks.unlinkRef`：只把一条引用移出记录，其余照旧关联；只剩一条时记录解散。

### 顺带补的契约漏洞（33872f4）

`AdmissionPolicy.evaluate` 的 bundled 分支不走批准、直接按宿主签名放行，但以前不检查它是不是真的随包内置：
**任何单独安装的 APK 在描述符里写 `deployment: bundled` 就能跳过用户授权和证书核验。**
现在 `installedPackage != null` 且自称 bundled 一律拒绝；registry 另外只允许宿主代码登记内置 provider。
新增测试在旧代码上失败（`+27 -1`）、新代码上通过（28/28），已先后实跑确认。

## 验收对照

- 不按名字/IP 自动合并设备：主机引用只认 id；`DeviceLinks` 没有自动合并入口（X00）。
- 没有所有能力共用 connected 布尔值：插件会话按 Terminal / RemoteDesktop / ExternalLaunch 分型各带状态；外部拉起的状态里没有「已连接」。SSH 标签上的 `connected` 只属于那一条 SSH 连接，没有被别的能力复用。
- 核心 SSH 不依赖外部插件存在：内置 provider 构造时同步 Ready；SSH 连接路径没有改动，也不查询 registry。
