## 结论先说

- **换网、断网（MOS06）**：一个 Mosh 会话连着，Wi-Fi 接管 → 切回蜂窝 → 整机断网 30 秒 → 断网 150 秒 → 后台里再切一来回，
  每一步之后命令都回来了（网络在时 100–130 ms，网络恢复后 2.5 / 3.2 秒）。整轮远端 mosh-server 只启动过 1 次、SSH 登录没增加，
  mosh-client 始终是同一个进程；断网时敲的两条命令远端各执行 1 次；终端输入 9 次 = 宿主写入 9 次。
- **崩溃和停止（MOS07、PLG16）**：mosh-client 段错误、插件崩溃、插件被强停、用户关标签、通知「全部断开」、系统停掉保活服务、
  宿主崩溃、宿主被强停：Mosh 标签都如实结束、写明原因；之后换网、进出后台、重新打开 App，**远端一次都没自己重起**，
  结束后敲的字写出 0 字节；点「重新连接」正好新起 1 个。
- **不影响已有 SSH（验收 2）**：上面 Mosh 这边的每一种出事，旁边的 SSH 标签都还是同一个对象、连着、命令照常回。
  「全部断开」和服务被停本来就是停所有会话，SSH 一起停，按设计。
- **TailSocks 路径继续 SSH + tmux（验收 3，模拟器形态）**：经本机 SOCKS5 的 SSH + tmux 标签，在旁边 Mosh 换网、插件崩溃、强停、
  重新连接、关标签的全过程里一直连着，远端 tmux 还是 `$0`、创建时间不变、客户端 1 个。真的 TailSocks App 没装。
- **后台和 Doze**：只有宿主一个前台服务（通知把 Mosh 标签算进「N 个连着」），插件没有自己的前台服务，靠被宿主绑着
  拿到同等优先级；强制深度 Doze（息屏）时插件 uid 的网络规则是 `fg svc / ALLOW_ALL`，会话照常收发。唤醒锁 0、媒体会话 0、音频焦点 0。
- **发现的问题**：① mosh-client 段错误、插件被强停时客户端来不及通知服务器，**远端各留下一个 mosh-server**，它默认永不超时、
  一直占一个 UDP 端口（提示里写了「远端可能还有旧会话」，没有自动回收）；② 断网期间宿主把 Mosh 标签显示成「已连接」，
  它只知道运行时还活着，真实网络状态只在 mosh 自己画的顶栏里。10-26 两条都改了：① 引导时让 mosh-server
  7 天收不到客户端就自己退出；② 状态改写「Mosh 运行中」并指到 mosh 的顶栏。见文末。
- **真机（Pixel 9 Pro，Android 17，出厂省电设置，第 7 节）**：
  - 所有者关 Wi-Fi 13 秒再开：同一个 mosh-client 接上，断开时敲的命令回来 2 秒内执行、远端只执行一次；
  - 拔线锁屏 34 分钟（其中深度 Doze 30 分钟）：**mosh-client 没被杀、没被冻**，每分钟都还在发包（灭屏后从 20 个降到 3–7 个），
    解锁后同一个会话第一条命令 1.1 秒回来；系统确实把 mosh-client 记成 phantom 进程，但只有这 1 个、没碰上限；
  - 段错误、插件崩溃、插件强停和模拟器上一样：不自己重起、不重发，旁边 SSH 不受牵连，留孤儿的也还是段错误和强停。
  - 22 项检查 0 项失败。
- **没测的**：真机上的真蜂窝漫游和运营商 NAT（BLOCKED，缺公网 UDP 主机）、真机上宿主被杀和「全部断开」、真 TailSocks、
  更长的锁屏和国产 ROM。见文末「支持矩阵」。

## 1. 换网、断网（MOS06，`roam-201922.log`）

Wi-Fi 连上时 wlan0 是 10.0.2.16、蜂窝 radio0 是 10.0.2.15，发出去的源地址真的会变；「断网」是关 Wi-Fi 再 `svc data disable`，默认网络变成 none，
恢复后系统给的是一张新网（编号变了）。每一步之后在会话里跑 `echo 标记-$((6*7))`，等 `标记-42` 回到屏幕上。

| 步骤 | 默认网络 | 命令往返 | 看到的 |
|---|---|---|---|
| 开会话 | 107 蜂窝 | 104 ms | mosh-client pid 9157，UDP 本地口 55531（没 connect，对端 0.0.0.0:0） |
| Wi-Fi 接管 | 109 Wi-Fi（1 秒内） | 刚切 103 ms，45 秒后 126 ms | pid、本地口都没变：没 connect 的 socket 每次发包按当时的默认路由走 |
| 关 Wi-Fi | 107 蜂窝 | 102 ms | |
| 断网 30 秒 | none → 110 蜂窝 | 网络回来后 2.5 秒 | 断网时终端顶上 mosh 自己写「Last contact 14 / 30 seconds ago」；宿主标签仍是「连着」、插件会话 active；断网时敲的一条命令宿主当场写了 1 次；回来后顶栏消失 |
| 断网 150 秒 | none → 111 蜂窝 | 3.2 秒 | 顶栏「sendto: Network is unreachable (1:13 / 2:28 without contact.)」；其余同上 |
| 后台（HOME）里 Wi-Fi 接管 45 秒、再关掉 | 112 Wi-Fi → 111 蜂窝 | 127 / 104 ms | 保活服务在、通知「1 个连着」 |
| 回前台 | | 105 ms | |

整轮合计：

- 远端 mosh-server 启动 +1（只有开会话那次），开完以后 SSH 登录数一直是 15（最后 +1 是测试自己的检查连接）。宿主没有重新 bootstrap。
- mosh-client 从头到尾是 pid 9157。断网之后它的 UDP 本地口从 55531 换成 42431：这是 mosh 自己长时间收不到回应时换端口，不是宿主做的。
- 宿主一次都没把标签判断开（每 200 ms 看一次，0 次）。终端输入 9 次 = 宿主写入 9 次，丢弃 0 字节。
- 断网时敲的两条 `echo off30 >> /tmp/x10-roam.log`、`echo off150 >> …`：远端文件里正好 `off30`、`off150` 两行。宿主只写一次，
  网络回来后由 mosh 协议送到，没有重发。
- 关标签后远端 0 个 mosh-server，插件确认停止（stopConfirmed=true）。

**宿主说的和真的**：断网时宿主显示「已连接」。它不替 Mosh 判断网络（R22 的换网探活对 Mosh 只看插件会话还在不在），
「已连接」的意思实际是「运行时还在」。真实状态在 mosh-client 画的顶栏里，而且写得很直白（多久没联系上、网络不可达）。
用例要的「失败状态真实」在终端里做到了，在标签状态上没做到，见「需要所有者定的」2。

## 2. 崩溃、停止，旁边开着 SSH（MOS07、PLG16、验收 2，`life-204951.log`）

一开始开一个 SSH 标签和一个 Mosh 标签（主机存在保险库里，「重新连接」只认保险库里的）。每种事件之后：等 Mosh 标签结束 →
往它里面敲字 → Wi-Fi 接管 8 秒再关 → HOME → 回前台 → 等 15 秒 → 手动叫一遍「恢复断开的标签」，然后数远端启动数、看 SSH 标签，
最后点「重新连接」（和状态条上那个按钮同一个调用）。

怎么造崩溃：这台镜像的 SELinux 不让 run-as 给应用进程发 SIGKILL，所以 mosh-client 发 SIGSEGV（原生代码段错误的样子），
插件和宿主用 `am crash`（进程真报一次未捕获异常，logcat 里是 `FATAL EXCEPTION … RemoteServiceException: shell-induced crash`）。

| 事件 | Mosh 标签 | 终端里的说明（原文节选） | 远端 | 之后换网 + 进出后台 | SSH 标签 | 重新连接 |
|---|---|---|---|---|---|---|
| mosh-client 段错误 | 中断，`exit-139`，等用户 | 「mosh-client 被信号 11 结束。远端可能还有旧会话（mosh-server）。不会自动重连，也不会重发…」 | **留下 1 个 mosh-server** | 启动 +0；结束后敲的字写出 0 | 同一对象，118 ms | +1，原位置，106 ms |
| 插件崩溃 | providerDied，等用户 | 「Mosh 插件进程没了（被系统或手动结束）。远端可能还有旧会话…可以在服务器上用 pkill mosh-server 清掉…」 | 没留：插件一死 PTY 主端被关，mosh-client 收到 SIGHUP 通知了服务器 | 启动 +0；**插件进程没被拉起来**（40 秒后仍没有） | 同一对象 | +1 |
| 插件被强行停止 | providerDied，等用户 | 同上 | **留下 1 个**：mosh-client 跟着整个包被 SIGKILL，来不及通知 | 同上 | 同一对象 | +1 |
| 用户关 Mosh 标签 | closed，stopConfirmed | | 这个会话的退出 | 启动 +0 | 同一对象 | — |
| 通知「全部断开」（后台） | 和 SSH 一起停，等用户 | 状态条「已从通知「全部断开」。不会自动重连…」 | 这个会话的退出 | 启动 +0；保活服务、通知都没了 | 按设计一起停 | — |
| 系统停掉保活服务（后台） | 四个标签都停，等用户 | 状态条「后台服务被系统停了，会话随之断开，没有自动重连…」 | 这个会话的退出 | 启动 +0 | 按设计一起停 | — |

整轮远端启动 18 → 24：开头 1 + 三次重新连接 + 「全部断开」前新开 1 + 停服务前新开 1，没有一次是自己起的。
还在跑的 mosh-server：段错误后 1、插件崩溃后仍 1、强停后 2，之后一直是 2——就是那两个孤儿。

**服务所有权（PLG16）**，各个时刻的 dumpsys：

| 时刻 | 宿主 | 插件 | mosh-client |
|---|---|---|---|
| 前台 | 前台服务 `SshKeepAliveService`，oom 0–50 | 没有前台服务；被宿主 `BIND_AUTO_CREATE` 绑着，`vis`、oom 100 | oom 100 |
| 后台 | 前台服务在，`prcp FGS`、oom 200；通知「2 个连着」（Mosh 算在里面） | 跟着宿主 `prcp FGS`、oom 200 | oom 100（见下） |
| 「全部断开」、停服务后 | 前台服务和通知没了，`prev`、oom 700 | 仍被绑着，跟着 oom 700 | 没有 |
| 宿主被杀后 | 没有进程 | 绑定没了（services=0），缓存进程 oom 905 | 没有 |

每个快照里两个包的唤醒锁都是 0、媒体会话 0、音频焦点 0。插件被杀以后，宿主在用户点「重新连接」之前不去重新绑它；
宿主被杀以后没有任何东西把它拉起来（保活服务是 START_NOT_STICKY）。

顺带看到的两件事（没改）：

- mosh-client 的 oom_score_adj 不跟插件走：插件被降到 200 时它还是 100。系统只调 App 进程，子进程停在 fork 时的值。内存紧时它反而比插件晚被杀，
  不影响对错。
- 「全部断开」以后宿主还绑着插件服务，插件进程跟宿主同寿（都是后台普通优先级）。这是 X09/X12 为了「连着就沿用」留的，没有会话也不占前台。

## 4. 息屏 + 深度 Doze（`doze-210622.log`）

HOME、息屏、装作拔了电源，`dumpsys deviceidle force-idle` 强制进深度 Doze（`deep=IDLE`、`mWakefulness=Asleep`）：
30 秒、90 秒时命令都回来了（106 / 104 ms），插件 uid 的网络规则是 `state=3 (fg svc) rules=32 (ALLOW_ALL)`——跟着宿主的前台服务豁免了。
退出 Doze 回前台 102 ms，整轮启动 +1、标签没断过。**模拟器的 CPU 不会真睡**，真机锁屏时 CPU 休眠、mosh-client 会不会被冻结没测。

## 撞到的墙

1. **`svc wifi enable` 之后 Wi-Fi 一直没连上**（「Wifi is not connected」，等 40 秒也一样），第一轮换网场景里「Wi-Fi 接管」其实一直在蜂窝上，
   那轮作废。这台 API 30 镜像不会自己连回 AndroidWifi（R22 用的 API 35 会），要再 `cmd wifi connect-network AndroidWifi open`。
2. **回执文件没删**：同名动作（offline、online）第二次出现时测试不等脚本就往下走，第二轮里「断网 150 秒」的命令其实在断网前就执行了。
   看着很像「断网时命令也执行了」，实际是测试没等。改成看到回执就删，上面的数是第三轮。
3. **SELinux 不让 run-as 杀应用进程**：logcat `avc: denied { sigkill } … runas_app → untrusted_app`，kill 返回 1，脚本被 `set -e` 带走，
   测试一直等回执。X09 在 API 35 上能杀。普通信号放行，改成 SIGSEGV / `am crash`；动作失败也照样回执。
4. **旁边的 SSH 标签经 10.0.2.2 时**，Wi-Fi 接管 8 秒就把它断了、自动恢复成新对象，看着像「Mosh 崩溃牵连了 SSH」。改走 adb reverse 后再没出现。
5. **`am stopservice` 从 App 自己的 uid 调要带 `--user 0`**，不带报 `SecurityException: … asks to run as user -2`，服务根本没停。
6. **宿主被杀后 `flutter test` 把 App 连数据卸了**，放回标签无从测起。改用 `flutter drive --keep-app-running`（R22 的 restore 也是这样）。
7. `远端还在跑 = 0` 的断言写错了：前面崩溃留下的孤儿也算在里面。改成和开这个会话之前比——孤儿本身就是上面记的发现。
8. **真机上不能用 adb reverse**：它只转 TCP、拔线就断，而且 Mosh 的 UDP 发往 SSH 连上的地址——SSH 走 127.0.0.1 的话 UDP 也发给手机自己。
   改成在 Mac 局域网地址上开 TCP + UDP 转发（只放行手机 IP），SSH 也连这个地址。OrbStack 只绑 127.0.0.1，局域网地址上同端口能再绑。
9. **拔线以后不能中途 `expect`**：flutter 在拔线前被杀，挂在前面就白等所有者后面几步。phone 场景每项记一行 `CHECK`、最后一起判，
   结果看手机里 `x10/log.txt` 的 `DONE` / `FAILED`。
