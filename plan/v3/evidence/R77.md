# R77 Tailscale 连不上时直接给修法

**IN_PROGRESS。代码做完。没开 Tailscale SSH（真 OpenSSH）、手机没连 tailnet（模拟器真连接失败）都真跑过；策略拒绝、要浏览器认证还是把异常塞给失败页看的，所以 UXR06 还是 NOT_RUN。真实 check 没账号，没有真 tailnet，也没开过真的 Tailscale App。**

## 四种情况

| 情况 | 怎么认出来 | 失败页给什么 |
|---|---|---|
| 没开 Tailscale SSH | 选了 Tailscale SSH，服务器回认证失败（`SSHAuthFailError`），而不是发 banner 断开 | 一句话、命令 `sudo tailscale set --ssh`、「复制命令」、「改认证方式或路线」 |
| 访问策略拒绝 | `TailscaleLoginDenied`，原有 | 原来那句（去后台查 ssh 规则）+「改认证方式或路线」 |
| 要到浏览器认证 | 普通 SSH 碰上 check，原有；选了 Tailscale SSH 的 check 卡片本来就有打开链接 | 原来那句 +「改认证方式或路线」 |
| 手机没连 tailnet | 手机自己拨的地址在 100.64.0.0/10 或 `*.ts.net` 上，拨不通（包括第一跳跳板）。经代理、经跳板转发的不算，那段 App 看不到 | 一句话 +「打开 Tailscale」（Android，没装时说没找到）+ 重试 +「改认证方式或路线」 |

默认登录没改成免密（F31）。没有任何自动重试，改完设置也不替用户连，重试还是用户点。

## 做错过一次

第一版「手机没连 tailnet」的提示**在真 App 里一次都不会出现**，我当时说做好了，说错了。真实连接失败都包成 `RouteHopException`（`SshService._atHop`），条件却写成「不是这种异常才提示」；单测塞的是裸 `SocketException`，所以是绿的。11-02 写模拟器走查才发现，修在 `fb3fa90`。把修复临时撤掉再跑走查，确实失败（`r70-device-20261102-171500`，exit=1），证明这条走查抓得到。单测也改成了真实形状。

## 没做到的

- **策略拒绝、要浏览器认证没真跑**：它们要 `test/tailscale_ssh_login_test.dart` 的仿制服务器，那要 Go，这台没有，用例还是跳过。
- **「打开 Tailscale」只对空壳验过**：模拟器上装的是同包名的空壳，不是真 App。真机没走。
- **「没开 Tailscale SSH」只对普通 OpenSSH 验过**：真 Tailscale 的拒绝方式仍然只来自 `ssh_login_watch.dart` 里记的 tailssh v1.104.0 行为。文案还是写「多半」。
