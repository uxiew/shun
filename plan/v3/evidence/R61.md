这两个结论有推断的成分：

- **那两个 Google 域名不是 App 发的**：`firebaseinstallations.googleapis.com`、`play.googleapis.com`。`pubspec.yaml`、`android/app/build.gradle.kts` 里没有 Firebase 和 Play 服务，App 的 uid 也是 0 字节，所以算模拟器镜像自己的 Google 服务。DNS 包不带进程信息，这条没有直接证据。
- **「只连填的地址」**靠服务器日志和抓包。`sync` 这段 App 连的是回环（`adb reverse`），netstats 是 0，`/proc/net` 每 0.3 秒读一次也没采到这条连接，这两路在这段没有贡献。

## 打开时一起改的

- **加解密挪到后台 isolate**（`1b2663b`）：一次 PBKDF2 约 2.8 秒，原来在主线程，打开自动同步后每次都会卡这么久。
- **主密码至少 12 位**：所有者没提，是我加的。云端那份泄露后能被离线猜，和加密备份同理。
- **GitHub 关着**（`ForkFeatures.githubSync`）：登录用的 OAuth clientId 是上游的，要开得所有者在 GitHub 注册自己的。存着 GitHub 配置也不外连。
- **删除确认框**：没开自动同步就不说「会传到其他设备」。

## 没测的

- **真的服务**：没有所有者的账号，按停止条件只用本机假服务器，**不算真服务通过**。假服务器不验 S3 签名（只有 `test/cloud_sync_service_test.dart` 看签名头的形状），MOVE、ETag 都是最简单的写法。第一次连真服务可能在这几处撞墙。
- **手机**：都是 API 30 模拟器。
- **WebDAV 上设备**：它只接受 https，模拟器不信自签证书，所以只在单测里走过。
- **下载写回真安全存储**：设备上只走了上传。拉下来进安全存储那段在单测里，安全存储底层是假的；同一个 `saveVault` 在 R60 的设备测试里走过真的。
- **两台手机同时写**：没测。ETag 是先读再比，不是原子的，可能后写覆盖，手册写了。
- **同步时不卡的实测**：只是把计算挪开了，没量帧。

## 测试工具的坑

设置页的输入框在界面树里没有标签，只能按顺序填：Region 自带 `us-east-1`，多填一个全部错位，`对象前缀`的值会跑进主密码框。「允许不安全连接」的开关和它旁边的说明按钮名字相同，要带 `|` 匹配才点得到开关。
