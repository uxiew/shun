## 同素材两引擎对比（本机，「CJK/全屏/协议回应无关键错误」）

`test/terminal_vt_corpus_test.dart`（41 条过，1 条耗时测试默认跳过），素材在 `test/fixtures/vt/`，重录脚本和说明在 `tool/vt-corpus/`。

比的是：文字、光标、是否备用屏、光标是否显示、回给远端的字节、字的样式（前景/背景色、粗、淡、斜、下划线、反显、删除线）。

- **真实程序 5 个、33 个检查点**（vim 中文 + 竖分屏 + 搜索高亮 + 插入、less -R 中文长行、htop 树形和设置页、tmux 客户端分屏/copy-mode/zoom、
  bash 行编辑）：Ghostty 和 tmux **全部一样**。样式对比里 tmux 那边带样式的字超过 1000 个，有一条测试专门确认不是空对空。
- **几种喂法**：整块、逐字节、随机小块（1–7 字节）、随机大块（≤4096 字节），33 段合成素材 + 33 个检查点，上面每一项都一样。
- **合成素材 33 段**，19 段三方一样；14 段 Ghostty 和 tmux 不同，逐条钉在测试里、写了原因：

| 素材 | Ghostty | tmux | xterm2 | 结论 |
|---|---|---|---|---|
| 裸 DEL `ab\x7fcd` | 0x7F 存进格子（方格） | `abcd` | `abcd` | **Ghostty 错**，fork 39a7ba8 修了（R04 问题 9） |
| 行尾待折行时 BS/EL/CUB/LF | 照 xterm 从最后一列往左挪 | 当作在第 81 列 | 同 tmux | Ghostty 对（照 xterm 源码判断，没在真 xterm 上跑） |
| HPR、VPR（`CSI a`、`CSI e`） | 正常移动 | 不认 | 同 Ghostty | tmux 缺 |
| 清掉全部制表位后 CHT | 跳到最右列 | 原地 | 同 Ghostty | Ghostty 对 |
| 左右边距 `?69` | 支持 | 不支持 | 同 Ghostty | tmux 缺 |
| DEC 画框字符 | `┌───┐` | `lqqqk` | 同 Ghostty | tmux 截屏吐的是内部存的原字母 |
| 非法 UTF-8 | 每处一个 `�` | 丢掉 | 同 Ghostty | 可接受 |
| C1 控制字符 | UTF-8 编码的 C1 丢掉；原始 0x9B 画 `�` | 当普通字存；0x9B 丢掉 | 当控制执行；0x9B 画 `�` | 可接受，丢掉更安全 |
| 在宽字右半格写字 | 整个宽字擦掉 | 留着原来的宽字 | 同 Ghostty | 可接受 |
| 换行后马上 REP | 重复上一行最后的字 | 不重复 | 同 Ghostty | 可接受（ncurses 只在同一行用） |
| 20 位数的参数 | 当最大值 | 整条丢掉 | 同 Ghostty | 可接受 |
| 光标位置报告的两种边角 | 照规范 | tmux 自己的问题 | 同 Ghostty | tmux 的问题 |

- 宽字三方完全一致（每行末尾用 CPR 核对列号）：CJK 行尾折行；ZWJ 家庭、VS16、键帽、肤色、国旗占 2 列，VS15 那个 1 列；组合字符、分解韩文一样。
- **R04 问题 6（组合字符缺重音）**：终端模型里重音在，宽度、光标和另外两个一致，只是绘制层没画出来。没修，不算关键错误（中文用户极少碰到，复制出来是对的）。
- bash 里编辑含 ZWJ emoji 的命令行会乱，三个终端乱得一样：readline 按 musl 的 wcwidth 算 6 列、终端显示 2 列。不是 Ghostty 带来的。
- 回应上钉住、没修的：**ANSI 模式的 DECRQM（`CSI 4 $ p`）不回**（上游 `stream.zig` 的 `'p'` 分支只认两个中间字节；私有模式正常回；
  要改 Ghostty 的 Zig 源码，现在没有打补丁的路子）；XTGETTCAP 问 `TN` 不回（flterm 没暴露 `terminfoName`）；DECXCPR 不回（tmux 也不回）。
  DA1 回 `?62c`，XTVERSION 回 `libghostty`，`CSI 21 t` 不回（SEC08）。
- **没挂视图时 OSC 10/11/12 不回**：对比测试看代码推断、本机复核过（后台标签里问背景色的程序会干等到超时），fork 54c19ed 修了，
  测试 `default_colors_test.dart` 撤掉改动就挂。
- 本机耗时（macOS，flutter test debug，三轮，只是参考）：5 MiB 合成素材 Ghostty 17–21 ms、xterm2 120–202 ms；约 5 MiB 真实录像 Ghostty 24–27 ms、xterm2 171–201 ms。

## 资源（TER11）

`tool/r20-gate.sh emulator-5580 resources`：真 App、Ghostty、真实 SSH。4 个标签各 `cat` 一份 0.9 MiB 的中文 + 8 色 + emoji 输出（共 3.6 MiB），
再新开一个标签、吃 64 KiB、关掉，重复 500 次；每 20 次读本进程的 RSS、PSS（`/proc/self/smaps_rollup`，原生库的内存也在里面）、fd、线程；
第 100、500 次另外让电脑抓 `dumpsys meminfo`，并经本进程的 VM service 强制 GC 后数各类还活着的实例；连 SSH 的 socket 由脚本用 root 读 `/proc/<pid>/net/tcp`。
判据在跑 300 次之前定下、之后没改：热身（前 100 次）后 RSS、PSS 每次开关涨不到 0.05 MiB（51.2 KiB），fd、线程每次涨不到 0.02 个；标签全关后连 SSH 的 socket 为 0。

**查出一个真泄漏，修了**（e6e1b19）：文件（SFTP）页在底部导航里一直活着，它按标签缓存的 `SftpService` 拿着会话，标签关了也从不删（原版 Netcatty 就这样）。
每个关掉的标签连同它的 Ghostty 终端、SSH 客户端都回收不了。R08 量过 fd 和服务器侧连接（都不涨，所以当时没发现），没数 Dart 对象。
经 VM service `getRetainingPath` 查到引用链停在 `_SftpScreenState._remoteServices`。

| | 修之前（9c19d37） | 修之后（ef3e013） |
|---|---|---|
| 强制 GC 后还活着的会话（4 个标签开着）第 100 / 500 次 | 104 / 504（Ghostty 适配器、flterm 控制器、SSHClient 同数） | 5 / 5（4 个开着的 + Flutter TextInput 记着的最后一个，不累积） |
| GC 后活着的 Dart 堆，第 100→500 次 | +17.3 MiB | +4.4 MiB（多的主要是 debug 模式 JIT 新编的代码对象） |
| RSS / PSS 斜率（判据 < 51.2 KiB/次） | 61.2 / 61.1 KiB，**FAIL** | **39.4 / 29.3 KiB** |
| fd / 线程斜率 | 0.002 / 0.004 | 0.004 / 0.000 |
| 第 100→500 次 RSS | +32.6 MiB | +13.7 MiB |
| 连 SSH 的 socket（root 读） | — | 开始 0；4 个标签开着时 4 条（已连上）；全关后 0 |
| 输入到远端回显 p50 / p95 / 最大（50 次） | — | 17.7 / 19.8 / 20.1 ms（预算 50 ms） |
| 50 次收起/叫出系统键盘 | — | 50/50 叫回，PSS −0.7 MiB |

- 修之后的一轮数据：开始 RSS 521 MiB、fd 159、线程 37；4 个标签吃完 RSS 566 MiB、fd 188；第 500 次 RSS 604 MiB、fd 188、线程 47；全关后 fd 182。
  fd 全关后比开始多 23 个，按类型数：`anon_inode:sync_file` +21（GPU 同步对象，终端页第一次画出来后就在，之后 4 个标签开着、开关 500 次都停在 32–33）、
  eventfd、eventpoll 各 +2、socket +1（随测试框架、VM service 的连接起落）、goldfish_pipe +1，普通文件 −3；连 SSH 的 socket 是 0。
- 回显延迟走的是快捷键栏、按键面板同一个入口（`sendText`），含 adb 转发、Docker 网络、sshd 的来回；数值贴着一帧 16.7 ms，说明测量粒度就是一帧。
  前几轮：p95 19.4、25.8、21.4、20.7 ms，最大 67.4 ms（那轮同时在编 release 包）。
- **没解释清、交给 R22 的**：修之后 Native Heap 第 100→500 次涨了 12.6 MiB（约 32 KiB/次），总量在判据内。是 Ghostty 的原生内存、Flutter 渲染缓存，
  还是 malloc 不还给系统，要单独量引擎才分得清——这正是 LIFE06（native 内存）的范围。R17 的引擎单测在本机 300 轮 +0.3 MiB，设备上 100 轮 RSS +5.8 MiB。
- 判据怎么来的：第一次只开关 100 次、按「第 20 次和第 100 次相减 < 16 MiB」判，挂在 +18.9 MiB，但曲线是第 30→40 次一个台阶、之后平的，两点相减分不清台阶和持续增长；
  于是拉长到 300 次、改按热身后的斜率判（判据在跑之前定）。300 次那轮斜率 42.8 KiB 过了线，但离线不远；再拉到 500 次就超了线（61.2 KiB），
  这才查到上面那个泄漏。修完按同一个判据过。

| Ctrl+[ | `1b` | 没测 |
| 有选区时 Ctrl+Shift+C，再 Ctrl+C | 只收到 `03`；剪贴板里是复制下来的 718 个字 | 有选区时 Ctrl+C 是复制、不发 |
| Ctrl+K/A、Ctrl+Shift+K/A、组合键、快捷键栏修饰键 | 和 R19 一样 | — |

根因（Ctrl+I/M）：Ghostty 照 fixterms 把 Ctrl+I/M/[ 留给 CSI u（`key_encode.zig` 里那三项是注释掉的），Android 硬件键盘的按键事件又不带字符，
CSI u 那条路也进不去，所以什么都不发；widget 测试里模拟的事件带字符，测出来是 CSI u，和设备不一样。fork c474751 在传统编码下直接给 C0；
远端开了 kitty 键盘协议时照上游（flterm 测试：`ESC [ 105 ; 5 u`）。flterm 新测试 23 条，撤掉改动挂 15 条；上游有一条钉着
「快捷键栏 Ctrl + 软键盘 `[` 发 CSI u」，期望改成 ESC。
