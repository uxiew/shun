## 已接入行为

- 本机加密存储保存至多 20 条最近工作指针，按源主机 ID、地址、端口、SSH 用户分开；每条记录工具类型和绝对可执行路径、项目实际绝对路径、最近打开时间、可选原生 ID 来源及完整 tmux server/session/window/pane/pane PID/本次请求 ID。无提示词、聊天内容、终端输出、账号或模型 token；不进入保险库导出/同步/诊断，Android 备份关闭，iOS 使用仅本设备可解锁的 Keychain 可访问性。列表可清除本机指针，不触碰远端进程。
- 首页保险库显示最近一项和“会话状态待核对”；主机的 AI 工具面板显示最近五项。返回仍连接的原普通 SSH 标签会更新最近打开时间；原 tmux 标签或冷启动后先核对同一 session 的 server 代次及 window/pane/pane PID，再附着，附着脚本在握手前后重复守卫。窗格更换/进程退出后拒绝按名字找替身，用户可再选原生继续或新建。AI tmux 断线不会经 R22 自动重附着，冷启动也只恢复最近工作入口。
- Claude 新建时由 App 分配 UUID，记录来源 `shun-assigned`；之后仅在原工具路径和项目实际目录执行 `--resume <UUID>`。该 ID 在 CLI 自己创建会话前仍是候选，缺失/不兼容时以 CLI 的实际报错为准，不降级到 `--continue` 或另一条对话。Codex 当前无法可靠取得本次运行的 ID，故原窗格不在时运行该项目的 `codex resume` 交互选择器，由用户选历史，并把新终端记入最近工作；没有使用 `--last`。Gemini、OpenCode 和自定义工具只提供新建及可核对的活终端/tmux 返回。
- 卡片只报告可确认的终端/窗格状态或“待核对”，不从终端标题、欢迎页或未核验的安装包版本推断 AI 已登录、原对话仍在、任务完成或得到批准。
