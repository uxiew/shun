## 怎么切的（给复核的人）

- **tmux 标签 SSH → Mosh**：在这个标签已登录的 SSH 上跑固定脚本：先按 R21 核对 server 代次、会话 id、创建时间，不对就退出（95/96/97），
  对了才 `exec mosh-server new -s -c 256 … -- tmux -u -S <socket> attach-session -t $ID`。UDP 发往这条 SSH 实际连上的 IP。
  Mosh 会话接在一块还没显示的新终端上；再用同一条 SSH 按「父进程 = 这次 mosh-server 的 pid」找到 Mosh 那一侧的 tmux 客户端——
  只数「多了一个客户端」会认错电脑上同时附着的那个。找到了标签才换过去（同一个标签 id、同一个位置），然后停掉用户确认过的端口转发、
  按终端 + pid 分离旧的 SSH 客户端、关 SSH。
- **tmux 标签 Mosh → SSH**：按标签冻结的路线重新登录，R21 握手附着同一目标，再确认新客户端确实在那个会话上，才换；然后分离 Mosh 那一侧、关 Mosh。
- 失败、取消、关标签：新的一边全关、新终端释放，原标签不动。两个方向都不往任何一边写字节。
- **普通标签**：按保险库现在的配置另开一个标签（协议换掉、不带启动命令），原标签不动。
- **Mosh 重新连接**：旧标签留着当历史，新会话连上了才顶替它的位置；Mosh-tmux 标签走 tmux 变体，只附着原来那个目标。

## 卡在哪：Mosh 插件的签名

宿主只认 `lib/domain/plugins/official_plugins.dart` 登记的证书（`ffb53d5a…52fe`）签的 `shun.mosh`。本机仓库外的

`7feb58259ea7ca210fc268f8df42ed4bd378ae04be2c270e31c559d6180e6e9d`；迁移包不带仓库外的密钥，原来那把不在这台机器上。
现在编出来的 Mosh 插件装上就是「已拒绝」，连不了 Mosh。改登记的证书是改信任名单（签名需明确授权，R39 手册也写了不改），这次没动。

1. 把旧机器上原来的 `fixture-author.jks`（证书 `ffb53d5a…`）放回 `../.toolchain/plugin-keys/`。代价：R39 之后用新钥匙签过的测试插件要重新批准。
2. 授权把 `official_plugins.dart` 里的 Mosh 证书改登记为 `7feb58…`（按文件里的要求从实际安装包 `apksigner verify --print-certs` 读）。

之后要补的是：在模拟器上装真插件，跑 tmux 标签 SSH ↔ Mosh（远端核对会话 id、记账 0 字节、切完在 Mosh 里打字只到一次）、
