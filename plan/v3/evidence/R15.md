## 先发现的一件事：开发机本身在真实 tailnet 上

这台 Mac 有 `utun4 100.x.x.x`，`100.64/10` 路由走它（真实 Tailscale）；Headscale 发的地址也在 100.64 段。所以：

- **从本机或模拟器直拨 100.x 会进真实 tailnet。** 模拟器的出站连接是由 Mac 上的模拟器进程发出的。回头看 R13：那次在模拟器上直连过 `100.64.0.10:22`（「far」那台），这个 SYN 实际进了所有者的真实 tailnet；R13 记录里从 Mac 连同一地址是超时，说明那里没有设备，没有建立任何连接。之后不再这样测。
- 本轮的防护：测试里的拨号器只放行 127.0.0.1，别的地址直接报错并记下（本轮记录里没有一次被拦，也就是 App 没有尝试直拨）；每个节点容器用 iptables 丢掉「发往 100.64/10、fd7a:115c:a1e0::/48 却不走 tailscale0」的包；自检脚本只连 127.0.0.1 上映射出来的端口。
- 开发机还开着 fake-ip 类代理：容器里解析任何名字都得到 198.18.x（fixture-environment 的 README 早记过）。影响见「环境造成、不算 App 的现象」。

## 过程中发现并修掉的

- **经代理或跳板机的一跳「连上后在登录前被关」，提示把人引去查端口**（ec15918）：第 2 轮里 SOCKS 已回报连上 ts-jump，随后在 SSH 版本行之前被关，App 提示「确认这个端口上是 SSH 服务——常见原因是把代理端口填成了 SSH 端口」。这时 App 看不到代理之后那一段，链路断了和端口不对都有可能。现在 `RouteHopException.relayed`（第一跳经代理或后面的跳）为真时两种都说；直连不变。
- **测试环境不稳**（2d8bbd2）：没有可用的 DERP，节点间只能直连。两台节点同时挂在 tsnet 和同一张 edge 网上时 disco 在两条路径间切换；保温只有单向 disco ping。改成每台一张 edge 网，`keepalive.sh` 对要用到的 peer 双向发 disco + TSMP。之前还试过：用 REJECT 封 edge 出网（magicsock 收到拒绝就反复 rebind，路径建不起来，改成只 DROP tailnet 网段）、只用 TSMP 保温（路径没摸出来时只会超时）。都写进了测试环境 README 的「撞墙时」。

## 环境造成、不算 App 的现象

- **「代理连不到的名字」回的是状态码 2**：fake-ip 代理让容器把 `ts-server.r15.invalid` 解析成 198.18.x，dante 按「只转发到 100.64/10」的规则拒了。正常环境下应是解析失败（状态码 4）。测试只断言它落在代理这一层。
- **经 tailscaled 的 SOCKS 连 tailnet 以外的名字，SOCKS 回成功再断开**：查了 tailscale v1.104.0 `net/socks5/socks5.go` 的 `handleTCP`，是先拨通再回成功，所以这不是 tailscaled 的行为，而是它经开发机网络出去、被 fake-ip 代理接下再断开。测试不走这条。
- **ts-server 的审计日志会被 tailscaled 自己限流**（`[RATELIMIT] format("audit: SSH login: …") (2 dropped)`），所以审计日志条数比登录次数少；App 侧的 `$SSH_CLIENT` 每次都有。

## 未测与局限

- **直连**：要手机开着官方 Tailscale App 的 VPN；模拟器里没有，开发机又在真实 tailnet 上，不能拿 Mac 的 Tailscale 代替。
- **真的 TailSocks App、真机、手机上已有别的 VPN**（NET12）：本地 SOCKS 是容器里 userspace tailscaled 自带的 SOCKS5 扮演的。
- **远程 SOCKS 用的是回环地址**：模拟器经 adb reverse 到达；真实的非回环地址（同一 Wi-Fi 里另一台机器）没测。App 对回环和非回环代理走的是同一段代码，界面只多一句「只在可信网络使用」的提醒。
- **官方 Tailscale 的 check 网页**（R14 已记），以及经共享远程 SOCKS 的 checkuser、代理入口 + 跳板下的 check。
- 目录 API 是假的：Tailscale 真实的 scope 回报、限流、共享设备可见性都没见过（R11 已记）。
