## 本机字节级测试（macOS arm64 直接加载 Ghostty 原生库）

`spikes/terminal_spike/test/`：19 通过 / 1 跳过（跳过的是下面问题 1 的段错误复现；10-04 加了 DEL 现状和回环退格两条）。**这是引擎行为证据，不是 Android 证据。**

- TER01（Ghostty 路径）：5 组素材（含非法 UTF-8）× 20 随机种子 + 逐字节，原始字节直接进终端，plain 和 VT 两种格式输出、DA 回应全部与整块输入一致。

## 模拟器结果

### 加载与 16 KiB

- 上表七台上 `flutter test integration_test -d <设备>` 都是 1/1 通过（native 初始化、中文与方向键按原始字节发出）。
- 16 KiB 页上 release 包冷启动 766 ms，渲染正常。进程 maps 里有从 `base.apk` 偏移 `0xf1c000` 起的 r--p / r-xp 映射，正是 APK 里 libghostty.so 的数据偏移（不压缩存放、直接映射，偏移按 16 KiB 对齐）。

### 按键（原始字节，logcat `SPIKE_SENT`）

| 输入路径 | 不加兜底 | 加兜底后 |
|---|---|---|
| Gboard 软键盘：字母 / 空格 / 回车 | 正确 | 正确 |
| Gboard 软键盘：**退格** | **0 字节** | 每次 `7f`，缓冲空时也发 |
| adb `input keyevent`：方向键、Esc、Tab、退格、回车、PageUp、Home、F1 | **全部 0 字节** | 10/10 正确（`tool/adb_key_check.sh`） |
| 真实扫描码的硬件键盘（root `sendevent` 写 qwerty2 设备）：上、退格、a、Ctrl+C、Ctrl+D、Alt+X、Shift+Tab | 由 flterm 自己处理，全部正确：`1b5b41`、`7f`、`61`、`03`、`04`、`1b78`、`1b5b5a` | 不接管 |

- 原因：输入法和 adb 发来的键 scanCode=0，Flutter 给的物理键是合成值 0x11_0000_0000+keyCode，flterm 只按物理键查表，认不出就 ignored；Flutter 引擎 `InputConnectionAdaptor.handleKeyEvent` 又不处理 KEYCODE_DEL，这个退格就被丢掉了。
- adb `input keycombination` 注入的 Ctrl/Alt 组合到达 Flutter 时 Ctrl 先抬起，测不了组合键；`adb emu event send` 在无窗口模式下事件不进内核（getevent 看不到）。所以组合键只认 `sendevent` 那一行。
- 模拟器虚拟键盘的键位表 `qwerty2.kl` 把扫描码 1（Esc）映射成 BACK，Esc 被系统当返回键吃掉，不是 App 问题；真实蓝牙键盘用 Generic.kl，不会这样。

### 收起后叫不回键盘

按返回收起软键盘，或切到桌面再回来，之后连点终端两次 `mInputShown` 都是 false。flterm 内部仍记为 showing，`showKeyboard()` 空操作，点按只 requestFocus。`KeyboardReshow`（轻点抬起、键盘未占位时 hide+show）修后同样步骤都能叫回。

### 中文输入（TER02 的模拟器部分）

**不打补丁打不了中文。** 终端获得焦点时 EditorInfo `inputType=0xa0091`（可见密码），Gboard 进 PasswordIme，空格键显示 QWERTY，敲 nihao 直接逐字母发出，没有候选。
原因在 Flutter 引擎 `TextInputPlugin.java:294-297`：`enableSuggestions=false` 会同时加 VISIBLE_PASSWORD；flterm 写死 multiline + 无建议。
原版 Netcatty（xterm2）同样无建议，但用 emailAddress，`0x20|0x90` 落成 FILTER（0xB0），不是密码——**直接换成 flterm 会让中文输入倒退**。

`spikes/terminal_spike/patches/flterm-0.0.5-android-ime.patch` 三处改动：inputType 改 emailAddress（实测 `0x800b1` Filter，Gboard 进 LatinIme）；scanCode=0 的键按逻辑键编码；这类键处理后推两次编辑状态，逼引擎给输入法发 updateSelection。
打补丁后，Gboard 拼音在"内联组字"开、关两种设置下，下面整套都对：

| 操作 | 发出的字节 |
|---|---|
| 敲 n-i-h-a-o（出候选：你好 / 你还 / 你 / 尼…；内联开时终端光标处显示带下划线的 "ni hao"） | 无 |
| 点候选"你好" | `e4 bd a0 e5 a5 bd`，一次 |
| 提交后退格 | `7f`，一次 |
| 敲 c-e-s-h-i 再退格 5 次删光（撤销组字） | 无 |
| 组字已空再退格 | `7f` |
| 敲 l-s 按回车（组字中） / 再按回车 | `6c 73`（不带换行） / `0d` |
| 敲 z-h-o-n-g 按空格（选首候选） | `e4 b8 ad`（中） |
| 敲 g-i-t 按空格（混排） | `67 69 74` |

第三处改动的由来：输入法发来的 DEL 被终端吞掉后编辑区没变，平台不通知输入法光标位置，Gboard 按"已删一字"估算，之后内联组字区间错一位（组字区间 2-3 而不是 1-3），删拼音时漏发一个字母。
A/B（内联组字开，先退格一次再敲 ceshi 删光，各 3 轮）：去掉重对齐 3/3 漏发 `63 7f`；加上 3/3 只有预先那一次 `7f`。补丁的干净版本（去掉调试日志）重新构建后复测一致。
麦克风：`aapt2 dump permissions` 看 spike 和 fork 的 APK，都没声明 RECORD_AUDIO，App 自己没法申请；语音输入走输入法自己的权限。
未测：语音输入本身（宿主麦克风已关）、搜狗/讯飞/百度等国产输入法、真机。

### 其他

### 最低 API

App 声明 minSdk 24，libghostty 却按 API 29 构建、带 ELF TLS。我原先推断 API 29 以下会加载失败，**API 28 实测推翻了这个推断**：

- API 28：spike release 包（`4b6f774d…`）冷启动 294 ms，终端正常渲染；root 读 maps 有 base.apk `0xf1c000` 起的映射（libghostty 已加载）。
  集成测试 1/1、`adb_key_check.sh` 10/10、连灌 5 行 400+ 字符后进程号不变，logcat 无 FATAL/SIGSEGV。唯一的 tombstone 是开机时 `com.google.android.gms` 自己崩的，与本 App 无关。fork 主 App 在 API 28 上也能冷启动到首页。
- API 28 的链接器怎么处理那 5 个 TLSDESC 重定位、线程局部变量读写是否全对，**没有弄清**；上面只是冒烟级别，没做多线程或长时间压力。
- API 24、25、26、27：同一个 spike release 包（`4b6f774d…`）和 fork debug 包（`27cfb997…`），与 API 28 同一套步骤，**全部通过**：

  |---|---|---|---|---|---|---|---|
  | 24（7.0） | 277 ms | 有 | 10/10 | 不变 | 0 | 1/1 | 1161 ms |
  | 25（7.1.1） | 201 ms | 有 | 10/10 | 不变 | 0 | 1/1 | 1115 ms |

  截图核对：四台上 spike 终端正常渲染中文/emoji/光标（组合字符同样缺重音，见问题 6），fork 都能进首页。
- API 24 的两次结果不一致：上午第一次尝试 10 分钟 `adb shell` 无响应；下午用 `hw.gpu.mode=host`、2 GB 内存、镜像 r29 重建 AVD，约 18 秒启动完成。第一次失败的原因没有查清，不再引用 android-emulator-m1-preview#72 作为"本机测不了"的依据。

### 所有者人工 TER02（打补丁的包）

所有者照清单走了一遍：打一句中文、拼音打一半删光、上屏后退格和长按退格、语音输入、中文标点、emoji、中英混排、回桌面再回来、返回手势收起再叫出。后台一直记录 `SPIKE_SENT`。中途 USB 断开过一次，重新接上后继续，日志从手机缓冲区补抓。

- 打字：「天气好噢」「，」「你说呢」都只发一次。所有者说"其他正常"。
- 退格：单按一次一个 `7f`；长按约每 100 ms 一个 `7f`，键盘自动重复，正确。
- **退格时屏幕上出方格**（所有者报告）：回环把 `7f` 原样回显，Ghostty 把 DEL 画成了方格（问题 9）。回环已改成像 PTY 那样回显 BS 空格 BS（914be7e）。
- **语音输入同一句话写入多次**（所有者报告，日志证实）：一句话发出 9 次，每次都是越来越长的整句——`你`、`你好，`、`你好，你谁`、`你好啊，你谁`……`你好啊，你是谁？在一`，中间没有任何 `7f`。远端会收到一长串重复的字。**TER02 FAIL**。

用带编辑日志的包让所有者再说一句「你好你在干嘛」，得到微信输入法语音时的编辑步骤（问题 8 的根因）：

| 时间（秒） | 输入法做了什么（Flutter 收到的增量） | flterm 做了什么 |
|---|---|---|
| .657 | 在占位空格后插入「你」，组字区 1–2 | 显示组字，不发 |
| .758 | 组字区清掉（-1），文字不变 | 当成提交：发出「你」，编辑区清回占位空格 |
| .760 | 把组字区重新圈回 1–2（输入法以为「你」还在） | — |
| .761 | 在组字区后插入「好」 | — |
| +0.65 | 收到 flterm 的清空后，插入整段「你好，」，组字区 1–4 | 显示组字 |
| +0.1 | 组字区又清掉 | 发出「你好，」…… |

也就是说：微信输入法每次更新识别结果，都会先**短暂结束组字**，紧接着又把组字区圈回已经出现的那段字、继续改写。flterm 把短暂的结束当成提交马上发出，并把编辑区清空；输入法想改写的那段字已经不在了，只好把整句重新插入一遍，于是每一版都整段重发，旧的那版也没被删掉。最后一版（带「系」的）一直停在组字区，没有发出去。

### adb 注入按键（真机上不可靠，只记现象）

`tool/adb_key_check.sh` 在弹着微信输入法时：第一遍 PASS 6 / FAIL 4（abc、上、右、Esc 连 Flutter 都没收到），第二遍 PASS 8 / FAIL 2（Esc、Tab）。
原因是**微信输入法拦截注入的键**：它把这些键当实体键盘输入，中文模式下字母进了组字区，有组字时方向键用来挪候选，Esc 被它拿去收起键盘。
之后它切进**实体键盘模式**（输入区高度 0，只剩导航条），重开 App、回桌面都不恢复。
用 `adb shell input text` 灌 5 行 425 字符做冒烟，内容全被输入法改过：每行只剩 60 字节，`_` 变成「——」，回车被拿去提交组字。所以这一项只能证明**进程没崩**（进程号不变、0 条 FATAL），内容对不对不算数。
真机上的硬件键盘没测（没有蓝牙键盘）。

### 对所有者手机的影响

- 为了把微信输入法从实体键盘模式里恢复，force-stop 了它两次。**第一次单独 force-stop 后，系统把默认输入法换成了 Gboard**，几秒内用 `ime set` 改回微信输入法；第二次 force-stop 和 `ime set` 放在同一条命令里，前后对比 `default_input_method`、`selected_input_method_subtype`、`enabled_input_methods` 三项完全一致。恢复办法写进了 `docs/xwshun/README.md` 第 7 节。
- 收尾：spike 已卸载（`pm list packages` 无 xwshun 包）；充电常亮改回 0（原值）；三项输入法设置和开始时一致；adb 转发清空；SSH 隧道已关。截屏和日志只在本机临时目录。

## 发现的问题

1. **dispose 后 write 会段错误，整个进程崩溃**（flterm 0.0.5）。复现：`XWSHUN_RUN_KNOWN_FAILS=1 flutter test --plain-name 已知问题` → `TestDeviceException(Shell subprocess crashed with segmentation fault.)`。终端页销毁后 SSH 迟到的数据会让 App 闪退。R17 适配器必须按代次在 Dart 层挡住（`GuardedWriter.close()` 已示范）。
2. **软键盘退格、蓝牙遥控类按键 0 字节**（模拟器）。适配层兜底 `lib/android_key_fallback.dart` 可修，但会引出问题 4，完整修法要进 flterm。
3. **收起后叫不回键盘**（模拟器）。适配层 `lib/keyboard_reshow.dart` 可修。
4. **打不了中文**（模拟器，Gboard）。只能改 flterm，补丁见上；内联组字漏字也要补丁里的重对齐。
   真机微信输入法不打补丁能打，但每次弹出都回到英文、要手动切（见真机一节）；打补丁后直接是中文。
5. **native 库缓存副本被篡改不会被发现**（GST01）：
   - 实验 B：篡改共享下载缓存并删掉 hook 输出 → hook 重跑，发现 hash 不符 → 删除 → 重新下载 → 正确。✔
   - 实验 A3：只篡改 hook 输出目录里的副本（在代码段内翻转 1 字节）→ 删 `build/` 重建 → **构建成功，篡改过的库进了 APK**（strip 后 `ddac4e6f…`，正确应为 `1c78966d…`）。hook 只在下载时校验，hooks_runner 按输入缓存输出，已有副本不再校验。
   - 实验 A/A2（在文件末尾追加字节）无效：strip 会丢掉 section 之外的字节，测不出东西，已作废。
   - 缓解：发布构建先删 `.dart_tool` 再构建（会重新下载校验），或在 R17 加打包前校验。
   - 同类的构建缓存坑：换 `pubspec_overrides.yaml` 的 path 后，Gradle 按旧依赖清单判断"没变"，跳过 Dart 编译产出旧 APK（spike README 有核对办法）。
6. **组合字符缺重音**（模拟器），绘制层。
7. **默认资源上限远大于计划预算**：`scrollbackLimit` 默认 10,000,000，Kitty 图像存储 64 MiB；另外按 TLS 段大小推算，每个访问过它的线程可能多占约 256 KiB（推算，未实测）。R17 必须显式设限并实测。
8. **语音输入把同一句话整段重复发送**（真机，微信输入法；打补丁的包上测出，补丁没动这段逻辑）。根因在 flterm 的 `TerminalInputClient`：
   每次提交后马上把编辑区清回占位空格，输入法没法改写已经出现的字；微信输入法语音每次更新都会短暂结束组字再圈回来，每一版都被当成新提交。
   修法方向（R17）：提交后不立刻清空编辑区；输入法改写已经发出去的文字时，按差异补发——先发 N 个 `7f` 删掉变了的部分，再发新的尾巴
   （「你好，你干」→「你好。你在干」= 3 个 `7f` + 「。你在干」）；只在换行、失焦、按键编辑、长度超限这类明确的边界才清空。
   也可以把"组字结束"延迟一小段再提交，期间组字区被圈回同一段字就取消；两种都要真机 + 语音再测。Gboard 语音、原版 xterm2 路径没测。
9. **Ghostty 把裸 DEL（0x7f）当可打印字符存进格子**，屏幕上是方格；VT100 和 xterm 会忽略它。远端程序真输出 0x7f 时也会出方格（少见）。
   `test/ghostty_bytes_test.dart` 钉住了现状，换库版本后行为一变就会失败。R17 决定要不要在写入前过滤。
10. **中文输入法拦截按键事件**（真机，微信输入法）：adb 注入的键被当成实体键盘输入，进组字区或被吃掉（Esc 被拿去收起键盘），之后输入法停在实体键盘模式。
    蓝牙/USB 键盘 + 中文输入法时，Esc、方向键可能到不了终端；属于 TER04（R17 起），这次没有硬件键盘没测。

## 资源测量方法（冻结）与本机基线

预算沿用 docs/06（初始设计值，未经设备验证）：4 个活动连接；每会话 5000 行或等价字节预算；待渲染缓冲 4 MiB 高水位。R17 起按下面的方法在设备上测，**不许为了测试变绿去放宽阈值**。

|---|---|---|
| 大量输出 | 5 MiB 合成 VT（中文+颜色+换行），16 KiB 一块写入；计时 + 进程 RSS（不是 Dart heap，原生库有自己的内存） | 13 ms，RSS +9.5 MiB |
