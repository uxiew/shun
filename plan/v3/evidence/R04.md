## 模拟器结果

### 加载与 16 KiB

- 上表七台上 `flutter test integration_test -d <设备>` 都是 1/1 通过（native 初始化、中文与方向键按原始字节发出）。
- 16 KiB 页上 release 包冷启动 766 ms，渲染正常。进程 maps 里有从 `base.apk` 偏移 `0xf1c000` 起的 r--p / r-xp 映射，正是 APK 里 libghostty.so 的数据偏移（不压缩存放、直接映射，偏移按 16 KiB 对齐）。

### 按键（原始字节，logcat `SPIKE_SENT`）

| 输入路径 | 不加兜底 | 加兜底后 |
|---|---|---|
| Gboard 软键盘：字母 / 空格 / 回车 | 正确 | 正确 |
| Gboard 软键盘：**退格** | **0 字节** | 每次 `7f`，缓冲空时也发 |
| adb `input keyevent`：方向键、Esc、Tab、退格、回车、PageUp、Home、F1 | **全部 0 字节** | 10/10 正确（`tool/adb_key_check.sh`） |
| 真实扫描码的硬件键盘（root `sendevent` 写 qwerty2 设备）：上、退格、a、Ctrl+C、Ctrl+D、Alt+X、Shift+Tab | 由 flterm 自己处理，全部正确：`1b5b41`、`7f`、`61`、`03`、`04`、`1b78`、`1b5b5a` | 不接管 |

- 原因：输入法和 adb 发来的键 scanCode=0，Flutter 给的物理键是合成值 0x11_0000_0000+keyCode，flterm 只按物理键查表，认不出就 ignored；Flutter 引擎 `InputConnectionAdaptor.handleKeyEvent` 又不处理 KEYCODE_DEL，这个退格就被丢掉了。
- adb `input keycombination` 注入的 Ctrl/Alt 组合到达 Flutter 时 Ctrl 先抬起，测不了组合键；`adb emu event send` 在无窗口模式下事件不进内核（getevent 看不到）。所以组合键只认 `sendevent` 那一行。
- 模拟器虚拟键盘的键位表 `qwerty2.kl` 把扫描码 1（Esc）映射成 BACK，Esc 被系统当返回键吃掉，不是 App 问题；真实蓝牙键盘用 Generic.kl，不会这样。

### 收起后叫不回键盘

按返回收起软键盘，或切到桌面再回来，之后连点终端两次 `mInputShown` 都是 false。flterm 内部仍记为 showing，`showKeyboard()` 空操作，点按只 requestFocus。`KeyboardReshow`（轻点抬起、键盘未占位时 hide+show）修后同样步骤都能叫回。

### 中文输入（TER02 的模拟器部分）

**不打补丁打不了中文。** 终端获得焦点时 EditorInfo `inputType=0xa0091`（可见密码），Gboard 进 PasswordIme，空格键显示 QWERTY，敲 nihao 直接逐字母发出，没有候选。
原因在 Flutter 引擎 `TextInputPlugin.java:294-297`：`enableSuggestions=false` 会同时加 VISIBLE_PASSWORD；flterm 写死 multiline + 无建议。
原版 Netcatty（xterm2）同样无建议，但用 emailAddress，`0x20|0x90` 落成 FILTER（0xB0），不是密码——**直接换成 flterm 会让中文输入倒退**。

`spikes/terminal_spike/patches/flterm-0.0.5-android-ime.patch` 三处改动：inputType 改 emailAddress（实测 `0x800b1` Filter，Gboard 进 LatinIme）；scanCode=0 的键按逻辑键编码；这类键处理后推两次编辑状态，逼引擎给输入法发 updateSelection。
打补丁后，Gboard 拼音在"内联组字"开、关两种设置下，下面整套都对：

| 操作 | 发出的字节 |
|---|---|
| 敲 n-i-h-a-o（出候选：你好 / 你还 / 你 / 尼…；内联开时终端光标处显示带下划线的 "ni hao"） | 无 |
| 点候选"你好" | `e4 bd a0 e5 a5 bd`，一次 |
| 提交后退格 | `7f`，一次 |
| 敲 c-e-s-h-i 再退格 5 次删光（撤销组字） | 无 |
| 组字已空再退格 | `7f` |
| 敲 l-s 按回车（组字中） / 再按回车 | `6c 73`（不带换行） / `0d` |
| 敲 z-h-o-n-g 按空格（选首候选） | `e4 b8 ad`（中） |
| 敲 g-i-t 按空格（混排） | `67 69 74` |

第三处改动的由来：输入法发来的 DEL 被终端吞掉后编辑区没变，平台不通知输入法光标位置，Gboard 按"已删一字"估算，之后内联组字区间错一位（组字区间 2-3 而不是 1-3），删拼音时漏发一个字母。
A/B（内联组字开，先退格一次再敲 ceshi 删光，各 3 轮）：去掉重对齐 3/3 漏发 `63 7f`；加上 3/3 只有预先那一次 `7f`。补丁的干净版本（去掉调试日志）重新构建后复测一致。
麦克风：`aapt2 dump permissions` 看 spike 和 fork 的 APK，都没声明 RECORD_AUDIO，App 自己没法申请；语音输入走输入法自己的权限。
未测：语音输入本身（宿主麦克风已关）、搜狗/讯飞/百度等国产输入法、真机。

## 发现的问题

1. **dispose 后 write 会段错误，整个进程崩溃**（flterm 0.0.5）。复现：`XWSHUN_RUN_KNOWN_FAILS=1 flutter test --plain-name 已知问题` → `TestDeviceException(Shell subprocess crashed with segmentation fault.)`。终端页销毁后 SSH 迟到的数据会让 App 闪退。R17 适配器必须按代次在 Dart 层挡住（`GuardedWriter.close()` 已示范）。
2. **软键盘退格、蓝牙遥控类按键 0 字节**（模拟器）。适配层兜底 `lib/android_key_fallback.dart` 可修，但会引出问题 4，完整修法要进 flterm。
3. **收起后叫不回键盘**（模拟器）。适配层 `lib/keyboard_reshow.dart` 可修。
4. **打不了中文**（模拟器，Gboard）。只能改 flterm，补丁见上；内联组字漏字也要补丁里的重对齐。
5. **native 库缓存副本被篡改不会被发现**（GST01）：
   - 实验 B：篡改共享下载缓存并删掉 hook 输出 → hook 重跑，发现 hash 不符 → 删除 → 重新下载 → 正确。✔
   - 实验 A3：只篡改 hook 输出目录里的副本（在代码段内翻转 1 字节）→ 删 `build/` 重建 → **构建成功，篡改过的库进了 APK**（strip 后 `ddac4e6f…`，正确应为 `1c78966d…`）。hook 只在下载时校验，hooks_runner 按输入缓存输出，已有副本不再校验。
   - 实验 A/A2（在文件末尾追加字节）无效：strip 会丢掉 section 之外的字节，测不出东西，已作废。
   - 缓解：发布构建先删 `.dart_tool` 再构建（会重新下载校验），或在 R17 加打包前校验。
   - 同类的构建缓存坑：换 `pubspec_overrides.yaml` 的 path 后，Gradle 按旧依赖清单判断"没变"，跳过 Dart 编译产出旧 APK（spike README 有核对办法）。
6. **组合字符缺重音**（模拟器），绘制层。
7. **默认资源上限远大于计划预算**：`scrollbackLimit` 默认 10,000,000，Kitty 图像存储 64 MiB；另外按 TLS 段大小推算，每个访问过它的线程可能多占约 256 KiB（推算，未实测）。R17 必须显式设限并实测。

## 要解除 BLOCKED 需要什么

1. 一台 ARM64 真机 + 用户常用中文输入法，在打过补丁的 spike 回环页人工走一遍上表（含语音输入到普通编辑区、不自动申请麦克风权限）。
2. 所有者或 R17 决定 flterm 补丁的去向：fork 进仓库维护，还是先向上游提 issue/PR 再 pin 新版本。
3. REL03 另需：真机复核；以及 armeabi-v7a、x86_64 要么找设备实测，要么发布时只声明 arm64（这台 Apple Silicon Mac 跑不了 x86_64 镜像）。最低 API 已按所有者"最低兼容到安卓七八"在模拟器上覆盖 24–27，不需要再把最低版本提高到 28。
