## 基座原来是什么样（先看清楚再动的）

| 地方 | 基座 | 后果 |
|---|---|---|
| `SshKeepAliveService` | 只要有标签（哪怕全断了）就开着，**一直拿不限时的 PARTIAL_WAKE_LOCK 和 `WIFI_MODE_FULL_HIGH_PERF` 锁** | 前台服务在 Doze 里唤醒锁照样生效（AOSP `PowerManagerService` 只禁 procState 高于 BOUND_FOREGROUND_SERVICE 的），开着会话 CPU 就永远不睡；Play vitals 把 24 小时累计 2 小时算过度。Wi-Fi 高性能锁在 Android 14+ 被换成低延迟锁，后台根本不生效 |
| 通知 | 只有「点击返回」，没有停止 | 要停只能逐个关标签，或在系统里强行停止 |
| 返回手势 / 从最近任务划掉 / 关画中画小窗 | `FlutterActivity` 结束，它自己建的引擎随之销毁 | **会话全没了，前台服务和通知却还挂着**（R17 发现的问题 2）。FlutterActivity 重写了返回键，绕过了 Android 12 起「根 Activity 按返回退到后台」的系统行为 |
| 后台断线 | 每 8 秒保活一次，断了就无限次重连（退避到 30 秒封顶），除了 Tailscale check、tmux 目标不在，**什么错都重试**（指纹不对、密码错也一样），**锁着屏也照样重新登录** | 拿同一套凭据反复去撞；锁屏时替用户登录 |
| 前台断线 | 不恢复，提示「返回前台后将自动重连」 | 人就在前台，只能切到后台再切回来；终端页没有任何重连入口 |
| 换网络 | 没有处理。dartssh2 自带的 keepalive 只发不等（`SSHKeepAlive` 吞掉错误），半死的连接在前台永远发现不了 | Wi-Fi 还连着但上不了网、NAT 掉了时，标签一直显示连着 |
| 服务器监控 | 后台也每 3 秒开一个 exec 通道读 `/proc` | 屏幕关着没人看，白费电和流量 |
| 进程被结束 | 标签全没了，tmux 目标也没了（R21 留下的） | 不知道上次开着什么 |
| 断开后的终端 | 还绑着已关的 SSH 通道 | **本次在模拟器上撞上**：回前台时终端量出新尺寸，往关掉的通道发 window-change，`SSHStateError` 一路抛进 `performLayout`；断线后转屏、在断开的标签里敲字也是这条路 |
| iOS | `sshBackgroundAudioKeeper` 放静音音频保活 | 就是 R22 停止条件禁止的「假媒体」。本 fork 不出 iOS 包，**没动也没测**；要出 iOS 时必须先去掉 |

## 改成了什么样

```text
MainActivity ──provideFlutterEngine──> ProcessEngine（进程里唯一的引擎）
                                         ├─ ConnectionChannel：开关保活服务（带代次和通知内容）、锁屏查询、默认网络变化
                                         └─ PluginBridge（插件会话的 Binder，原来跟着 Activity 走）
  有会话时 Activity 走了引擎留着；首页按返回 = moveTaskToBack
SshKeepAliveService（specialUse，START_NOT_STICKY，不拿任何锁）
  通知：「xwshun 终端：2 个连着，1 个在恢复」+「全部断开」 ──> Dart 先失效再释放 ──> 停服务（5 秒没反应自己停）
  被系统或别人停了 ──> 报给 Dart（带代次）
SessionController
  断线 ──> 当场试一次，之后按 1/2/5/10/15/30 秒退避，窗口 120 秒（没网的那段不算）
           非网络错误（指纹、凭据、路线、代理拒绝、check、tmux 目标不在）──> 停，写原因
           后台 + 手机锁着 ──> 停（untilForeground），回前台再给一轮
  换了默认网络 ──> 逐条 ping（15 秒），答不上的才算断
  后台满 10 分钟 ──> 冻结路线 withoutSecrets()；恢复时 rehydrateRoutePlan() 按保险库补回、形状不同就停
  通知「全部断开」/ 后台时服务被停 ──> stopAll：失效所有尝试和恢复 → 释放连接 → 标签留着写原因
  标签清单（主机 ID + tmux 目标）写 SharedPreferences；启动时放回成断开的标签，点了才连
终端页：断开的格子顶上挂状态条（叠在终端上，不改尺寸）+「重新连接」
```

**做法**：三条标签——`usb` 走 adb reverse（经 USB 线），`wifi`、`tick` 走手机 Wi-Fi 到 xdwmbp 上只放行手机 IP 的转发（无 NAT），

锁屏约 30 分钟以上，插回线、解锁。手机睡了多久 = 墙上时钟减 Dart `Stopwatch`（它不算休眠时间）。服务器那头每 5 分钟看三条最初的 sshd 进程还在不在。

**结论**：两轮里 App 说的状态每次都对得上真实情况（说连着的当场都能跑命令，说断了的确实断了），没有一次多余的登录；锁着屏不登录，解锁回到 App 才恢复。
这台手机上，**不加省电豁免时 Wi-Fi 上的两条连接锁屏 31 分钟照样活着、远端输出一条不丢，加了豁免也一样**——前台服务的进程本来就不受 Doze 断网，
豁免在这个时长里没起作用。只说明这一台手机、这一个 Android 版本、局域网直连（没有 NAT、没走蜂窝）、30～40 分钟内是这样，**不说明默认配置能无限保活**：
NAT 超时、蜂窝、国产 ROM 的后台策略、几个小时的锁屏都没测。

**撞到的**：

1. **第一轮前台后段 App 一直占一个核**（CPU 106%，RSS 631 MB，Native Heap 78.5 MB，核对 10–13 秒才回）：测试为了不让 `pump` 在 App 被盖住时卡死，用了 `framePolicy = fullyLive`，
   而 flutter_test 的 live binding 在这种模式下画完一帧立刻排下一帧（`handleDrawFrame` 末尾 `scheduleFrame()`），debug 包 120 帧/秒一直重画。第二轮改回按需出帧（每秒一帧、只在 App 在最前时），CPU 6–17%。
   正式 App 不这样出帧。
2. **插着 USB 线手机 CPU 不睡**（试跑：锁屏 187 秒睡了 0 秒）；**插着电按电源键进的是屏保**（所有者开了「充电时显示屏保」），拔了线屏保也可能不退（试跑：162 秒睡了 0 秒）。所以锁屏阶段先拔线再锁屏；
   拔线后 flutter 连不上手机，脚本先 `kill -9` 它，测试把日志另写一份到私有目录，插回后读。解锁时手机 USB 重新握手、adb 断 2–3 秒，反向转发跟着没了，脚本重建。都写进了本机手册。
3. **新发现的漏洞（已修，a067eff）**：凭据副本的 10 分钟租期只靠 Dart `Timer`，它按 CPU 醒着的时间走。第一轮锁屏 31 分钟 CPU 只醒 2 分钟，租期一直没到点，解锁回来恢复时用的还是冻结在内存里的密码；
   SEC07 定的「后台 10 分钟清掉」在真机上成了「醒着累计 10 分钟」。改成记下进后台的墙上时间，后台探活、每一轮恢复、回前台之前都核一次，过了就先清、再按保险库重取（两条新单元测试，去掉这一步都会挂）。
   **修完没在真机上再跑**：长测测试已经加了 `lease.forgotten` 一行，下次跑就能看到。
4. 第二轮 USB 那条停在「这台主机已经从保险库里删掉了」：测试用的是不在保险库里的临时主机，后台满 10 分钟（那一轮 CPU 醒得多，`Timer` 到了点）清掉凭据副本之后它才断，恢复时找不到来源。
   正式 App 的标签都对应保险库里的主机（主机列表、tmux、托管终端都记着来源），所以是测试造的；测试已改成先存进保险库（c5edd37）。
5. **我又犯了一次并行的错**：第一轮锁屏期间我在模拟器上跑出帧实验（下面 LIFE06 那段），它连了一次同一个测试环境的 sshd，服务器登录计数多了 1（18:29:32）。
   手机那时拔着线（USB 那条连不过来），Wi-Fi 两条要经 xdwmbp 的转发、转发日志里没有新连接，所以那一次不是手机的；后面的模拟器实验改成不连 SSH。
6. 解锁后测试包黑屏几十秒（所有者看到）：测试包只在测试代码 `pump` 时出帧，解锁后要等脚本确认 App 回到最前、测试画一帧才有画面；20:27 测试画完后的截图内容正常。
   正式 App 回前台由 Flutter 自己重画，模拟器上放回标签那次正常，**真机上没拿正式包试过锁屏再解锁**。
7. 通知标题原来只数连着、在恢复、在连接的，锁屏断掉在等的那条不写（试跑时看到「2 个连着」，看不出还有一条停着）。改成也写「N 个等回到 App 再恢复」「N 个停了，要你处理」（a420e57），两轮正式跑里都看到了。

## 发现的问题

1. **断开后的终端还绑着已关的 SSH 通道**（基座就有，R22 回前台时更容易撞上）：终端量出新尺寸、用户在断开的标签里敲字，都往关掉的通道写，
   `SSHStateError` 一路抛进 `performLayout`。修法：连接释放（`abort`）时解除终端到它的输入和尺寸绑定；终端那头再兜一层，连接端抛什么都不传给按键和布局（5911504，有回归测试）。
2. **测试环境的 sshd、socks 容器不能单独重启**：入口脚本每次启动都 `adduser`，第二次就报错退出；sshd 还每次启动换主机密钥。改成建用户先查、密钥只在新容器生成（6103d4d）；`up.sh` 之后指纹照样变。
3. **我自己犯的错**：切网场景第一次跑的时候，我在本机跑全量 `flutter test`，其中 `integration_ssh_fixture_test` 会 pkill ssh-edge 上的全部会话、数连接数（本机手册第 7 节写着不能和别的连同一测试环境的测试并行）。
   设备上那一轮从 t+165 秒起两条连接都被反复杀掉，结果作废、重跑（上表是重跑的）；本机那几条失败也单独重跑，查出是下面第 4 条，不是被搅的。
4. **断线当场就自动恢复以后，「手动再恢复一轮」的接口会提前返回**：`reconnectDisconnected()` 发现已有一轮在跑就直接返回，调用方马上看「连上没有」看到的是半路状态（真实 OpenSSH 上 LIFE06 连接层、NET10 两条因此挂）。
   改成等手头那一轮跑完再跑自己的（1881953）。R21 的 TMX04/05/08 测的是「断线后服务器上先改了东西、再恢复」，自动那一轮会抢在改动前把原目标附着回来，测试里报「没有网络」关掉自动的那一轮，另补一条测自动重新附着（92db386）。
5. 本 App 的通知是 IMPORTANCE_LOW，系统把它放在通知栏「静音」区、**默认折叠**，「全部断开」要点右边的箭头展开才看得到（手册写了）。要不要提高重要性（会出现在上面、但可能有提示音）没改，留给 R25 和所有者。
6. 冷启动照旧停在「保险库」页，放回来的标签在「终端」页（手册写了）。要不要有放回的标签时直接进终端页，留给 R25。
7. 模拟器上撞过的墙（写进本机手册第 2 节）：集成测试等回执时不出帧，截图是黑的；`settings put global always_finish_activities 1` 不生效，要在开发者选项里真点开关；
   开发者选项里那一项是弯撇号「Don’t keep activities」；`adb … | grep -m1` 配 `pipefail` 会让脚本悄悄退出。

## 没做的、留给后面的

- **真机只跑了 LIFE07**（Pixel 9 Pro / Android 17，见「真机长测」），其余都是 Android 15 模拟器。Android 7–14 的前台服务行为（14 起要类型、12 起后台不能启动）、预测性返回（16 起默认开）、
  国产 ROM 的后台策略、蜂窝和 NAT 后面的长连接、几个小时的锁屏都没测。
- 凭据租期按墙上时钟（a067eff）修完没在真机上再跑；正式包在真机上锁屏再解锁的画面没看过（测试包解锁后黑屏几十秒是测试框架出帧方式造成的，见「真机长测」撞到的 6）。
- 后台启动前台服务被系统拒绝的那条路（`ForegroundServiceStartNotAllowedException` → 状态条提醒、回前台再开）：按现在的设计不会在后台去开，设备上没触发过，只有代码。

- 凭据副本租期：设备上没等满 10 分钟，只有单元测试（30 毫秒租期）。保险库整体在内存、连着的连接里 dartssh2 拿着私钥，这两样清不掉（手册写明）。
- 应用锁、生物识别：所有者定另开任务。
- **LIFE06 记 FAIL**：整个标签开关一次 Native Heap 涨约 40 KiB（显示终端），只连 SSH 不显示约 10 KiB，只建销毁引擎和视图约 1 KiB。

  10-10 排除了一种可能——「终端每画一帧漏一点」：模拟器上一直出帧 20 分钟（`framesview`，约 7.2 万帧）Native Heap 55.9→65.3 MB，
  可同样的字换成 Flutter 自带 `Text`（`framestext`）也涨 54.2→62.4 MB，每帧 0.13 / 0.12 KiB，差在噪声里；不动时两者都不涨。是 debug 包一直出帧时 Flutter 自己的，不是 Ghostty 的。

- 归 R23 的：断线那一刻的输入标「结果未知」（NET11）；放回来的标签、恢复成新 shell 时旧画面和新 shell 的边界（REG04）。
