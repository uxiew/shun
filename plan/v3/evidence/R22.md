## 基座原来是什么样（先看清楚再动的）

| 地方 | 基座 | 后果 |
|---|---|---|
| `SshKeepAliveService` | 只要有标签（哪怕全断了）就开着，**一直拿不限时的 PARTIAL_WAKE_LOCK 和 `WIFI_MODE_FULL_HIGH_PERF` 锁** | 前台服务在 Doze 里唤醒锁照样生效（AOSP `PowerManagerService` 只禁 procState 高于 BOUND_FOREGROUND_SERVICE 的），开着会话 CPU 就永远不睡；Play vitals 把 24 小时累计 2 小时算过度。Wi-Fi 高性能锁在 Android 14+ 被换成低延迟锁，后台根本不生效 |
| 通知 | 只有「点击返回」，没有停止 | 要停只能逐个关标签，或在系统里强行停止 |
| 返回手势 / 从最近任务划掉 / 关画中画小窗 | `FlutterActivity` 结束，它自己建的引擎随之销毁 | **会话全没了，前台服务和通知却还挂着**（R17 发现的问题 2）。FlutterActivity 重写了返回键，绕过了 Android 12 起「根 Activity 按返回退到后台」的系统行为 |
| 后台断线 | 每 8 秒保活一次，断了就无限次重连（退避到 30 秒封顶），除了 Tailscale check、tmux 目标不在，**什么错都重试**（指纹不对、密码错也一样），**锁着屏也照样重新登录** | 拿同一套凭据反复去撞；锁屏时替用户登录 |
| 前台断线 | 不恢复，提示「返回前台后将自动重连」 | 人就在前台，只能切到后台再切回来；终端页没有任何重连入口 |
| 换网络 | 没有处理。dartssh2 自带的 keepalive 只发不等（`SSHKeepAlive` 吞掉错误），半死的连接在前台永远发现不了 | Wi-Fi 还连着但上不了网、NAT 掉了时，标签一直显示连着 |
| 服务器监控 | 后台也每 3 秒开一个 exec 通道读 `/proc` | 屏幕关着没人看，白费电和流量 |
| 进程被结束 | 标签全没了，tmux 目标也没了（R21 留下的） | 不知道上次开着什么 |
| 断开后的终端 | 还绑着已关的 SSH 通道 | **本次在模拟器上撞上**：回前台时终端量出新尺寸，往关掉的通道发 window-change，`SSHStateError` 一路抛进 `performLayout`；断线后转屏、在断开的标签里敲字也是这条路 |
| iOS | `sshBackgroundAudioKeeper` 放静音音频保活 | 就是 R22 停止条件禁止的「假媒体」。本 fork 不出 iOS 包，**没动也没测**；要出 iOS 时必须先去掉 |

## 改成了什么样

```text
MainActivity ──provideFlutterEngine──> ProcessEngine（进程里唯一的引擎）
                                         ├─ ConnectionChannel：开关保活服务（带代次和通知内容）、锁屏查询、默认网络变化
                                         └─ PluginBridge（插件会话的 Binder，原来跟着 Activity 走）
  有会话时 Activity 走了引擎留着；首页按返回 = moveTaskToBack
SshKeepAliveService（specialUse，START_NOT_STICKY，不拿任何锁）
  通知：「xwshun 终端：2 个连着，1 个在恢复」+「全部断开」 ──> Dart 先失效再释放 ──> 停服务（5 秒没反应自己停）
  被系统或别人停了 ──> 报给 Dart（带代次）
SessionController
  断线 ──> 当场试一次，之后按 1/2/5/10/15/30 秒退避，窗口 120 秒（没网的那段不算）
           非网络错误（指纹、凭据、路线、代理拒绝、check、tmux 目标不在）──> 停，写原因
           后台 + 手机锁着 ──> 停（untilForeground），回前台再给一轮
  换了默认网络 ──> 逐条 ping（15 秒），答不上的才算断
  后台满 10 分钟 ──> 冻结路线 withoutSecrets()；恢复时 rehydrateRoutePlan() 按保险库补回、形状不同就停
  通知「全部断开」/ 后台时服务被停 ──> stopAll：失效所有尝试和恢复 → 释放连接 → 标签留着写原因
  标签清单（主机 ID + tmux 目标）写 SharedPreferences；启动时放回成断开的标签，点了才连
终端页：断开的格子顶上挂状态条（叠在终端上，不改尺寸）+「重新连接」
```

## LIFE06 复查（2026-10-25）

**结论**：原来记 FAIL 的「每开关一次 Native Heap 涨约 40 KiB」是量法造成的，不是 App 漏的。去掉量法里的三个干扰（用 profile 包、关掉 Dart 时间线、量之前不调 `getAllocationProfile`）以后，模拟器上显示终端开关 1200 次，第 200→1200 次 Native Heap 只多 99 KiB（约 0.1 KiB/次，采样点之间本来就上下浮动 ±200 KiB），Dart 堆不涨；只开关 SSH 400 次，最后 100 次多 6 KiB。heapprofd 按调用栈查了剩下的未释放分配，落在有上限的缓存和模拟器的 GL 驱动上，Ghostty 和 App 自己的代码没有逐轮留下的。

顺带查出一个真漏，已修（e40534d）：借用连接（`SshLease`）每做一步就在「连接断了」的 future 上挂一个监听，连接不断就永远不摘，连同那一步的结果一起留着。服务器监控在每个连着的 SSH 标签上每 3 秒采一次、复用同一个借用（`session_controller.dart` 的 `_watchSession` 一连上就开），所以每个标签每 3 秒多留一份采样输出。测试环境那台机器一次采样输出 1091 字节，连同几个 future、闭包算约 1.3 KB，推算下来每个连着的 SSH 标签每小时多留约 1.5 MB、直到断线才还。按时间涨，不按开关次数，所以以前的量法看不出来。

LIFE06 改记 PASS。只是模拟器、profile 包的证据，发布包和真机没这样量过，见本节末。

### 怎么量的

- 模拟器 `shun-r39-a30`（Android 11 / API 30，arm64，Play 镜像，没有 root），本机测试环境的 sshd（`adb reverse` 22201）。跑法和每个开关的意思见本机手册 `docs/dev/README.md`「LIFE06」那段。

### 三个干扰

1. **`getAllocationProfile` 调一次留下 8–19 MB 原生内存，不还。** debug 包第 50 轮采完样调一次，第 50→100 轮 63551→82497 KiB（+18.5 MiB），之后 80564、82919 不再涨；profile 包第 200 轮调一次，下一个采样点 51753→59500 KiB（+7.6 MiB）。R20 资源门禁的脚本（R22 重跑的是同一个）第 100 轮先抓 meminfo、再调 `_heapAfterGc()`（就是这个调用），第 500 轮的 meminfo 落在它之后：R20 的 +15.2 MiB、R22 重跑的 62975→79084 KiB（+15.7 MiB）基本都是这一下，除以 400 次就成了「约 40 KiB/次」。R20 真机的「约 39 KiB/次」是同一个脚本。（专门复现它的那一轮：第 100 轮调完，第 101 轮等连接超时挂了，只跑了一次、没再试；上面两个数是另两轮里顺带看到的。）
2. **debug / profile 包里 Dart 时间线按帧涨。** heapprofd 抓到 `TimelineEventRecorderWithPerfettoSupport::AddAsyncTrackMetadataBasedOnEvent` 往一张 `SimpleHashMap` 里加条目，调用方是 `flutter::Animator::RequestFrame`：引擎每请求一帧发一个新 ID 的异步事件，记录器给每个 ID 存一条、不删。profile 包只开关 SSH 第 100→300 轮没释放的 2208 KiB 里，时间线相关的约 800 KiB。同一版本的发布版引擎（Flutter 3.47.7，engine `deb287481e`，`bin/cache` 里 flutter.jar 带符号的 libflutter.so）里这个函数只有一条 `ret`，会存东西的那两个版本不存在。测试开头用 `setVMTimelineFlags` 关掉所有流以后，profile 包显示终端的斜率从 2.42 降到 0.71 KiB/次，只开关 SSH 从 2.0 降到 0.29。上面「没做的」里 10-10 的出帧实验多半也是它。

### Dart 堆和修掉的漏

修漏之前那组 1200 轮里 Dart 堆一路涨：第 200→1200 轮 27311→27458→27532→27613→27688→27773 KiB（约 0.46 KiB/次）。类快照对比（`--classdiff`，第 400→800 轮，`life06-view-profile-20261025-160513`）里 App 侧涨的只有 `_Future` +124、`_FutureListener` +62、`_AsyncCompleter` +62、`_Closure` +59、`Context` +62，引用链是一长串 `_FutureListener._nextListener`，挂在常驻标签的 `SshLease._lost` 上。400 轮约 190 秒涨 62 个，正好是每 3 秒一次的监控采样。

修法（e40534d）：不再在 `lost` 上挂 `.then`，借用自己记一张「还在等结果的操作」，做完就删，断线时把表里的一起报错（还是放到下一个 microtask，和以前的时机一样）。下载、预览用的 `readStream` 同样处理。新单测在 `test/r24_borrowers_test.dart`：复用的借用做 100 步后不挂着任何等断线的操作、没做完的照样报断线；下载流读完、被取消后也不挂着。把「做完就删」去掉，第一条报 `Expected: <0>, Actual: <101>`。

修完在模拟器上重跑：同样的类快照对比（`life06-view-profile-20261025-161659`）里 `_Future`、`_FutureListener`、`_AsyncCompleter`、`_Closure`、`Context` 的增长都是 0；1200 轮长跑里 Dart 堆 27563→27372→27704→27449→27810→27535 KiB（第 200→1200 轮），上下晃、不涨。

量的时候要知道的：类快照里涨得最多的 `_OneByteString`、`_List`、`_Record` 一开始大半是测试自己存的第一份快照（每个类一个类名字符串、一个 record），改成压成一个 JSON 字符串存、第二份取完再解码才干净；剩下的那个大字符串和它的临时表也还在增长里。有上限的历史会涨到封顶：服务器监控历史 60 条（约 3 分钟）、连接记录每台 200 条、一共 1000 条；`flutter_test` 的 `TestPlatformDispatcher._testFocusEvents` 每轮记 2 个 `ViewFocusEvent`（各 32 字节，正式 App 里没有这个测试类）。

### 没量的、说明不了的

- 只在模拟器（Android 11）上、用 profile 包量的。发布包没法这样量：没有 VM service，测试叫不动 Dart GC；真机没跑。
- fd、线程这次没重量，用 R20 / R22 的（第 100→500 次斜率 0）。Mosh 这条链路（X10 的约 10.7 KiB/轮）是 debug 包、时间线开着量的，没按新量法重量。
- 「每小时约 1.5 MB」是按采样输出大小推算的，没在设备上挂一小时实测；修之前的发布包、真机走的是同一段代码，也有这个漏。
- 真机长测第二轮锁屏 56 分钟里（不出帧，只有 tick 输出和每 8 秒的后台探活，醒着约 17 分钟）Native Heap 59.0→66.3 MB，而前台 30 分钟持平在 59 MB 左右：debug 包、时间线开着，没重跑，不知道是不是时间线或刚修的那个漏。
