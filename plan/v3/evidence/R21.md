## 基座原来是什么样（先看清楚再动的）

| 地方 | 基座 | 实测后果 |
|---|---|---|
| 列会话 | `tmux list-sessions -F '名字<Tab>…'`，按 Tab 拆 | tmux 2.4–3.5a 输出时把格式里的 Tab 换成 `_`，**列表永远是空的**（面板一直显示「还没有 tmux session」）。基座的单元测试喂的是手写的 Tab 分隔文本，所以没发现 |
| 附着 | 在交互式 shell 里打一行 `tmux set-option -t '=名字:' mouse on \; attach-session -t '=名字:'` | ① 顺手把这个会话的 mouse 打开（改了用户的配置）；② 打进交互式 shell：`.bashrc` 里自动起 tmux 的话就打进了错的地方；③ 进 shell 历史；④ 断线恢复后只剩一个普通 shell（R03 起不重跑启动命令），回不到原来的会话 |
| 结束 | `tmux kill-session -t '名字'`（没有 `=`） | tmux 找不到精确名字就按前缀找：**`work` 已经不在时结束的是 `workshop`**（2.7、3.5a 实测，测试「基座对照」复现） |
| 新建 | `tmux new-session -d -s '名字' && tmux send-keys -t '名字' '命令' C-m` | ① `-s` 的值会被 tmux 做格式展开，名字里的 `#(命令)` 会被执行（2.7、3.0a、3.5a 实测）；② send-keys 按名字（同样的前缀匹配问题），命令不加 `-l`，里面的 `Enter`、`C-c` 之类会被当成按键 |
| 输出 | 整个 stdout 读进内存，不设上限 | 远端吐多少读多少 |
| 中文 | exec 通道里没有 LANG | tmux 按 C 语言环境输出，名字里的中文每个字节都变成 `_`（2.4、3.5a 实测；存着的名字没坏） |
| 关标签 / 断网 / 退出 App | 只关通道，不发 Ctrl-C、不 kill（这一点基座本来就对） | 本次用真实 tmux 逐字节核对过，见 TMX08 |

没找到基座「自动新建」的地方：查询不建、附着不建；所谓「自动新建默认」在基座里不存在，危险的是按名字匹配。

## 改成了什么样

```text
面板（只读查询）──标签自己的 SSH 连接──> sh -c '固定脚本' xwshun '白名单参数'… ──> tmux -u -S <socket> list-sessions
        │                                             （名字、启动命令走 stdin；输出远端 head/cut + 本地字节上限）
        └─ 附着 ──> SessionController.openTmuxTerminal（沿用来源标签冻结的路线）
                   ──> SshService：带 PTY 的 exec 通道跑附着脚本
                         1. 核对 uid、socket、server pid + 启动时间、session ID + 创建时间（不对：退出 95/96/97，不附着、不新建）
                         2. 报回本客户端的终端和 pid → TmuxClientBinding（恢复元数据，存在标签上）
                         3. App 先绑定终端（尺寸发过去）再回一个换行 → 再核对一次 → exec tmux -u attach-session -t '$ID'（不带 -d）
断网 ──> 自动恢复用同一个目标重新附着；远端核对不过 → 标签停下、写明原因、不再重试
tmux 客户端自己退出（分离、会话结束）──> 不算断线，不自动重新附着
```

| 文件 | 作用 |
|---|---|
| `lib/domain/tmux/tmux_target.dart` | 目标：hostKey（路线目标地址）、Unix 用户和 uid、socket（默认 / `-L` / `-S`，白名单）、server 身份（socket 路径 + pid + 启动时间）、session ID + 创建时间；客户端绑定（tty + pid） |
| `lib/infrastructure/tmux/tmux_protocol.dart` | 固定脚本和命令构造（脚本里不含单引号、`!`、`\\`、换行，sh/bash/zsh/fish/csh 下单引号里都原样）；查询/新建/详情输出解析（分隔符 `|~|`，名字放最后；两个 server 或重复 ID 时整表不可信）；版本解析（≥2.4 才给操作）；显示用文字去控制字符和双向控制符；退出码 → 说法 |
| `lib/infrastructure/tmux/tmux_service.dart` | 在标签自己的 SSH 连接上执行：期限（查询 10 秒、操作 15 秒）、输出上限（查询 1.5 MiB）；probe / create / kill / setMouse / detach / details |
| `lib/infrastructure/ssh/ssh_service.dart` | `connect(tmuxAttach:)`：exec 通道 + PTY 跑附着脚本，握手拿客户端绑定；`ActiveTerminalSession.tmux` |
| `lib/application/session_controller.dart` | `openTmuxTerminal`（沿用来源标签的冻结路线，hostKey 对不上直接拒绝）；恢复带目标；目标不在了停下；客户端自己退出不算断线 |
| `lib/presentation/widgets/system_management/tmux_manager_panel.dart`、`system_management_sheet.dart` | 面板重写：版本 / socket / 用户、按可用性给说明、会话卡片（`$ID`、前缀键、鼠标）、附着、结束（确认）、单会话鼠标开关（确认写明作用范围）、新建（只建不附着）、详情（窗口、客户端，标出本标签）、「分离本标签」 |
| `lib/presentation/screens/terminal_screen.dart` | 关标签确认框：tmux 标签写明只分离客户端；普通标签写明 shell 里的程序通常随连接结束 |
| `lib/infrastructure/ssh/system_management_service.dart`、`lib/domain/models/system_management.dart` | 删掉基座按名字拼命令的 tmux 方法、模型和它们的测试 |
| `tool/tmux-fixture/` | 测试环境，见那里的 README |

## 验收

| 验收项 | 结果 | 证据 |
|---|---|---|
| 目标含 host/user/socket/server 代次 | 是 | `TmuxTarget` 七项一起比（`sameAs`），任一项不同都不算同一个（单元测试逐项改）。远端核对串 `$ID:server pid:server 启动时间:session 创建时间`，再加 uid、socket 文件；host 由「沿用来源标签的冻结路线 + hostKey 不对直接拒绝」保证 |
| 缺失不新建同名 | 是 | TMX04：断网后删掉目标、另建同名，恢复停下、写明原因，同名的新会话没有被附着，会话总数不变；TMX05：server 重启后 `$0` 被重用，不附着 |
| 查询无副作用、命令不注入 | 是 | 查询前后 `/tmp/tmux-1000` 不存在、没有 tmux 进程（四个版本）；恶意名字（`#(touch …)`、`$(…)`、引号、分号、Tab/换行、转义序列、300 字符、中文）只显示、按 ID 结束后什么都没执行；新建名字白名单在 App 这边拒绝，远端什么都没建；启动命令按字面输入 |
| 关标签不 kill/Ctrl-C | 是 | TMX08：pane 里跑 `stty raw; dd bs=1` 逐字节记录输入，关标签、断网、分离、整个 App 停止四种离开之后会话都在、pane 没死，记录到的只有测试自己打的 `typed`，没有 0x03 |

停止条件「不支持版本/自定义配置先退到普通 SSH，不自动修改远端配置」：版本 < 2.4 或认不出（`openbsd-7.5`、`master`）时面板只显示版本，不给附着/新建/结束，终端照常是普通 SSH；
附着不改任何选项（基座会开 mouse），tmux.conf 前后 md5 一致；鼠标只能对单个会话显式打开。

## 发现的问题

1. **基座的 tmux 面板在常见版本上列表永远是空的、按名字结束会误伤**（见「基座原来是什么样」）。已改。
2. **tmux 会对 `new-session -s` 的值做格式展开**：名字里写 `#(命令)`，tmux 就以用户身份执行它（2.7、3.0a、3.5a 实测）。
   这是 tmux 的行为，不只是基座的问题：用户在终端里自己 `tmux new -s '#(…)'` 也一样。App 这边新建时拒收 `#`。
3. **tmux 输出里的 Tab 会被换成 `_`、exec 通道里中文会被换成 `_`**：所有解析都不用 Tab 分隔，所有 tmux 调用带 `-u`。
4. **tmux 3.5a 的 `display-message -t 不存在的目标` 不报错**，输出空字段、退出码 0（2.4/2.7/3.0a 会报 `can't find session`）。
   核对身份时连 session_id 一起比，才不会把「找不到」当成「对上了」。
5. **附着刚完成那一瞬间敲的字可能丢**：附着测试里一返回就打字，tmux 2.4 上那几个字没到 pane；等客户端真的附着上再打就稳定。
   这和 X05 看到的「连接完成前敲的字前几个被丢」是一类，归 R23（输入在连接/附着边界上的去向）。
6. 远端 tmux 挂住时，App 按期限关通道，但没有 PTY 的 exec 通道关闭不会给远端进程发挂断信号，挂住的 `tmux -V` 会在远端留到它自己退出（假 tmux 那条测试里是 `sleep 600`）。
   只是查询，没有副作用；记一笔。
7. 测试环境的坑（假 tmux、老 busybox、`/proc/PID/stat` 进程名带空格）写进了 `tool/tmux-fixture/README.md`。
8. **关已断开的 tmux 标签时确认框说错话**（模拟器走查撞上）：恢复时已经查明原会话不在，确认框还说它「留在远端」。已改（4c90a5e）。

## 没做的（越界，留给后面的任务）

- **App 被杀、重启后的恢复**：目标存在标签上（内存里），App 进程没了标签也就没了；重启后要用户在面板里重新附着。持久化恢复元数据、进程死亡后的行为归 R22（生命周期）。
- **普通 shell 标签里用户自己敲的 tmux**：断线恢复照旧开一个新 shell，不会替用户附着（不暗建、不猜目标）；要回去用面板。是否提示「检测到你刚才在 tmux 里」归 R23/R25。
- **恢复不重放、旧画面隔离**：恢复只是重新附着，tmux 会整屏重画；断线时没送达的输入、附着边界上的按键归 R23（NET11、REG04、「发现的问题」第 5 条）。
- **手机上的 tmux 快捷操作**（切窗口、分屏、缩放的按钮，按实际前缀发键或按绑定的客户端发命令）、tmux 鼠标模式下的手势：R19 / R25。面板已经读出每个会话实际的前缀键和鼠标状态，供它们用。
- **xterm2 / Ghostty 两个引擎在 tmux 下的显示对比**：R20 的 TUI 门禁。本次集成测试用的是默认的 xterm2 适配器（标签里的终端引擎不影响附着逻辑）。
- **真机上的走查**：不在授权内。模拟器上走过（见「设备」）。
- 面板「默认 socket」按 `TMUX_TMPDIR`（exec 通道里一般没设）推路径，shell 配置里改了 `TMUX_TMPDIR` 的用户要自己填 `-S`。没去读用户的 shell 配置（会执行用户脚本）。
