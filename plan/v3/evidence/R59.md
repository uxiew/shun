## 真钥匙怎么测（SKY02–SKY05，所有者）

先在一台服务器上准备好：电脑上 `ssh-keygen -t ed25519-sk`，把 `.pub` 加到服务器 `~/.ssh/authorized_keys`。服务器 OpenSSH 要 8.2 或更新。

| 用例 | 做什么 | 应该看到 |
|---|---|---|
| SKY02 | 凭据页导入 `id_ed25519_sk`，主机选它，连接，钥匙贴手机背面 | 弹框写着 `用户@主机`，贴上就登录。再试「在钥匙上生成」「读取钥匙里已有的」 |
| SKY03 | 同一个主机，USB-C 插钥匙，第一次允许系统授权，碰钥匙；拔掉再插再登录；拒绝授权试一次 | 能登录；拔插不卡死；拒绝后最多 60 秒报「没有等到安全密钥」 |
| SKY04 | 弹框点取消；不碰等超时；通信中拔掉；`verify-required` 的密钥输错 PIN | 都报得清；PIN 显示剩余次数，不自己重试 |
| SKY05 | 连上后断网再恢复；经跳板；锁屏时断线 | 自动恢复停下说要碰钥匙，点重连才弹框；每跳分别碰；锁屏不弹 |

## 工具没测到、真钥匙上可能出事的地方

- **USB 授权框**：带通用 HID 接口的非钥匙设备（比如有按键的耳机）插着时也会弹框，授权后报「和安全密钥通信失败」。没授权读不了 HID 描述符，分不清。
- **NFC 贴的时机**：`NfcConfiguration` 用了默认超时。贴上后多久算掉线要实测。
- **新系统上的 USB 授权**：只读了 yubikit 3.1.0 的源码（`UsbDeviceManager.java`）：USB 插拔监听只收系统广播，Android 14 允许不带 exported 标志；授权回调用 `RECEIVER_NOT_EXPORTED`，`PendingIntent` 带 `setPackage`。没看到会崩的写法，但模拟器没有 USB，所有者手机上才算数。
- **不支持的**：老 U2F 钥匙（`Ctap2Session` 不替我们转协议）、agent forwarding。

## release 包

只有 release 才过 R8（裁剪和混淆）。第一次构建报 `Missing class edu.umd.cs.findbugs.annotations.SuppressFBWarnings`，单测和模拟器都查不出来，加了 `android/app/proguard-rules.pro`。之后构建通过，`mapping.txt` 里 `Ctap2Session`、`ClientPin`、`CredentialManagement`、两个 PIN 协议、`YubiKitManager` 都在。yubikit 只有 `YubiKeyPromptActivity` 用反射，我们没用它。**release 包上还没真的走过安全密钥的流程**，模拟器没钥匙，通道测试只有调试构建。

## 版本选择

yubikit-android 用 3.1.0，不是最新的 3.3.0：3.2.0 起 `minCompileSdk=37`，项目是 compileSdk 36（Flutter 默认），AGP 9.0.1 也只推荐到 36。构建直接报错 `Dependency 'com.yubico.yubikit:android:3.3.0' requires ... version 37 or later`。我们用到的公开接口（对照 `public` 方法签名）在 3.1.0 和 3.3.0 之间没变。以后升 compileSdk 时顺手升它。

Credential Manager、Rust crate、`dartssh2_conduit` 为什么不选见 [docs/21](../docs/21-credentials-sync-plan.md) 第 3 节。

## 这次顺手修的

- yubikit 的 `checkUsbDevice` 在授权**之后**才调，写在那里拦不住弹框，所以过滤放在 `checkVendorProductIds`。它首次扫描时把 deviceId 当 productId 传进来（`UsbDeviceManager.java:90`），所以只按厂商号比。
- yubikit 不做 PIN 的 Unicode NFC 规范化，CTAP2 要求做，桥里自己做。
