## 结论先说

- 主 App 里能「用 Mosh 连接」了：主机协议选 Mosh、连接路径直连，点连接 → 核对本机插件 → SSH 先核指纹再登录 → 只执行固定命令启动 mosh-server →
  **断开 SSH** → 把数字 IP、UDP 端口、临时 key 交给 Mosh 插件 → 插件经 UDP 直连。模拟器上点连接到出提示符 1.2–1.4 秒。
- **SOCKS、TailSocks、HTTP 代理、跳板、SOCKS+跳板五种路线都在任何网络动作之前拒绝**：桌面上拨号次数 0、远端 mosh-server 启动 0、SSH 登录 0、
  插件 0 次调用；模拟器上真 App 同样 0（远端记账 + 插件日志）。
- 指纹首见被拒、指纹变了、密码错：都停在 SSH，插件一次没被调用、远端没启动；服务器没装 mosh：如实报「远端没有安装 mosh-server」，
  测试环境里记账的 sudo/apk/apt-get 被调用 0 次。
- 输入和尺寸只有终端绑定一个出口：模拟器上回放输入法 8 段脚本经 Mosh 到远端的字节和 R18 经 SSH 的期望逐字节一致，每段「终端输入次数 = 宿主写入次数」；
  转屏三次远端 `stty size` 都等于引擎行列。
- 会话结束不自动重连、不重发输入，终端里写明原因；X08 留下的 `failed:exit-N` 说成了人话（退出码 1 = 多半 UDP 不通）。
- 设计取舍（理由见下面「设计取舍」）：UDP 发往 SSH 实际连上的 IP；Mosh 标签跟随终端引擎设置；Tailscale SSH 登录方式 + 直连允许（没测）。

### 设计取舍

- **UDP 发往哪个 IP**：SSH 那条 TCP 实际连上的 IP（`socket.remoteAddress`）。主机名只由系统解析一次，SSH 和 UDP 必然到同一台；
  命令里的 `-s` 让 mosh-server 只在 SSH_CONNECTION 的本地地址上收 UDP，二者对得上。这和官方 mosh 脚本默认的 `--experimental-remote-ip=proxy` 做法一致。
  另起一次 DNS 解析可能拿到另一个地址（多 A 记录、IPv4/IPv6），所以不用。
- **Mosh 标签用哪个终端引擎**：跟随「设置 → 外观与终端」，和 SSH 标签一样。连接层不认识引擎（R16），Mosh 是传输方式、引擎是显示方式，两维正交；
  强制 Ghostty 会让同一个 App 里两种标签输入法行为不一样。验收按目标引擎 Ghostty（flterm）做；xterm2 跑了 11 轮连开连关，能用。
- **Tailscale SSH 主机算不算 Direct**：路线判定只看路线（代理、跳板），不看登录方式。Tailscale SSH + 直连 = 手机经系统 VPN 直连 100.x，docs/04 定义的 Direct 就是这个，
  所以允许。**没测**：本机在真实 tailnet 上，手册第 3 节不许直连 100.x；Headscale 测试环境只经 SOCKS/跳板可达，恰好是 Mosh 不支持的路线。
- **插件选择**：只认 pluginId `xwshun.mosh`，且要申请了 `own-session-ephemeral-secret`、声明支持 system-default。别的插件哪怕也声明终端会话，临时 key 也不给。
- **重连入口**：没加「重新连接」按钮（终端页 R19 正在改，避免冲突）；结束提示里写「从保险库重新连接，会新起一个 mosh-server，不是原来那个会话」。

### 怎么连到测试环境（撞的墙）

SSH 和 UDP 必须发往同一个地址，所以 App 里的主机填 `10.0.2.2:22301`，不用 adb reverse（走 reverse 的话 SSH 连上的是 127.0.0.1，UDP 就发到模拟器自己身上）。
第一次跑，独立的监控 SSH 报 `Connection closed before authentication`，sshd 日志里根本没有这条连接。排查：在 Mac 上垫 TCP 中继、起一个 Python HTTP 服务，
经 10.0.2.2 一样收不到；**`adb shell svc wifi disable` 之后立刻正常**。原因是模拟器默认网络是虚拟 Wi-Fi，经它发往 10.0.2.2 的 TCP 收不到数据（UDP 是通的）；
关 Wi-Fi 后默认网络换成模拟器的蜂窝网卡就好。本机手册第 3 节原来把这归给 OrbStack，已改正。测完 `svc wifi enable` 开回来了。

### 强杀插件（kill）

会话开着时 `run-as top.xdwa.xwshun.mosh kill -9 <插件 pid>`：标签记 providerDied、`autoRestoreBlocked`，终端里提示「Mosh 插件进程没了…远端可能还有旧会话…pkill mosh-server 清掉」。

## 4. 安全

- 插件拿到的：数字 IP、UDP 端口、22 字节临时 key、句柄、代次、行列。拿不到 SSH 密码、私钥、代理口令、Tailscale 凭据、保险库（插件 API 本来就没有这些入口，X00/X02）。
- 远端只执行一条固定命令；端口范围是校验过的整数。没有安装、没有 sudo、没有重试。
- 路线不是直连，不拨任何连接、不启动远端、不碰插件，也不退回直连。
- 结束后输入绑定解除：之后的按键丢掉，不排队、不留给下一次连接。会话结束不自动重新 bootstrap（重连等于新起一个 mosh-server，冒充不了原会话）。

## 没做的、给 X10/X11 的话

- **X10**：后台存活（Android 12+ 会杀插件的子进程）、Wi-Fi/蜂窝切换、锁屏后回来——Mosh 最该派上用场的场景一次没测。真机没测。
- **在插件详情页点「连接测试」会断开 Mosh 插件正在跑的会话**（Kotlin 桥重新 connect 先断旧连接），会话记成 permissionRevoked，提示说「被停用、撤销、更新或断开」。
  手册里写了别这么做；要彻底改得让 `check` 复用已有连接，X10/X11 定。
- 插件进程被系统杀时，会话结束说明只有 providerDied 一种说法，分不出「系统回收」和「用户强杀」。
- 没有「重新连接」按钮：终端页 R19 正在改，这次没动。结束提示里说了从保险库重连。
- Tailscale SSH 登录方式 + 直连的 Mosh：逻辑上允许，没测（见设计取舍）。IPv6 目标没测（`authority` 会加方括号，插件只认数字地址）。
- 批准只绑能力不绑权限（X08 已记，X11）。
- 模拟器测试要关 Wi-Fi 才能经 10.0.2.2 连 TCP（本机手册第 3、7 节）；真机上没有这回事。
