## 做了什么

- **冻结口径**：RustDesk 没有第三方接入文档，只能照源码。tag `1.4.9`（提交 `6c578292`）的清单、`common.dart`、`hbb_common` 的 ID 规则存到仓库外 `../.toolchain/artifacts/`，逐条写进 docs/17「X07 固定的 RustDesk 口径」。逐个 tag 对比出计划里没有的两件事：1.2.3 及更早不接链接；改密码、改服务器的链接到 1.4.7 才设防（计划原文以为一直有开关，docs/13 已更正）。
- **证书**：GitHub 发行版 1.4.9 APK（sha256 和发行页 API 的 digest 一致）读出 `e92d44ba…72bfc86`，1.2.7 的也是这张；F-Droid 的两个 1.4.9 构建是 F-Droid 自己的 `85366b10…9660fa48`。两张都固定进 `RustDeskProtocol.knownSigners`，只对官方包名 `com.carriez.flutter_hbb` 算数。
- **只拼一种链接**（`lib/infrastructure/plugins/rustdesk_external.dart`）：`rustdesk://connect/<ID>`。ID 只收纯数字或字母开头的 6–16 位自定义 ID，类型上只能经 `RustDeskPeerId.parse` 得到；带服务器、密钥、`/r`、IP、整条链接、控制字符的一律拒收并说出是哪一类。不用 `rustdesk://<ID>`：ID 在主机名位置会被转小写，恰好叫 config、password 的 ID 会被 RustDesk 当成命令。
- **发给谁**：官方包名 + 已知证书直接可用；别的证书、别的包名都要用户看过包名和证书后明确信任（同一时刻只信任一个包），之后换签就停。别的包声明了 `rustdesk://` 只列出，不因为「只有它能打开」就拿到请求。
- **状态机**（`lib/application/rustdesk.dart`）：填 ID 只保存；只有点「用 RustDesk 远控」才发；每次发之前重新探测；发出去只记 `launchedUnverified`（「已交给」）和交给了哪个包哪个版本，没有任何会让它变成已连接、已断开的东西。SSH 经代理/跳板的主机，不确认「RustDesk 走自己的网络」就不发（复用插件契约 `checkRoute`）。关联存在 RustDesk 这边自己的加密存储，不进保险库。
- **Android**（`RustDeskBridge.kt`）：查谁声明了 `rustdesk://` 及各自的版本、证书；发送用显式包名 + `FLAG_ACTIVITY_NEW_TASK`，发之前平台层再按同一条正则核链接、按系统读出的证书核一次。`<queries>` 多三条（scheme、带 host 的 scheme、官方包名）。
- **界面**：主机详情加「RustDesk」→ 每台主机的 RustDesk 页；设置「远程桌面」一节加 RustDesk 总览。
- **设备关联**：`deviceLinksOf` 多收一种引用 `rustDeskPeerRef(关联 ID)`，引用用本 App 起的 ID，不用 RustDesk ID（两台主机可以填同一个 ID，仍是两条引用）。
- **落点**：计划写 `infrastructure/plugins/rustdesk_external`（照做）；状态机在 application 层，理由同 X05、X06。为此先把 UU 和 RustDesk 都要用的主机视图、路线判断、加密存储后端挪到 `lib/application/external_remote.dart`，UU 的存储名不变。

## 过程中发现并修掉的

- **用户自己信任的客户端也写「按源码核对过」**（f914bc2）：模拟器上看到的。自己编译的客户端只是版本号对得上，链接处理改没改过不知道，不该替它作保。
- **换签后两个按钮没对齐**（同上）。
- **测试漏了一条规则**（086bfe1）：见上面改坏检查。
- **集成测试会覆盖 `app-debug.apk` 并在结束时卸掉 App**：之后直接装那个文件，App 一打开就无响应。写进了本机手册「撞墙时」。
