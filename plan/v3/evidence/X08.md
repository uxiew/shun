## 结论先说

- **选了官方 mosh-client 1.4.0（native），不用 dart_mosh 0.0.4。** 理由和对比表在 `docs/decisions/mosh-runtime-decision.md`，这里只放证据。
- 运行时从核对过 SHA256 的源码交叉编译（mosh 1.4.0、protobuf 21.12、OpenSSL 3.5.4、ncurses 6.5，全部静态链接），
  随独立插件 APK `top.xdwa.xwshun.mosh` 安装，每个会话一个子进程，经 PTY 接宿主的 socketpair。
  可执行文件只来自 APK 安装时系统解出的 nativeLibraryDir（只读）；宿主从不执行它；不拷到 files/cache 再 exec。
- 会话 key 经 Binder byte[] → JNI 写进管道 → 子进程 fd 3（补丁 0002），不进命令行参数，不进环境变量。

## 1. Dart 候选：dart_mosh 0.0.4 对真 mosh-server

来源核对：pub.dev 归档 `dart_mosh-0.0.4.tar.gz` sha256 `3301f3c6537e265bc70cc703105657a401088fd405cbc9776b12da3a2124a52d`；
Apache-2.0；README/NOTICE 自称 clean-room、不含上游代码；唯一依赖 pointycastle ^4.0.0；四个版本都发在 2026-06-05 至 06-22。
API 照源码用（`MoshServerConfig.parse`、`MoshSession.connect/send/resize/close`、`MoshPacketCipher.aesOcb`），没有臆造。

探针 `tool/mosh-fixture/dart_probe`（23 条，本机真连容器里的 mosh-server）。屏幕比较的「对照」是**容器里官方 mosh-client 在 tmux 里画出的屏幕**
（`tmux capture-pane`），两边都画成文字逐行比：

| 检查 | 结果 |
|---|---|
| 大量滚动（seq 1 3000）、中文宽字符与组合字符与 emoji、光标定位与清屏、备用屏与滚动区、颜色与折行、200x60 满屏彩色（多分片）、改尺寸后输出、vim 开文件/删行/保存退出 | 8 条全部逐字等于官方客户端 |

| 篡改服务器的包（每 3 个改 1 个字节） | 报认证失败、丢掉，命令照常执行 |
| 把收到过的服务器包全部重放 | 屏幕不变 |
| **反射：把客户端自己发出的包弹回客户端** | **缺陷**：之后输入的 `echo lost-$((6*7))` 服务器连 `echo lost-` 都没收到；对照组（同样断开输入方向再恢复、不反射）照常出 `lost-42`。原因（读源码）：不查 nonce 方向位，反射包里的确认号被当成服务器对输入的确认，待发队列被删，之后的状态号和服务器对不上 |
| 远端程序退出 | `done` 完成，1 秒内 mosh-server 退出 |
| **客户端 `close()`** | **不通知服务器**：5 秒后远端 mosh-server（连同 shell）还在 |
| bootstrap 解析 | 解析失败的异常里带着整段 bootstrap 输出（里面可能有 key）；结果对象保留原文 `rawOutput` |
| 连着时 seq 1 200000 | 约 3.2 秒到最终画面，只收到约 700 字节（mosh 跳帧，不逐行） |

容器里的官方 mosh-client 经 `host.docker.internal` 连 Mac 上的中继，中继再转给 mosh-server，跑和 Dart 候选一样的故障：

| 检查 | 结果 |
|---|---|
| 反射（和上面完全同样的做法） | 反射包被丢掉（源码 `src/network/network.cc:513` 的 `dos_assert` 查方向位），`lost-42` 照常送达；对照组也通过 |

## 4. 设备（模拟器）

模拟器 `xwshun-a35-4k`（arm64、Android 15 / API 35、4 KiB 页），2026-10-06 21:05–21:16 持锁使用（锁在 R18、R21 手里时等着没抢）。
宿主是本 worktree 的 debug 构建（`integration_test/mosh_runtime_test.dart`，每次重装）；插件是上面那个 release APK。
SSH bootstrap 走 `adb reverse tcp:22301`。

### 设备上的 UDP 通路

模拟器直接往 `10.0.2.2:<mosh 端口>` 发 UDP 就能到 Mac 上 OrbStack 转发的容器端口，回包也回得来——**和 TCP 不一样**
（handbook 第 3 节：TCP 经 `10.0.2.2` 连 OrbStack 转发的端口能建连但收不到数据）。adb reverse 只管 TCP，用不上。
先用 `adb shell -tt` 直接跑解出来的运行时验证过（shell 的 PTY 是 0x0，要先 `stty rows 24 cols 80`，不然 mosh-client
断言 `s_height > 0` 退出），再走插件。所以 `x08_config.py` 默认 `udpHost=10.0.2.2`。

## 5. 安全：key、bootstrap（MOS08）

### bootstrap 解析（宿主侧，`lib/domain/plugins/mosh_bootstrap.dart`）

命令是固定串，只有校验过的端口范围是参数：`mosh-server new -s -c 256 -l LANG=en_US.UTF-8 -p 60001:60999`。
解析按字节做（Dart 字符串清不掉，key 不进字符串）。`test/mosh_bootstrap_test.dart` 14 条：

| 输入 | 结果 |
|---|---|
| mosh-server 1.4.0 原样输出（CRLF、版权行、detached 行；样本取自测试环境，key 换成假的） | 正确取出端口和 key |
| motd、非 UTF-8 字节、NUL、ANSI 颜色夹在前面 | 照常认出那一行 |
| 两条都像真的 | 失败（ambiguous），不取第一条 |
| 同一行夹东西：前缀 `echo `、后缀 `; rm -rf ~`、行中 `\r` 覆盖、制表符、两个空格、行首空格、行尾 NUL | 失败（malformed） |
| 端口 0、前导 0、6 位、>65535、非数字、空；不在请求范围 | malformed / portOutOfRange |
| key 21/23 位、带 `=`、`-_`、非 ASCII；非规范 base64（最后一位低 4 位不为 0） | malformed / badKey |
| 64 KiB + 1 字节 | 直接拒绝，不逐行扫；恰好 64 KiB 且连接行在最后照常解析 |
| glibc 上 locale 不支持的原话 | localeUnsupported（明确说要在服务器上生成 UTF-8 locale）。**Alpine/musl 上 LC_ALL=C 也给 UTF-8，测试环境里造不出这种输出**，所以样本是 mosh 1.4.0 源码里的原话，不是实测输出 |
| sh / bash / zsh 的「找不到 mosh-server」 | serverMissing |
| 所有失败 | 错误信息只说类别，不含原始输出、不含 key；`toString()` 不打印 key；`wipe()` 后字节全 0 |

变异验证（改坏一处、跑测试、改回）：

| 改坏的地方 | 挂的测试 |
|---|---|
| 不拒绝多条连接行 | 两条都像真的；错误信息不带 key |
| 把 `\r` 也当行尾（行中覆盖伪装就能混进来） | 同一行夹了别的东西 |
| 不查规范 base64 | key 那一条 |
| 不查端口范围 | 端口那一条；错误信息不带 key |
| 不限输出大小 | 超长输出 |
| 不认 locale 失败 | locale 那一条 |
| 宿主不查插件的临时密钥权限 | 没申请权限：不发给插件 |
| 交完不清宿主这边的 key | 申请了权限：交完清零 |

### key 从宿主到 mosh-client 的路径

1. 宿主经 App 自己的 SSH（已核对主机指纹）执行 bootstrap，按字节解析出 key（22 个 ASCII 字节）。
2. `PluginSessionManager.open(mosh: …)`：插件描述符没申请 `own-session-ephemeral-secret` 就不发；无论成败，返回前清掉宿主这边的字节。
3. 平台通道 → Kotlin `PluginBridge`：调完 `openMoshSession`（不管成败）把 ByteArray 清零。**平台通道和 Binder 自己的缓冲清不到。**
4. 插件 `openMoshSession` 逐事务核对调用方 UID + 证书（CallerVerifier），校验数字 IP、端口、尺寸、key 长度；不合格清零拒绝。
5. JNI：fork 之前把 key 写进管道、关写端、清缓冲；子进程把读端放到 fd 3、其余 fd 全关（不把插件的 socket、Binder 漏给子进程），
   exec `nativeLibraryDir/libmoshclient.so`，环境只有 `TERM`、`LANG`、`PATH`、`MOSH_KEY_FD=3`。
6. mosh-client（补丁 0002）从 fd 3 读正好 22 个字符、关掉，清掉临时缓冲。

不经过的地方：命令行参数（`ps` 可见）、环境变量（`/proc/<pid>/environ` 在会话期间一直可读——官方 `MOSH_KEY` 的问题）、文件、日志。
剩下的：mosh-client 进程内存里有 key（它要用）；第 3 步的平台缓冲。设备上的核对（参数、环境、日志、插件私有目录里找不到 key）见第 4 节。

## 6. 宿主侧顺带改的

- AIDL 末尾追加 `openMoshSession`（v1.0 未发布，照 X03 先例不升 minor）；echo 收到就清零拒绝，rogue 把它加进冒充宿主的探测。
- **宿主会被一个插件弄崩（已修）**：`PluginBridge.callPlugin` 原来只接 SecurityException / IllegalState / IllegalArgument / RemoteException。
  Binder 会把插件抛的 UnsupportedOperationException、NullPointerException 等原样带回来。模拟器实测：echo 拒绝 `openMoshSession`
  （抛 UnsupportedOperationException），宿主 `FATAL EXCEPTION: pool-6-thread-1` 整个退出。补了 `RuntimeException` 一档后同一场景如实报
  「插件出错：UnsupportedOperationException echo 不提供 Mosh 会话」，宿主照常；Dart 层因为 echo 没申请临时密钥权限根本不发（`echo-mosh.dartGate=refused`）。
  这个洞在 X03 起就有（任何插件方法抛这类异常都会这样），不只是 Mosh。
