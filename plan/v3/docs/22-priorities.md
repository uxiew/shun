## 先说结论

2. **所有者拿 31 包跑 R26 清单。**

## 第五档：已知缺口，影响小

都写在 STATUS「已知缺口」。不主动做，日用撞到就升档。

- **上游的问题**：组合字符缺重音、ANSI 模式 DECRQM 不回。改要动 fork 的引擎，规模中，影响很小。
- **输入法**：中文输入法拦截硬件键盘的 Esc、方向键。要看所有者用不用外接键盘，不用就不做。
- **连接生命周期**：通知在静音区默认折叠、冷启动不进终端页。R70 之后从任何页都能一步回到会话，冷启动这条价值变小。
- **旧 JSON 经 29 包转换的路**：30 包上回不去 29，走不了，手册写了。不做。
- **失败提示**：拨不通的人话按英文原文匹配，系统语言变了可能退回原文。规模小。
- **设置里「建过的终端：N」把失败的也算上**：发布检查脚本靠这句原文，发版时一起改。

## 第五批第 3 问：App 被杀后还能接上吗

现状（`docs/user/README.md` 第 7 节，代码 `session_controller.dart` 的 `_persistTabs`、`_restoreTabs`）：

| 标签类型 | 重开 App 后 | 接得上原会话吗 |
|---|---|---|
| 普通 SSH | 标签放回来，写「上次 App 被结束了」，点「重新连接」 | **接不上**：shell 是 SSH 连接的子进程，连接一断服务器就结束它，连回去是新 shell |
| tmux 标签 | 同上 | **接得上**：先核对还是不是原来那个会话，是才附着 |
| Mosh | 同上 | **接不上**：会话密钥只在内存，mosh-server 留在服务器上最多 7 天但没人连得回去；Mosh + tmux 接得上 |
| AI 工具 | 标签不放回，首页「最近工作」卡片 | 在 tmux 里的核对后返回；已退出的按会话 ID 继续 |

两件事分清楚：

- **从最近任务划掉不算杀**：有会话时前台服务还在，会话照跑，点通知回来。29 包上 10-31 12:11 系统确实因内存不够杀过一次（`LOW_MEMORY`），这种才会走上面这张表。
- **上次的画面不保留**：放回来的标签是空的，只记主机、tmux 目标和 SSH / Mosh。

真要「杀了也接得上」，只能让程序跑在服务器的 tmux 里，协议层没有别的办法。所以 R71 做成按主机的开关。开了就连接时进 tmux，默认关，不替用户在服务器上建东西。
