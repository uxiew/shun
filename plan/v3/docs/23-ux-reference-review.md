# 23 交互复盘：对照 TermRover、LobiShell，新建连接和 Tailscale 怎么改

所有者 11-01 反馈（F39）：新建连接的布局、Tailscale 的设置方式，还有一些别的功能「怪怪的」，要参考这两个 App 学交互和功能，先记录分析、再拆任务。任务详情在 [docs/08](08-implementation-tasks.md) 的 R72–R80，用例 UXR01–UXR08 都是 NOT_RUN。新建连接已按下面「所有者指认」改了（[R73](../evidence/R73.md)），其余还是计划。

## 结论

- **怪的根子是我们把内部概念摆到了用户面前**：「来源」「导入」「批量导入」「连接类型」，用户要先弄懂这些才能连上一台机器。TermRover 没有这些词：填 key，机器就出现在主机列表里。
- **改三件事，收益最大：** 新建连接去掉中转页、核心三项放最上面（R73）；Tailscale 设置常用项减到两个（R75）；Tailscale 设备直接算主机，去掉「导入」这个概念（R76）。
- **R72 手机走查又成了必须做的：** 所有者 11-02 说只看字符串学错了，管理页尤其「莫名其妙」，要实际打开两个 App 操作。详见下节。

## 新建连接

**改之前（截图 `r70-device-20261101-192555/20-editor-new.png`，现状见上一节）：** 点 ⊕ → 整页「选择连接类型」→ 整页表单。首屏依次是名称、主机名、端口、分组、标签、置顶、认证方式、用户名，共 8 项；密码被底部栏压住，要往下滚。

| 问题 | 为什么怪 | 参考 App 怎么做 | 依据 |
|---|---|---|---|
| 每次都先过一页选类型 | 绝大多数时候就是 SSH，这一页是白点 | TermRover 的 SSH、Mosh 是编辑页里的一个选择，记录和字符串里都没看到类型页（待 R72 确认）。LobiShell 有类型选择，但它有 8 种类型，我们最常用的就 SSH、Mosh | 10-10 记录、字符串 |
| 名称排第一 | 真正要填的是地址和账号，名称只是备注 | TermRover 有「名称可选」这个提示，是不是这个表单待 R72 确认 | 字符串 |
| 分组、标签、置顶排在认证前面 | 这是整理用的，第一次连根本不关心，却占了 3 行 | 待 R72 确认位置 | — |
| 用凭据要先离开去建 | 选凭据时没有就卡住 | LobiShell 在选择框里就能新建，也能选「手动填」，还写着这个身份被几个连接用 | 字符串 |
| 只有「保存」 | 新建主机的目的是连上，还得回列表再点一次 | 待 R72 确认 | — |

**改法（R73、R74）：** 点 ⊕ 直接进表单，所有类型都在顶上「连接类型」里切；分组、标签、置顶、连接路径都进「高级」。

> 这推翻了 R39「新建连接先选类型」。旧类型页的内容都留着，挪进了「连接类型」面板，不再挡在路上。

## Tailscale

**现在（手册第 13 节）：** 点 ⊕ → 类型页 → 「批量导入」下的 Tailscale → 设置页。设置页除 API key、默认登录外，「高级」里还有端口、地址种类、连接路径、分组、tailnet、名称 6 项。设备要「导入」才成主机，入口有 5 个：点一台、全部导入、只导入、关联到已有主机、用自定义设置导入。

**TermRover（`termrover01.jpg`）：** 主机列表上弹一个底部面板，只有 API key、SSH 用户名，再加一个折叠的 Tailnet，底部是移除 key、取消、保存。机器直接出现在主机列表里，带在线状态，不要的可以隐藏。

| 问题 | 为什么怪 | 改法 | 任务 |
|---|---|---|---|
| 入口藏在「批量导入」下 | 用户想的是「连 Tailscale」，不是「批量导入」 | 新建入口和空状态都给「连接 Tailscale」 | R73、R78 |
| 设置项太多 | 只想看到机器，却要面对路径、端口 | 常用两项，其余收进一个折叠区 | R75 |
| 「来源」「名称」「tailnet: -」 | 这是我们的数据结构，用户没有这个概念 | 只有一个 tailnet 时不出现这些词 | R75 |
| 「导入」和 5 个入口 | 设备明明列出来了，为什么还要导入 | 设备就是主机行，点了就连；不想看的隐藏 | R76 |
| 连不上时用户不知道怎么办 | 服务器没开 Tailscale SSH、要到浏览器认证，都是常见情况 | 报错直接给修法：要运行的命令、改用密码、打开认证页 | R77 |

**不照搬的地方：** TermRover 没有代理，我们的用户要走 TailSocks 和公司代理（R06、R07），所以连接路径留着，只是折叠。

## 其他「怪」的地方

所有者没点名是哪些，下面是我对照后的判断，R72 走查时请所有者指认、补充。

| 地方 | 现在 | 参考 App | 任务 |
|---|---|---|---|
| 连接页的空状态 | 一句「还没有终端连接」和一个「添加连接」 | TermRover 明确告诉你两条路：加主机、连 Tailscale | R78 |
| 凭据、代理、转发散在设置各处 | 设置是一长串，混着主题、凭据、备份、插件 | LobiShell 有一个「管理」页，连接、转发、身份三个 tab 共用一个搜索 | R79 |
| 设置分组 | 都在一页 | LobiShell 分为通用、终端外观、终端行为、首页、安全、备份。只学分组，不学它每项一大段说明（违反 F30） | R79 |
| tmux 的日常操作 | 没有快捷按钮，靠前缀键 | TermRover 有快捷行、可加星的会话选择器；鼠标模式没开时一键打开 | R80（DEFERRED） |

**不学：** TermRover 的付费墙、Agent Fleet、语音通话（和这次的「怪」无关，工程量大）；LobiShell 按新手、老手分流的引导（先把界面改到不用教）。

## 替所有者定的（不同意就说）

1. **类型页改成表单里的面板**，理由见上。R39 的 RustDesk、UU、Tailscale、插件入口都在面板里。
2. **Tailscale 默认登录不改成免密**：继续按 F31 的「用户名密码或凭据」。TermRover 从字符串看默认是免密，但我们的 Tailscale SSH 没在真实 Tailscale 上走过（CRD04 NOT_RUN），没跑通不当默认。
3. **旧数据不迁移、不丢**：已导入的主机、已有来源的设置照常生效，只改界面。
