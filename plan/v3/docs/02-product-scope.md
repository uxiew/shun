# 02 产品范围与交互

## 产品定义

一个不占用系统VPN的Flutter移动SSH工作终端：复用已有网络入口，快速选中Tailnet设备，使用Ghostty驱动的终端操作远端原有CLI、tmux与文件。

Android是本批验收平台。保留基座已有其他平台结构，不宣称同时完成iOS；不新增WebSocket云中转，不做AI聊天客户端，不建立账号系统，不自动在主机安装专有agent。

## 进入主机的三种路线

| 路由模式 | 必填 | 显示 |
|---|---|---|
| Direct | 目标host/port | “系统网络（遵守当前VPN）” |
| Existing SOCKS5 | 代理profile + 目标 | “通过已有代理；由外部应用管理” |
| ProxyJump | 有序跳板列表 + 目标 | “逐跳SSH验证” |

首轮UI三选一；不要复制两枚彼此冲突的布尔开关。配置模型可表示“SOCKS入口→跳板→目标”，第一版在高级入口明确允许并单独测试；不支持的更复杂链路在保存与连接前拒绝，而不是猜优先级。

## Tailscale导入旅程

设置只读目录来源 → 刷新 → 搜索/选中设备 → 指定用户名、认证与共享route profile → 保存为普通主机 → 点击连接。默认用户名不是root；若无用户名要求用户填，不能从Tailscale账号邮箱推算Unix用户。

设备目录和手动主机共存。导入页默认优先展示适合服务器的设备但允许显示全部，不删除手机/Windows等设备。显示来源、IP/FQDN、刷新时间、可验证的最近状态；“目录可见”“刚刷新”“端口可达”“SSH认证成功”是不同状态。

本地缓存可离线浏览。删目录凭据只停止刷新，默认保留已导入主机并标为手动/已断开来源；批量删除须另确认。不能因一次401、网络异常或空列表自动删主机或清除host trust。

## 新连接页面（行为规格，不是视觉仿制）

1. 基本：名称、分组/标签、SSH目标与端口。
2. 身份：Unix用户、复用身份、普通SSH/显式外部认证。
3. 连接路径：三选一，必要时展开“入口代理+跳板链”，实时显示链路摘要。
4. 终端与恢复：实际引擎、字体/主题、tmux偏好。
5. 高级：有限超时、keepalive、显式Fresh启动命令，默认关闭。

保存校验不主动连生产机器。“测试连接”区分代理协商、逐跳SSH、最终PTY；发现异常host key先确认，不能用测试入口绕过。

不照搬截图中的sudo密码自动输入、agent forwarding、Port Knocking、NFC、Wake webhook、WOL和自动VPN切换。它们不是本次必要能力。快捷命令默认先进入编辑区；需要执行时用户明确发送。

## 保留与收缩

保留基座的主机/密钥/主题/SFTP/多标签成熟路径并回归；不重新开发一套相同功能。Mosh改为X08–X10的独立APK插件主线；未安装/未授权或当前路由不支持时说明原因。Telnet若未通过route矩阵，不进入默认菜单。已有配置显示具体不支持而非暗中改成Direct。远端管理和AI功能不要成为本次改造主线。

## 成功标准

同一Android候选：保留现有VPN；TailSocks→SSH成功；可从目录导入；ProxyJump及外部远程SOCKS符合路径策略；Ghostty中文/TUI通过；切网络与锁屏后状态真实；恢复不重发；旧有SFTP不绕路；主机指纹变化阻断。全部仍为待执行验收。

## V3插件成功标准

最终范围必须有实际可安装/停用的Mosh提供方、设备能力入口、插件管理及签名/版本/崩溃边界，不仅是抽象接口。用户可在同一设备卡片选择SSH或已有远控绑定；UI说明内嵌与外部App差异。UU目前协议只覆盖Windows/macOS，Linux不能伪造支持。无插件仍可使用已验证SSH核心。

首版不做：插件商城、脚本热更新、任意下载native代码、手机被控端、自动登录UU/RustDesk、远控密码放URL、自动安装mosh-server。
