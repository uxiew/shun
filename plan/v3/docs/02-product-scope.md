# 02 产品范围与交互

## 产品定义

一个不占用系统VPN的Flutter移动SSH工作终端：复用已有网络入口，快速选中Tailnet设备，使用Ghostty驱动的终端操作远端原有CLI、tmux与文件。

Android是本批验收平台。保留基座已有其他平台结构，不宣称同时完成iOS；不新增WebSocket云中转，不做AI聊天客户端，不建立账号系统，不自动在主机安装专有agent。

## 进入主机的三种路线

| 路由模式 | 必填 | 显示 |
|---|---|---|
| Direct | 目标host/port | “系统网络（遵守当前VPN）” |
| Existing SOCKS5 | 代理profile + 目标 | “通过已有代理；由外部应用管理” |
| ProxyJump | 有序跳板列表 + 目标 | “逐跳SSH验证” |

首轮UI三选一；不要复制两枚彼此冲突的布尔开关。配置模型可表示“SOCKS入口→跳板→目标”，第一版在高级入口明确允许并单独测试；不支持的更复杂链路在保存与连接前拒绝，而不是猜优先级。

## Tailscale导入旅程

设置只读目录来源 → 刷新 → 搜索/选中设备 → 指定用户名、认证与共享route profile → 保存为普通主机 → 点击连接。默认用户名不是root；若无用户名要求用户填，不能从Tailscale账号邮箱推算Unix用户。

设备目录和手动主机共存。导入页默认优先展示适合服务器的设备但允许显示全部，不删除手机/Windows等设备。显示来源、IP/FQDN、刷新时间、可验证的最近状态；“目录可见”“刚刷新”“端口可达”“SSH认证成功”是不同状态。

本地缓存可离线浏览。删目录凭据只停止刷新，默认保留已导入主机并标为手动/已断开来源；批量删除须另确认。不能因一次401、网络异常或空列表自动删主机或清除host trust。

## 新连接页面（行为规格，不是视觉仿制）

1. 基本：名称、分组/标签、SSH目标与端口。
2. 身份：Unix用户、复用身份、普通SSH/显式外部认证。
3. 连接路径：三选一，必要时展开“入口代理+跳板链”，实时显示链路摘要。
4. 终端与恢复：实际引擎、字体/主题、tmux偏好。
5. 高级：有限超时、keepalive、显式Fresh启动命令，默认关闭。

保存校验不主动连生产机器。“测试连接”区分代理协商、逐跳SSH、最终PTY；发现异常host key先确认，不能用测试入口绕过。

不照搬截图中的sudo密码自动输入、agent forwarding、Port Knocking、NFC、Wake webhook、WOL和自动VPN切换。它们不是本次必要能力。快捷命令默认先进入编辑区；需要执行时用户明确发送。

## 保留与收缩

保留基座的主机/密钥/主题/SFTP/多标签成熟路径并回归；不重新开发一套相同功能。Mosh改为X08–X10的独立APK插件主线；未安装/未授权或当前路由不支持时说明原因。Telnet若未通过route矩阵，不进入默认菜单。已有配置显示具体不支持而非暗中改成Direct。继承的 AI 聊天、云同步及自动管理仍默认关闭；2026-10-11 所有者明确新增的远端 AI CLI 发现、启动和继续会话进入 R55–R57 主线，范围见下。

## AI CLI 快速启动与继续上次工作

2026-10-11 所有者明确要求：识别远端已经安装的 Claude Code、Codex 及其他命令行 AI 工具，快速启动，再次打开 shun 时快速回到最后一次工作的会话。R55–R57 为 P4 主线；R55 工具发现于 2026-10-12 完成本机隔离验证，R56/R57 尚未开始。这是 SSH 终端功能，不需要先完成 R54 的协议级工作区，也不接管远端工具的账号、模型或权限设置。

### 用户操作

1. 主机菜单增加「AI 工具」。连接并验证该主机后，按该主机设置检测工具；可刷新、补充工具路径或自定义启动项。只打开主机列表不连接、不扫描所有服务器。
2. 工具卡显示名称、可执行位置、已知版本和支持的动作；「已发现」不代表已登录或能调用模型。选好项目目录后点「新建会话」，以后可复用这个启动项。
3. 有 tmux 时推荐「保留远端会话」：这个明确的新建动作创建专属目标并启动工具。没有 tmux 时可启动普通终端，说明连接断开可能结束进程；不代装 tmux。
4. 首页和主机内显示「继续上次」卡片：主机、工具、项目目录、最近打开时间、当前可确认的状态。点击后核对工作项与运行关联，优先返回原来的终端或仍存在的 tmux；不需要再挑主机、输入目录和命令。
5. 若原进程已退出，能确认原生会话 ID 时提供「继续这段对话」；不能确认时给「选择历史会话」或「新建」。缺失、离线与权限失效如实显示，不跳到另一段“最近对话”。也能查看该主机/项目的其他最近会话，而非只有一条全局记录。

进程被终止后冷启动只恢复入口和显示状态；存活进程回前台时，原有传输层恢复继续遵守 R22/R23，两种情况都不把历史命令再执行一遍。用户点「新建」「继续」即是对应动作，不再叠加通用确认弹窗；主机指纹变化、身份变化和缺失目标仍按原有规则处理。

### 工具发现的范围

首批内置 Claude Code（`claude`）、Codex（`codex`）、Gemini CLI（`gemini`）、OpenCode（`opencode`）识别规则。规则表可随 App 更新扩充；自定义工具用明确的可执行路径和参数接入。自动发现覆盖已登记名称、当前远端用户的 PATH、已声明的常见安装位置和用户补充位置；不递归扫描整个磁盘或运行目录中每个程序来猜工具。

「所有已存在」落实为展示扫描范围并允许补全，而不是宣称能枚举任何未来工具、任意别名、shell 函数、容器内部或其他用户的安装。未命中显示「此范围未发现」，保留手动入口。非交互与交互 PATH 不同、版本管理器、shell alias/function、多个同名安装需要分别显示；不自动 source 用户 rc 或执行未知包装脚本来扩展探测。

探测复用已验证的目标 SSH client/RoutePlan，采用有截止、有输出上限的独立只读通道；不能把 `command -v`、`cd`、`--version` 打到正在运行的 Claude、vim 或 shell 提示行。版本/能力检查只调用经过版本规则审核的已知无模型请求命令；自定义工具默认只查路径，任何不能确认无副作用的探测省略。安装、登录、升级、模型调用不属于检测；凭据与环境变量值不读回手机。

### 启动和恢复必须分开

| 当前情况 | 「继续上次」的动作 | 不能替代它的行为 |
|---|---|---|
| 本地原标签仍绑定原工作项、连接代次和运行关联 | 聚焦原标签；只能确认终端存活时标「返回终端 / 工具状态未知」，CLI 已退出则转显式原生继续 | 把 SSH 连接存活当 AI 还在运行，或把命令粘进现有 AI 输入框 |
| SSH 已断，完整 tmux 目标仍可验证 | 按 R21 的 host/user/socket/server/session 身份重新附着 | 按名字匹配或用新会话顶替旧会话 |
| tmux 存在但工具已经退出 | 展示已结束或未知；有已绑定原生 ID 才显式继续对话 | 看到 tmux 还在就称 AI 还在运行 |
| 原进程结束，原生会话 ID 和项目已确认 | 用户点击后在原项目启动工具的指定 ID 恢复方式 | 自动使用全局 `--last` / `--continue` 猜目标 |
| 未获得原生 ID、目标已删、版本能力未知 | 提供工具自己的历史选择器或新建入口，说明限制 | 自动降级成新会话并显示“恢复成功” |
| 发送启动后连接丢失，结果不明 | 标记结果未知；先核查此请求对应的目标，禁止自动重发 | 依靠自动重试制造重复进程/重复提示词 |

恢复记录按主机身份、远端用户、工具实例、项目实际路径/worktree 和可选配置身份隔离；记录稳定的工作项 ID、完整 tmux 目标、可选原生会话 ID、发现方式与最近成功打开时间。只点卡片但连接失败不能覆盖最后成功记录。主机修改、用户切换、工具路径/配置改变需重新核对；不把同名主机或目录当成原目标。

R21 现有 tmux 目标只到 session；同一 session 可以有多个 window/pane。启动器应创建专属目标，记录并核验 window/pane ID 与本次运行的关联；仅有 session、pane 名称或 PID 不足以证明原工具仍活着。用户拆分窗格、更换程序或在别处操作后，无法确认就显示未知并让用户选择，不向猜测的窗格发送命令。

恢复元数据进入独立本机加密存储并能清除，不保存对话正文、API token、终端输出或未提交提示词；默认不进普通导出、云同步、备份和诊断。进程重启遵守 R22 的解锁/凭据租期；无网络可看缓存卡片，但状态是待检查。手工从别处打开的会话须先显式选择/关联，不扫描所有用户的会话历史。

### 原生继续能力的官方依据

下面只是已核对的命令语义。实施时须冻结远端实际版本并验证参数、退出码与项目范围；`--help` 文字和网页不代替运行证据。

| 工具 | 官方提供的方式 | 本项目的采用条件 |
|---|---|---|
| Claude Code | `--resume <id>`；`--continue` 选择当前目录最近会话；新会话可指定 UUID `--session-id` | 优先绑定明确 ID。版本支持时新建可预分配 UUID，但必须确认启动成功；不以一次预分配记录证明已有历史。[S85](13-sources.md#s85) |
| Codex | `codex resume <id>`；`--last` 默认按当前目录筛选，`--all` 扩大范围 | 绑定原 ID 和原目录；不默认 `--all`。新会话 ID 的可靠获取须单独验证，不臆造指定新 ID 的 CLI 参数。[S86](13-sources.md#s86) |
| Gemini CLI | `--resume <UUID>` 和项目内 `--list-sessions` | 如采用列表，仅保留 ID/项目等必要元数据，屏蔽提示词预览；不使用可能变动的列表序号作为稳定标识。[S87](13-sources.md#s87) |
| OpenCode | `--session <id>`、`--continue` 与 `session list` | 按版本冻结列表解析和项目关联；不默认开启服务监听、分享或权限自动批准。[S88](13-sources.md#s88) |

原生 ID 只能来自已验证的版本适配、工具支持的显式 ID 或用户绑定；可选的历史元数据读取必须限定当前用户和选定项目、只读且有界，不修改工具的私有状态文件。拿不到可靠 ID 时，仍可依靠 tmux 回到活会话；不得为实现“继续”偷偷启用 R54 的服务端部署或把终端标题当作可信 ID。

首批 Claude/Codex 的启动、tmux 返回与指定原生 ID 继续分别验收；Gemini/OpenCode 和自定义工具按实际验证列出发现/启动/继续三级能力。不支持原生继续的工具仍可保留启动项和返回活 tmux 会话。

### 复用已有实现和验证边界

- 复用 R21 的受限 tmux 探测、显式创建/附着和完整目标；R22 的恢复记录只含原有 host/tmux 信息，需要版本化扩展。R23 的恢复不重放必须先通过。
- 现有 snippet 会把文本送进当前标签，`openManagedTerminal` 目前不持久化，也没有显式沿用父会话冻结路线；不能直接拿它们当启动器。新启动使用绑定目标/目录的专用终端或显式新建 tmux，参数经过统一转义，不拼接任意命令模板。
- 新建操作携带请求 ID 并绑定 connection generation；双击、超时、迟到返回、取消后重连不得自动执行第二次。只在用户明确新建时建 tmux；恢复、检测和打开 App 都不隐式创建或杀会话。
- Dokodemo 的 AI 三态只借鉴为「工具报告」提示。终端标题/输出不可信，必须有未知、过期和来源标识；不得触发批准、启动、目录切换或本地动作。手机后台没有新的可信事件就不能声称任务完成。
- R54 继续保留为 P6 的协议级工作区；R50 仍负责输入建议。R55 的固定工具探测不扩展 R50 的 shell-history/compgen 范围，R01 禁用的 AI 聊天入口也不因此重开。

验收 AIC01–AIC09 分开覆盖发现范围、探测边界、启动目录、重复请求、tmux 返回、原生恢复、冷启动、状态提示及真实工具。同版本 fixture 只能验证结构与故障；真实登录/模型工作需要对应授权和实测证据，不能用 R20 的未登录欢迎页结果冒充本功能通过。

## 成功标准

同一Android候选：保留现有VPN；TailSocks→SSH成功；可从目录导入；ProxyJump及外部远程SOCKS符合路径策略；Ghostty中文/TUI通过；切网络与锁屏后状态真实；恢复不重发；旧有SFTP不绕路；主机指纹变化阻断。新增 AI CLI 发现、启动、继续指定会话按 AIC01–AIC09 验收；当前执行结果以 docs/09 和 STATUS 为准。

## V3插件成功标准

最终范围必须有实际可安装/停用的Mosh提供方、设备能力入口、插件管理及签名/版本/崩溃边界，不仅是抽象接口。用户可在同一设备卡片选择SSH或已有远控绑定；UI说明内嵌与外部App差异。UU目前协议只覆盖Windows/macOS，Linux不能伪造支持。无插件仍可使用已验证SSH核心。

首版不做：插件商城、脚本热更新、任意下载native代码、手机被控端、自动登录UU/RustDesk、远控密码放URL、自动安装mosh-server。
