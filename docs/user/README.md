# xwshun 使用手册

写给用这个 App 的人。怎么构建、测试、装到手机，看 [本机手册](../xwshun/README.md)。

xwshun 是 Netcatty 手机版的实验改版，功能还是那三样：SSH 终端、SFTP 文件管理、服务器管理面板。改的主要是三块：

- **连接怎么走**：代理或跳板出问题一律报错、不会偷偷直连；服务器指纹变了一律拦下。
- **密码私钥怎么保管**：只存在系统安全存储里，导出的文件不带。
- **终端**：可选新引擎 Ghostty（实验），中文输入法、语音输入不再重复发送；tmux 面板按编号操作，不会误伤名字相近的会话。

> 现状（2026-10-06）：开发中，没有安装包。功能都在 Android 模拟器上验证过；真机只测过一台（Pixel 9 Pro），
> 测的是 Ghostty 终端里的中文输入（拼音、语音）。本手册只写已经做完的功能；没做完的列在 [第 18 节](#18-还没有的功能)。

**最快上手**

1. 装好 App。用过原版 Netcatty 的，先把原版的主机导进来（[第 1 节](#1-安装与搬数据)）。
2. 保险库页顶部点 ⊕，填主机名、用户名、密码或私钥，保存（[第 2 节](#2-添加服务器)）。
3. 在保险库里点这台主机，弹出的框里点「连接」。第一次连会让你核对服务器指纹，对上了点「接受并记住」（[第 5 节](#5-服务器指纹)）。
4. 要用中文输入法或语音输入的：先到「设置 → 外观与终端 → 终端引擎」选 Ghostty，再新开标签（[第 8 节](#8-终端引擎实验)）。
5. 连不上时，报错里写着是哪台机器、哪一步出的问题，对照 [第 6 节](#6-连接中连接失败) 查。

## 1. 安装与搬数据

- 要自己从源码构建再装，步骤见 [本机手册第 4 节](../xwshun/README.md#4-装到真机)。最低 Android 7.0，只给 64 位 ARM 手机（近几年的 Android 手机都是）。
- 包名是 `top.xdwa.xwshun`，和原版 Netcatty 能同时装在一台手机上，数据互不相通。
- **从原版搬主机过来**：原版里导出保险库 JSON → 这里「设置 → 数据管理 → 导入 Netcatty JSON」。
  原版导出的文件里有明文密码和私钥，导入完把那个文件删掉。导入前会弹框让你选合并还是替换，见 [第 12 节](#12-导出导入与凭据)。
- 这几样在这个版本里**默认关闭、界面上看不到**：AI 助手（Catty Agent）、云同步、检查更新。
  关着的时候它们不发任何网络请求。这是有意的，不是坏了。

## 2. 添加服务器

保险库页顶部的 ⊕（添加主机），打开「新建连接」。

1. **基本信息**：最上面选协议（SSH、Telnet、Mosh，Mosh 见 [第 17 节末尾](#用-mosh-连接)）；名称随便起；「主机名 / IP」和「用户名」必填；SSH 端口默认 22。
2. **连接路径**：默认直连，见 [第 3 节](#3-连接路径直连经代理经跳板机)。
3. **身份认证**：最上面先选「普通 SSH」还是「Tailscale SSH」（后者见 [第 14 节](#14-tailscale-ssh用-tailscale-身份登录)）。普通 SSH 的认证方式三选一：

   | 认证方式 | 怎么用 |
   |---|---|
   | 自动（私钥 / 密码 / 交互式） | 按 私钥 → 密码 → 交互式 的顺序试，没选私钥、没存密码的那一步跳过 |
   | 密码 | 用保存的密码登录 |
   | 私钥 | 必须选一把私钥。没有就点「管理私钥」导入，或者先在「设置 → SSH 密钥库」里导入 |

   服务器走交互式登录（问验证码、PIN，或者用这种方式问密码）时，App 弹「交互式认证」框让你自己填，不会自动把保存的密码填进去。
4. 右上角「保存」。路线配置有矛盾时保存不了，原因写在编辑器的红框里。

**高级选项**里能改：连接后执行命令、Keepalive 间隔（默认 10 秒）、连接超时（建 TCP 连接，默认 15 秒）、认证超时（默认 30 秒）。

私钥口令填错、私钥被删、私钥文件损坏，会在连接前直接报出来，不会先连上服务器再说「登录被拒绝」。

## 3. 连接路径：直连、经代理、经跳板机

编辑器里「连接路径」三选一：

| 选项 | 怎么走 | 什么时候用 |
|---|---|---|
| 直连 | 手机直接连服务器。你开着的 VPN 照常生效 | 手机能直接到达服务器 |
| 经代理 | 手机先连 HTTP 或 SOCKS5 代理，由代理去连服务器 | 服务器只能从某个代理后面访问 |
| 经跳板机 | 手机先 SSH 到跳板机，再由跳板机转发到服务器。最多 3 台，按连接顺序排 | 服务器在内网，只有跳板机能进去 |

- **跳板机要先作为一台普通主机存进保险库**，再在「添加跳板机」里选它。跳板机必须用 SSH。
- **先经代理、再走跳板**：选「经跳板机」，打开「先经代理连第一台跳板机（高级）」，在下面填代理。
  这个代理只用来连第一台跳板机，之后每一跳都由上一跳转发。
- **代理可以选已保存的，也可以当场填**「自定义 HTTP / SOCKS5 代理」。
  代理的用户名和密码是明文发给代理的——SSH 只加密之后的会话，保护不了这段口令。远程代理只在可信网络里用。
- **编辑器下方「连接时会这样走」**实时显示整条路线，连接时就按这条走，不会临时换路。大致长这样：

  ```
  手机
  SOCKS5 代理    10.0.0.5:1080（代理之后怎么走由代理决定，App 看不到）
  跳板机“hop1”   admin@10.0.1.2:22
  目标“web”      SSH deploy@10.0.2.9:22
  ```
- **Telnet 只能直连**：编辑器里选 Telnet 就没有代理和跳板选项，保存时会去掉原有的代理和跳板设置。
  从别处导入、带着代理或跳板的 Telnet 主机，连接时直接报错，不会改成直连。
- **Mosh 也只能直连**，但和 Telnet 不同：选了代理或跳板不会被悄悄去掉，而是不让保存，原因见 [用 Mosh 连接](#用-mosh-连接)。

**选了代理或跳板，失败就是失败，不会改成直连。** 下面这些配置保存不了，红框里会写原因：

| 红框里的原因（节选） | 怎么改 |
|---|---|
| 选了「经跳板机」，但还没有添加跳板机 | 加一台，或改回直连 |
| 跳板机“X”自己配置了代理，经它连接时不会隐式套用 | 把代理设在**目标主机**上（打开上面那个高级开关），跳板机上的代理去掉 |
| 跳板机“X”自己又配置了跳板机，不支持嵌套 | 在目标主机上按顺序列出全部跳板机 |
| 跳板机链路存在循环 / 路线里同一台机器出现了两次 | 检查跳板顺序，每台只出现一次 |
| 跳板机数量超过上限（最多 3 个） | 减到 3 台以内 |
| 地址、端口格式不对（空格、端口超出 1–65535、中文域名没转 `xn--` 写法等） | 按提示改。中文域名要填 Punycode 写法 |

两种情况只提醒、不拦：代理的地址端口和 SSH 服务一模一样，或者代理端口填了 22。多半是把 SSH 端口填到代理那一栏了。

## 4. 测试连接

编辑器底部「测试连接」：**按还没保存的配置**走一遍，不用先保存。

它会核对指纹、登录，然后只检查远端能不能分到终端，**不打开 shell、不执行启动命令**。成功时显示「登录成功，远端分配了终端：/dev/pts/3」这样的结果。
中途点「停止」，已经建好的连接会全部关掉。失败时显示卡在哪一跳、哪一步，以及下一步该查什么（见 [第 6 节](#6-连接中连接失败)）。
Mosh 主机没有这个按钮（只测得了 SSH 那一段）。

## 5. 服务器指纹

指纹是服务器的身份证。第一次连一台服务器（包括每台跳板机）会弹「确认服务器指纹」，显示地址、算法和一串 `SHA256:…`。

**核对方法**：让管理员（或者你自己在服务器控制台上）执行

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
# 弹框里的算法带 rsa 就换成 ssh_host_rsa_key.pub，带 ecdsa 就换成 ssh_host_ecdsa_key.pub
```

输出里的 `SHA256:…` 和弹框里一字不差，再点「接受并记住」。对不上就点「拒绝」。

**指纹变了**会弹「服务器指纹已变化，已阻止连接」，并且**没有「仍然连接」的按钮**。可能是服务器重装了，也可能是有人在冒充它。

1. 先向管理员确认新指纹。
2. 确认是正常更换，在弹框里点「删除旧指纹」。
3. 重新连接，按第一次连接那样重新核对。

## 6. 连接中、连接失败

连接等待页写着现在到哪一步，比如「第 2/3 跳，“hop2”：SSH 握手、核对指纹、登录」。
点「终止连接」，已经连上的那几段马上断开，不会在后台继续连完。

连接失败时，报错写明是哪台机器、哪一步，格式是「机器（地址）步骤：原因」，比如
「跳板机“hop2”（10.0.1.2:22）转发失败（到 10.0.2.9:22）：…」。下面跟一句建议，常见的几种：

| 建议开头 | 多半是 | 查什么 |
|---|---|---|
| 手机连不到这个地址 | 地址或端口填错，或当前网络（含 VPN）到不了 | SSH 端口和代理端口是两个端口，别填混 |
| 对方在登录完成前断开了 | 这个端口上跑的不是 SSH | 常见是把代理端口或别的服务端口填成了 SSH 端口 |
| 代理或跳板机已经回报连上了目标，随后在登录前断开 | 经代理或跳板机时：端口不是 SSH，或者代理、跳板机之后那一段断了 | 先确认 SSH 端口；再看代理或跳板机那边能不能连到目标（比如 TailSocks 还连着 tailnet 没有）。稍后重连能好的，多半是后者 |
| 服务器拒绝了登录 | 用户名、密码错，或者公钥没加到服务器 | 服务器上 `~/.ssh/authorized_keys` 里有没有这把公钥 |
| 跳板机拒绝转发 | 跳板机不允许转发，或它那边到不了下一跳 | 跳板机 sshd 的 `AllowTcpForwarding`；在跳板机上试试能不能连下一跳 |
| 检查代理的地址、端口、用户名和密码 | 代理地址、端口、账号错，或代理拒绝了 | 代理之后怎么走由代理决定，App 只看得到代理返回的结果 |
| 服务器指纹没通过核对 | 你点了拒绝，或指纹变了 | 见 [第 5 节](#5-服务器指纹)。此时还没发送任何登录信息 |
| 到主机编辑器重新选择私钥 | 私钥口令错、私钥被删或损坏 | 在编辑器重新选私钥，或在「设置 → SSH 密钥库」补上正确口令 |
| 路线配置有问题 | 导入或同步来的主机路线有矛盾 | 打开这台主机的编辑器，红框里写着原因 |
| 到 Tailscale 后台检查访问策略里的 ssh 规则 | Tailscale SSH 不让你登录，或 check 被拒、过期 | 见 [第 14 节](#14-tailscale-ssh用-tailscale-身份登录) |
| （报错是）服务器没要任何密码或私钥就让登录了 | 普通 SSH 连上了一台不要凭据就放行的服务器，多半是 Tailscale SSH | 是 Tailscale SSH 就把登录方式改成「Tailscale SSH」 |
| （报错是）服务器要求另外到浏览器里认证 | 普通 SSH 碰上了 Tailscale 的 check | 同上 |

## 7. 断线与自动恢复

- 网络断了，终端里会出现黄色的「连接已断开，正在后台自动恢复…」，恢复后接着用。
- 自动恢复**沿用这个标签原来的路线和账号**。断线期间改了主机、跳板或代理，要关掉这个标签重新连才生效。
- 恢复时**不会再执行一遍**「连接后执行命令」。
- 恢复后服务器那边的窗口大小和屏幕一致。以前恢复后会停在 80 列 × 24 行，要转一下屏幕才对，期间 vim、htop、tmux 排版是乱的。
- Tailscale SSH 的主机恢复时，Tailscale 要是又要求 check，自动恢复就停下，不替你打开链接，终端里写明原因；这个标签之后也不再自动重试。关掉它，从主机列表重新连。
- tmux 标签（面板里附着出来的）恢复时只重新附着原来那个会话，会话不在了就停下，见 [第 10 节](#10-tmux)。
- Mosh 标签不在这套自动恢复里：Mosh 会话一结束就是结束了，见 [用 Mosh 连接](#用-mosh-连接)。
- 在 shell 里 `exit` 或断线后，这个标签的 SSH 连接连同跳板会立刻释放。借它开的端口转发随之不能用，但条目还留在列表里，要手动停掉。
- **已知问题**：断线那一刻你敲的字，服务器可能收到了也可能没收到，App 现在不会标出来。断线前正在执行重要命令的，恢复后先确认一下结果。

## 8. 终端引擎（实验）

「设置 → 外观与终端 → 终端引擎」能选 xterm2（默认，就是原来那个）或 Ghostty（实验）。

**怎么选**：用中文输入法、语音输入的选 Ghostty。xterm2 会把语音输入的一句话整段重复发出去，
输入法回头改已经上屏的字时也会重发；Ghostty 修好了这个（输入法表现见 [第 9 节](#9-快捷键栏键盘与分屏)）。
离不开下面表里那几样（点网址、翻 5000 行以上的历史、看图片）的先留在 xterm2。

- **只影响之后新开的终端**，开着的标签不换。用 Ghostty 开的标签，名字后面标着「· Ghostty」。
- Ghostty 起不来时（比如这台手机加载不了它的程序库），连接直接失败，不会偷偷换回 xterm2。
  失败页写「终端引擎 Ghostty 无法启动」，还没开始连服务器；改回 xterm2 再连就行。
- 快捷键栏、软键盘、复制都能用：长按后拖动选字（双击选一个词），右上角点「复制」；vim、less 这类全屏程序里点「复制」弹出整屏文字再选。

现在用 Ghostty 和 xterm2 不一样的地方（迁移还没做完）：

| 地方 | Ghostty 现在 |
|---|---|
| 网址 | 不识别成链接，点了不打开 |
| 往回翻的历史 | 最多约 5000 行（xterm2 是 1 万行） |
| 服务器发来的图片（Kitty 图像） | 不显示，直接丢掉 |
| é 这类带「组合重音」的字 | 重音画不出来，显示成 e |
| 系统「字体大小」 | 终端里的字不跟着变，用设置里的终端字号（xterm2 跟着变） |

## 9. 快捷键栏、键盘与分屏

**快捷键栏**（终端下面那两行键）

- Esc、Tab、方向键、Home/End 按服务器上程序当前的键盘模式发：vim、less、tmux 里方向键照常移动，不会乱跳、不会打出 `A` `B`。
  自己加的快捷键按你填的字符原样发。
- Ctrl、Alt、Shift 按一下亮起，只管下一个键（快捷键栏上的、软键盘上的、蓝牙键盘上的都算），用完自动熄灭。
  亮着的时候切到别的标签、在分屏里点另一格、或者切到后台，都会自动熄灭——不会回来后打的第一个字变成控制键。
- 每个键能点的范围是 48dp 高（原来行高 38dp、实际只有中间一半能点到）。

**地方不够时**（横屏，或小屏手机弹着键盘）快捷键栏收成一行：键横排，放不下就左右滑；端口转发、系统管理、画中画、全屏、分屏、
编辑快捷键收进行尾的「…」菜单，「收起键盘」留在最右边。横屏还弹着键盘时，顶上的标签条也收起来（收起键盘就回来）。
服务器那边看到的行数始终等于你屏幕上看得见的行数：模拟器上横屏弹键盘剩 3 行，vim 不会再把内容画到键盘底下。

**分屏**：两格都能打字，点哪一格，键盘和快捷键栏就发给哪一格，那一格四周有一圈描边。

**输入法**

- 拼音打到一半不会发出去，选了字才发；拼音删光不发任何东西；上屏之后的退格删一个字（emoji 也只删一个）。
- 语音输入（Ghostty）：一句话只发一遍。输入法边听边改识别结果时，服务器那边先出现字，改了的部分被删掉重写，最后留下最终那一版。
  真机（Pixel 9 Pro + 微信输入法）上实测过：说一句、说两句中间停一下，服务器收到的都是原话、只有一遍；
  拼音选字、上屏后删字、拼音删光、中英混着打也都对。xterm2 的语音输入仍会整句重复，见 [第 8 节](#8-终端引擎实验)。
- 「设置」里的「系统安全键盘」两种引擎都管用：开了以后输入法按密码框对待（不联想、不学习），多数中文输入法只给英文键盘。
- 本 App 不申请麦克风权限，语音输入用的是输入法自己的权限。

**蓝牙/USB 键盘**：Ctrl+C、Ctrl+D、Alt+字母、Tab、方向键、Shift+Tab 都对，组合键松开后不粘。
Esc 键在模拟器上测不了（模拟器把它当返回键），真键盘上还没测。

## 10. tmux

在终端快捷键栏的「系统管理 → tmux」里。查询和操作都走你打开面板的那个标签的连接（同一条路线、同一个账号）。

**看会话**

- 列出这个 socket 上的会话：名字、编号（`$3` 这种，tmux 给的）、窗口数、附着着的客户端数、前缀键、鼠标开关。
- 只是看：不会启动 tmux server，不在服务器上建任何文件；远端没有 tmux 就直说，不会替你装。
- 默认看 tmux 不带参数时用的那个 server（`/tmp/tmux-你的 uid/default`）。用 `tmux -L 名字` 或 `-S 路径` 开的，点「默认 socket」换。
  shell 配置里改了 `TMUX_TMPDIR` 的，面板看不到（它不读你的 shell 配置），填 `-S` 路径。
- 只在 tmux 2.4、2.7、3.0a、3.5a 上实测过。更老的、或版本号认不出来的（比如写成 `openbsd-7.5`、`master`），面板只显示版本，
  不给附着、新建、结束；终端里照常可以自己敲 tmux。
- tmux 的输出不对劲（同一个编号出现两次、混进了另一个 server 的行）时，整张表不给操作，免得点错。会话超过 1000 个只列前 1000 个，并写明。

**附着（会话右边的箭头）**

- 在新标签里附着，标签名是「tmux: 名字」。不会踢掉电脑上已经附着着的客户端。
- 附着的是你点的**那一个**会话：它已经被结束、tmux server 重启过（编号会从 `$0` 重新数）、或者只剩一个同名的新会话，都不附着，
  等待页写明原因。不会按名字找一个凑合，也不会替你新建。
- 附着不改任何 tmux 设置（原版会顺手把这个会话的鼠标模式打开）。
- 刚附着上那一瞬间敲的字可能被 tmux 丢掉，等画面出来再打字。

**断线、分离、关标签**

| 发生了什么 | 会怎样 |
|---|---|
| 网络断了 | 自动恢复只重新附着原来那个会话，先在服务器上核对还是不是同一个；不是就停下，终端里写明原因，不再自动重试 |
| 在 tmux 里按前缀键 + d 分离，或会话结束 | 标签停在那里，不自动重新附着；要回去，在面板里再附着一次 |
| 面板上的「分离本标签」（从 tmux 标签打开面板时才有） | 只分离这个标签自己的客户端，同一会话的其他标签、电脑上的客户端不受影响 |
| 关标签、退出 App | 只是这个客户端离开：tmux 会话和里面的程序留在服务器上，不发 Ctrl-C，不结束会话 |
| 关一个已经断开的 tmux 标签 | 只是把标签移走，不碰服务器。确认框写「tmux 会话 …（$4）如果还在，不受影响」：断开期间会话可能已经没了，App 不替你打包票 |

普通（不在 tmux 里的）标签关掉时，shell 里正在跑的程序通常会跟着结束，关标签的确认框也这样提醒。

**已知问题**：自动恢复停下（红字写着原因）时，红字下面可能还留着断线前那一屏 tmux 的状态栏。那是旧画面，不代表又连上了；要回去，在面板里重新附着。

**新建、结束、鼠标**

- 「新建」只建不附着。名字只能用字母（含中文）、数字、`_`、`-` 和中间的空格；不收 `#`，因为 tmux 会把 `#(命令)` 当命令执行。
- 「启动命令」会原样输进新会话的 shell，再回车一次。
- 「结束会话」要确认，按编号核对后才结束，名字相近的别的会话不受影响。
- 「为这个会话打开鼠标」只改这一个会话，不改 tmux.conf、不改全局设置，tmux server 重启后就没了。

## 11. 文件（SFTP）

- 两台服务器之间复制或移动文件，会先问你走哪条路：

  | 选项 | 怎么走 | 代价 |
  |---|---|---|
  | 手机中转 | 按两台服务器各自的路线，文件经手机收发 | 走手机流量，慢 |
  | 服务器直传 | 源服务器直接连目标服务器 | 不走你给目标设的代理或跳板；要求两台服务器之间能互通、源服务器配好了到目标的密钥和可信指纹 |

  直传不可用时会问你要不要改用手机中转。服务器上的操作（直传、同一台服务器内复制移动）做到一半失败，不会自动改成手机中转，报错里写着该去检查的目标和临时目录。
- 移动文件时，传输失败会保留源文件；同名文件不会被直接覆盖。
- 服务器没开 SFTP 时，10 秒内报原因，不会一直转圈。

## 12. 导出、导入与凭据

**凭据**指密码、私钥、私钥口令、代理口令。它们只存在系统安全存储（Android Keystore）里，不进普通文件，也不进系统备份和换机迁移。

- **导出**（「设置 → 数据管理 → 导出保险库 JSON」）：文件里**没有**凭据，只有主机、分组、路线这些配置。
- **导入**（「导入 Netcatty JSON」）：选好文件后先弹「导入保险库文件」，写明会新增几台、更新几台、本机独有的是哪些，确认了才写。

  | 按钮 | 结果 |
  |---|---|
  | 合并（默认） | 文件里有的按条目新增或更新（两边都有的以文件为准），本机独有的主机、私钥、代理配置、片段连同凭据都留着 |
  | 替换（红色，只在本机有独有条目时出现） | 保险库变成文件的内容。本机独有的条目**连同密码和私钥**删掉，之后再导入不带凭据的备份也找不回来 |
  | 本机没有独有条目时只有「导入」 | 合并和替换结果一样 |

  - 凭据怎么带过来：在同一台手机上导入本 App 导出的文件，地址、端口、用户名都没变的主机沿用本机已存的密码；私钥和代理口令同理。改了地址的不沿用，免得你的密码被发给另一台机器——确认框会点名列出这些主机。
  - 文件里自带凭据的（比如原版导出的），以文件为准。
  - 换手机导入，凭据全部要重新填；确认框会列出只有名字、没有内容的私钥。
  - 服务器指纹记录：合并时同一台服务器两边不一样，保留本机核对过的那条；替换时用文件里的。
  - 确认框开着的时候，本机的主机、私钥、代理或片段有了增删（比如另一处刚存了一台新主机），会报「确认期间本机保险库有变化，没有导入」，什么都不写，重新选文件就行。连接时自动记下的最近连接时间之类不算。
- **保险库页出现红色「保存的凭据中有 N 条无法解密」**：设备密钥失效了，或者数据被改动过。主机配置都还在，只是这 N 条凭据读不出来；用到它们的连接会被拒绝，并写明是哪台主机的哪一样。在编辑器里重新填对应的密码或私钥就好了。
- 没有应用锁。拿到你解锁手机的人能直接用 App 连服务器。

## 13. Tailscale 设备目录

从 Tailscale 读一份设备列表，勾选设备批量建成主机。它**只读列表**：导入不会连接这些设备，也不会启动 VPN。
要连上导入的主机，手机得先能到达它们——开着官方 Tailscale App，或者经代理、跳板机。

入口：「设置 → Tailscale 设备目录」。

**第一次用：**

1. 点「添加来源」。名称随便起；tailnet 保持 `-`（意思是「凭据所属的 tailnet」），一般不用改。
2. 进入来源，二选一读一次设备列表：

   | 方式 | 怎么做 | 会不会保存 |
   |---|---|---|
   | 粘贴 token 读一次 | 在 Tailscale 后台生成一个 API access token，粘进来 | 不保存，读完就丢。建议用短期 token，用完在后台删掉 |
   | 用 OAuth client 读取 | 在 Tailscale 后台新建一个**只勾 `devices:core:read`** 的 OAuth client，填 ID 和 secret | 勾了「保存到本机」、且服务器确认它只能读设备时才保存，以后点「刷新」就行 |

3. 勾选设备 → 底部「导入所选设备」→ 填导入设置（见下）→ 右上角「导入」。

**导入设置**（所有勾选的设备共用）：

- **登录用户名：必填。** 目录不知道服务器上的 Unix 用户是谁，不会默认用 root。
- SSH 端口：默认 22。
- 用设备的哪个地址：IPv4（默认）、IPv6 或 MagicDNS 名称。设备没有所选种类的地址就跳过，不会换用别的种类。
- 连接路径：直连 / 经代理（已保存的配置或自定义 HTTP / SOCKS5）/ 经跳板机（选保险库里的主机，最多 3 台）。规则和 [第 3 节](#3-连接路径直连经代理经跳板机) 一样。
- 认证：自动或私钥。**密码不在这里批量填**，导入后到各主机的编辑器里填。
- 下方实时显示每台会建成什么（`名字 → 用户@地址:端口`）、哪些被跳过及原因、连接时走哪条路线。

已导入过的设备不能再勾，不会重复建；已有的主机（包括你手动建的）一台都不改。导入的主机第一次连接照常要 [核对指纹](#5-服务器指纹)。

**保险库里已经有这台机器？** 别再导入一台，点设备下面的「关联到已有主机」，选那台主机。
只记下它对应目录里的哪台设备：地址、用户名、端口、路线、指纹都不改，也不连接；**地址不跟随目录**（刷新永远不改它）。
一台主机只能关联一台设备，反过来也一样；已经关联的要先在编辑器里断开。列表里写「已导入为主机」的是导入的（地址跟随），「已关联主机」的是这样手动关联的。

**页面上的字是什么意思：**

| 看到的 | 意思 |
|---|---|
| 缓存时间 | 最近一次成功读到列表的时间。目录不会自己刷新，只在你点的时候读 |
| 这次的列表不完整（N 条无法识别…） | 列表里有读不懂的条目，这次没有据此把任何设备标成「不见了」 |
| 最近一次读取失败 | 失败原因写在下面；缓存里的设备和已导入的主机都没动 |
| Tailscale 控制面：已连接 / 未连接 / 不知道 | 设备有没有连上 Tailscale 的协调服务器。**不是「在线」**：它不代表手机能连到设备，也不代表 SSH 开着 |
| 最近完整列表里没有它 | 设备可能被删了、换了 tailnet，或者是别人共享给你、OAuth client 看不到的设备（Tailscale 已知问题 tailscale#16911）。设备和主机都不会被删 |

**刷新后主机会怎样：** 只有地址可能变，而且只在你没手动改过地址时——设备换了 IP，主机地址跟着改；你改过就不再跟随。
用户名、端口、路线、认证、指纹信任，刷新一概不碰。地址变了，第一次连接要按新地址重新核对指纹。

**在主机编辑器里：** 导入的主机多一块「目录来源」，写着来源、设备、目录状态、缓存时间、地址是否还跟随目录。
点「断开和目录的关联」再保存，主机和它的设置都留着，只是以后刷新不再改它。

**删凭据、移除来源：**

- 来源页右上角菜单「删除本机保存的 OAuth client」：只删手机上的副本，client 在 Tailscale 那边仍然有效，要彻底作废去 Tailscale 后台撤销。
- 「移除这个来源」：删掉设备缓存和保存的 client。关联它的主机都保留、照常能连，编辑器里显示「本机没有这个来源」。要删主机到保险库逐台删。

**想让这些主机重新对上目录：** 目录页下方会列出「主机里引用了、本机没有的来源」（来源被移除过，或主机是从别的手机同步、导入来的）。
点「在本机恢复」，再用**同一个 tailnet** 的 token 或 OAuth client 读一次，主机就重新显示目录状态，导入的主机地址也恢复跟随。
恢复只建一个空来源，不发请求、不改主机；读成了别的 tailnet 也没关系，设备对不上，主机什么都不会被改。

## 14. Tailscale SSH（用 Tailscale 身份登录）

目标机器开着 Tailscale SSH（在那台机器上执行过 `tailscale up --ssh`）时，可以不用密码和私钥，由 Tailscale 按 tailnet 的访问策略决定让不让你登录。

**怎么用：**

1. 主机编辑器的「身份认证」选「Tailscale SSH」，保存。
2. 手机得先到得了这台机器：开着官方 Tailscale App；或者「经代理」走 TailSocks 这类连进 tailnet 的 SOCKS 代理；或者经一台在 tailnet 里的跳板机。
3. 连接。第一次照常 [核对指纹](#5-服务器指纹)。
4. 策略要求 check 时，等待页会出现「Tailscale 要求 check」卡片。核对主机和链接域名（只会是 `login.tailscale.com/a/…`），点「在浏览器中打开」，在浏览器里登录 Tailscale 并确认。回到 App，它自己接着连。

**它做什么、不做什么：**

- 只发 SSH 的 none 认证（不带任何凭据的那种）。编辑器里存着的密码、私钥留着，但不发；私钥连解密都不解。
- 只有你在编辑器里明确选了才这样。地址是 100.x 开头、从 [Tailscale 设备目录](#13-tailscale-设备目录) 导入的，都不会自动变成 Tailscale SSH。
- Tailscale 认的是**连过去的那台 tailnet 节点**，不是你手机上登录的账号，更不是设备目录用的 token 或 OAuth client：

  | 连接路径 | Tailscale 把这次登录算成 |
  |---|---|
  | 直连 | 手机上官方 Tailscale App 的节点 |
  | 经代理 | 代理出口那台节点。手机上的 TailSocks 就是 TailSocks 登录的那个节点，远程 SOCKS 就是那台远程机器；几个人共用一个代理，就都算同一个节点 |
  | 经跳板机 | 最后一台跳板机所在的节点 |

  编辑器里选了 Tailscale SSH 后，下面按当前填的路线写出来。
  所以同一台机器、同一个用户名，**换条路线可能就进不去了**：比如经手机上的 TailSocks 能进，
  经一台大家共用、打了 tag 的远程 SOCKS 就被拒（策略里允许的是你的设备，不是那台代理）。看到「Tailscale 拒绝了」先想想这次是从哪个节点进去的。
- check 链接只在你点按钮时交给浏览器，不复制、不记日志，页面上只显示域名、不显示链接里的一次性 token。**回到 App 不等于通过**，以 SSH 登录结果为准。
- 等 check 最多 10 分钟，到点放弃这次连接，什么命令都没执行。随时可以点「终止连接」。
- 链接不是 `https://login.tailscale.com/a/…` 这种样子的（别的域名、http、不止一条、夹了不可见字符等），卡片变红、没有打开按钮，写出原因和它指向的域名。
  用自建控制面（比如 Headscale）的，它的链接不在名单里：可以在控制面那边批准（Headscale 是 `headscale auth approve --auth-id …`），App 会一直等到截止时间。

**和普通 SSH 的区别（容易踩）：**

- 用「普通 SSH」连开着 Tailscale SSH 的机器的 22 端口：Tailscale 会收下你发的密码或公钥，但**根本不看内容**，照样按 tailnet 身份放行——密码填错也能进（自建控制面 + 真 tailscaled 上实测）。
  想让密码真的起作用，连那台机器上另开的 OpenSSH 端口：Tailscale SSH 只占 tailnet 地址的 22 端口。
- 普通 SSH 下，服务器一个密码私钥都没要就让登录了（none 认证），App 会断开并提示。原版会照样连上，你却以为用的是密码。
- 普通 SSH 下服务器发来带链接的提示（Tailscale 的 check 就是这样），App 立刻断开并提示，不挂着等。
- 桌面端 Netcatty 不认这个设置：同步过去的主机在桌面端还是按普通 SSH 连。

**看到这些报错：**

| 看到的 | 意思 |
|---|---|
| Tailscale 拒绝了这次登录，服务器说：… | 策略不让，或者 check 被拒、过期了。去 Tailscale 后台看访问策略里的 ssh 规则：来源有没有包含这次的来源节点（上表），用户名在不在允许的列表里 |
| 登录完成前连接断了：可能是 Tailscale 不让你登录…，也可能是网络断了 | Tailscale 拒绝时可以一句话不说直接断开，App 分不清是哪种。先看网络 |
| 等 Tailscale check 超过 10 分钟，已放弃这次连接 | 没在时间里确认。重新连 |
| N 秒内没有等到登录结果 | 还没等到 check 链接就卡住了。这个 N 是编辑器「高级选项」里的认证超时；从核对完指纹开始算 |

> 只在本机仿制的服务器、自建控制面 Headscale 加真 tailscaled 上验证过：经本地 SOCKS、远程 SOCKS、跳板机、代理入口 + 跳板四种路线都实测过，
> 各路线测了什么见 `plan/v3/docs/05-tailscale.md`「R15 能力支持矩阵」。**官方 Tailscale 的 check 网页、直连（手机开着官方 Tailscale App）、真的 TailSocks App 都没走过**。

## 15. UU 远程

用网易 UU 远程控制 **Windows 或 Mac 电脑**。远控画面、账号、网络都在 UU 远程 App 里，本 App 只负责发起请求、记下 UU 报告的结果。只在 Android 上有。

先装好 UU 远程 **4.42.0 或更高**，在 UU 里登录，被控电脑要开着「允许被控」。UU 不能控制 Linux、安卓、电视——Linux 服务器用 SSH。

**第一次用：**

1. 在保险库点开一台主机 →「UU 远程」。
2. 看「手机上的 UU 远程」一栏。写着「签名证书和从官方下载的一致」就可以往下走。
   要是它列出一串证书、让你「批准这张证书」：说明手机上这个 UU 不是本 App 核对过的那张官方证书签的（网易换了签名，或者装的不是官方包）。**只在确定它是从官方渠道（uuyc.163.com 或正规应用商店）装的时候**才批准——网上仿冒 UU 下载站很多。
3. 点「在 UU 里选设备」→ UU 列出你账号下的 Windows/Mac 电脑，选一台 → 回到本 App 弹框问要不要关联到这台主机，点「关联」。
4. 之后在这个页面点「全屏远控」或「小窗远控」。

**页面上的字是什么意思：**

| 看到的 | 意思 |
|---|---|
| 已交给 UU 远程。全屏模式 UU 不回报结果 | 全屏时 UU 从不告诉本 App 成没成功，连没连上看 UU 自己的画面 |
| 已交给 UU 远程，等它回报小窗结果 | 小窗时 UU 会回报一次；它可能先弹窗让你确认，不会自动超时。不想等就点「结束等待」 |
| UU 报告小窗已就绪 | 只是 UU 那一刻的报告，不代表现在还连着 |
| UU 报告小窗远控失败：… | 原因照 UU 给的写。「不能用小窗」时有「改用全屏」按钮，本 App 不会自己切 |
| 这条 UU 绑定已失效 | UU 说设备不存在、解绑了或换了 UU 账号：点「重新绑定」。只影响 UU 这一条，主机的 SSH 照常 |
| 已打开 UU 远程的设备授权页，等它回报 | UU 没登录（或第一次打开、停在《用户须知》）时不会回报，实测等了 6 分钟也没有。回到本 App 点「结束等待」，在 UU 里登录好再点一次 |
| 你结束了等待：结果未确认 | 之后 UU 再回报也不算数；要再试就重新点 |
| 等了 10 分钟 UU 没有回报：结果未确认 | 没人点「结束等待」时，10 分钟后自动作废，可以重新发起 |
| 另有 App 也声明能打开 uuremote:// | 手机上还有别的 App 自称能接 UU 的请求。本 App 只把请求发给官方包名，不会发给它们 |
| 另有 App 也声明了本 App 的 UU 回调地址：（包名） | 手机上有个 App 想接 UU 发给本 App 的回报。「在 UU 里选设备」「重新绑定」「小窗远控」变灰，全屏照常。按包名把那个 App 卸掉，回到本 App 就恢复 |
| 绑定没成功：…这次返回的设备不可信，没有采用 | 绑定发出去之后才出现了上面那种 App。卸掉它，重新绑定 |

**要知道的：**

- 同一时间只能有一个在等 UU 回报的请求，要先「结束等待」才能发新的。
- 主机的 SSH 经代理或跳板时，发起前会提醒：UU 走它自己的网络，不经过这些设置。要求远控也走同一条路线的话 UU 做不到，点「取消」。
- UU 只给一个加密的设备标识，本 App 看不到设备名。它只存在本机的加密存储里，不进保险库、不导出、不跟着同步；换手机要重新绑定。
- 没刚在 UU 里选过设备，却弹出「UU 远程返回了一台设备」：点「不要」。别的 App 也能伪造这种回调。
- 从 UU 回来时系统弹「Open with / 打开方式」让你选 App：说明手机上有别的 App 也想接这条回报。选 **xwshun**，别选别的，更别点「始终」。选错了，那个 App 会拿到这次的加密设备标识。
- 把系统的 bugreport（错误报告）发给别人前要知道：里面的「最近任务」记录带着本 App 发给 UU 的远控请求地址，地址里有加密设备标识。这是 UU 的协议把标识放在地址里决定的，本 App 改不了；本 App 自己收到的回报地址不会留在那里。
- 手机上的 UU 换了签名证书（比如换了渠道重装），本 App 停下来要你重新核对，核对前不发任何请求。
- 「设置 → UU 远程」看 UU 的状态和全部绑定（包括主机已删掉的），可以删除绑定。删绑定只删本 App 里这一条，UU 里的设备和主机都不受影响。

## 16. RustDesk

给一台主机记下它的 RustDesk ID，点一下交给手机上装的 RustDesk 去连。远控画面、密码、ID 服务器和中继设置都在 RustDesk 里，本 App 只负责记住「这台主机是哪个 RustDesk ID」并替你打开。只在 Android 上有。

先装好 RustDesk **1.2.4 或更高**（建议 1.4.7 以上，原因见下面的表），从 [GitHub 发行页](https://github.com/rustdesk/rustdesk/releases) 或 F-Droid 装。
自建服务器的话，先在 RustDesk 里把 ID 服务器配好、自己连通一次——本 App 不会、也不能替你改 RustDesk 的服务器设置。

**第一次用：**

1. 在保险库点开一台主机 →「RustDesk」。
2. 看「手机上的 RustDesk」一栏。写着「签名证书和 GitHub 官方发行版的一致」或「和 F-Droid 构建的一致」就可以往下走；要你批准证书的情况见下表。
3. 在「这台主机的 RustDesk ID」里填被控电脑 RustDesk 主界面上的「ID」，点「保存」。数字 ID 带不带空格都行。保存只是记下，不会打开 RustDesk。
4. 点「用 RustDesk 远控」：手机切到 RustDesk，它马上开始连这个 ID。要密码就在 RustDesk 里输。

**ID 能填什么：** 纯数字（RustDesk 自动分配的那种），或字母开头、6 到 16 位的字母、数字、下划线、连字符（自定义 ID）。下面这些会被拒，输入框下面会写原因：

| 填了 | 为什么不行 |
|---|---|
| `rustdesk://…` 整条链接 | 链接里能带密码、能改 RustDesk 的服务器设置。只填 ID |
| `ID@服务器`、`ID?key=…` | 这是让 RustDesk 改连别的服务器。用哪台服务器只在 RustDesk 里配 |
| 结尾加 `/r` | 这是强制走中继。在 RustDesk 里设置 |
| IP 地址或域名 | 按 IP 直连这一版不支持，只能填 RustDesk ID |
| 中文或别的文字的 ID | RustDesk 允许，这一版填不了 |

**页面上的字是什么意思：**

| 看到的 | 意思 |
|---|---|
| 已交给 RustDesk。它不向本 App 回报结果 | 系统已经把请求交给 RustDesk。连没连上、什么时候断开，本 App 永远不知道，要在 RustDesk 里看。实测连一个不存在的 ID：RustDesk 自己弹「Failed to connect: the target device is offline or does not exist」，本 App 这边不会变 |
| 交给了：（包名 版本） | 这次发给了哪个 App、当时是什么版本。出问题时用来对照 |
| 没能打开 RustDesk：… | 系统没接下这次启动（比如 RustDesk 刚被卸载、被停用）。本 App 不会重试，也不会改发给别的 App |
| 这张证书不是本 App 核对过的发行渠道证书 | 手机上的 RustDesk 不是 GitHub 发行版或 F-Droid 那张证书签的：可能是应用商店重签的、自己编译的，也可能是冒牌的，本 App 分不出来。确定来源才点「批准这张证书」 |
| 你信任的那个 RustDesk 换了签名证书 | 批准过的那个 RustDesk 被换成了另一张证书签的。核对前不发任何请求；确认没问题点「批准新证书」，否则「撤销信任」 |
| 另有 App 也声明能打开 rustdesk://：（包名） | 手机上还有别的 App 自称能接 RustDesk 链接。请求不会发给它。如果它是你自己编译、改了包名的 RustDesk，点「信任并改用」，看过包名和证书再确认 |
| 装着的 RustDesk 版本太旧 | 1.2.3 及更早不接受别的 App 发来的连接请求，先更新 |
| 这个版本能用，但它会执行任何 App 或网页发来的改密码、改服务器链接 | 1.4.6 及更早的 RustDesk 自己的问题：手机上随便一个 App 或网页发条链接，就能改这台手机上 RustDesk 的固定密码和服务器。本 App 从不发这种链接，但建议更新到 1.4.7 以上 |
| 这个版本比本 App 核对过的新，没有核对过 | 本 App 是照 1.5.0 及以前的源码写的。链接照旧写法发；打不开或连错了先怀疑这里 |

**要知道的：**

- 本 App 发给 RustDesk 的只有一种链接：`rustdesk://connect/<ID>`。不带密码，不带服务器，不带别的参数，也从不发改密码、改配置的链接。
- 只在你点「用 RustDesk 远控」时才发。填 ID、打开页面、回到 App 都不发。
- 主机的 SSH 经代理或跳板时，点远控前会提醒：RustDesk 走它自己配置的服务器和网络，不经过这些设置。要求远控也走同一条路线的话 RustDesk 做不到，点「取消」。每次都会问。
- RustDesk ID 只存在本机的加密存储里，不进保险库、不导出、不跟着同步；换手机要重新填。同一台电脑的两个 SSH 主机可以填同一个 ID，互不影响。
- 卸载 RustDesk、删掉这条 ID、删掉同一台主机的 UU 绑定，都只动那一样：主机、SSH 设置和别的关联照旧。RustDesk 装回来不用重填 ID。
- RustDesk 自己会把收到的整条链接（含 ID）打进系统日志；系统的「最近任务」记录（bugreport 会带上）里 RustDesk 那一条也有。这是 RustDesk 和系统的行为，本 App 改不了；本 App 自己不打。
- 「设置 → RustDesk」看手机上 RustDesk 的状态和全部主机的 ID（包括主机已删掉的），可以删。

## 17. 插件（实验）

插件是**另外安装的 App**，给这个 App 提供新的连接方式。只在 Android 上有。
Mosh 就走这条路：装上 Mosh 插件（包名 `top.xdwa.xwshun.mosh`）并批准后，主机协议选 Mosh 就能连，见本节末尾 [用 Mosh 连接](#用-mosh-连接)。
除它以外，现在能装的插件都是开发和测试用的。

入口：「设置 → 插件（实验）」。

- 列表里只出现**声明了本 App 插件接口**的已安装 App。批准之前不会启动它们的任何代码。
- 「SSH / Telnet（内置）」「连接路径（内置）」「Tailscale 设备目录（内置）」「UU 远程调用（内置）」「RustDesk 调用（内置）」是 App 自带的，一直可用、不能停用。
- 点一个插件进详情页：来源、证书 SHA-256、插件自称的版本和系统报告的安装包版本、能力、支持的连接路线、申请的权限都在这里。
  Mosh 插件申请的是「本会话的临时凭据」：连 Mosh 时，App 把服务器当场为这一次会话生成的一次性密钥交给它，用完两边都清掉；
  保险库里的密码、私钥它照样拿不到。没申请这项权限的插件，App 不会把这种密钥交给它。
- **批准**：点「批准」，弹框里有插件的签名证书 SHA-256，和插件作者公布的核对一致再批。
  批准后它只能收到自己会话里的数据，拿不到保险库、私钥、密码或其他主机。
- 批准后可以点「连接测试」看它能不能正常握手。
- **停用**：它正在跑的会话被关掉，别的会话不受影响；批准记录保留，重启 App 后仍是停用，点「启用」直接恢复，不用重新批准。
- **撤销批准**：收回批准，回到待批准；要再用得重新核对。
- **插件自己的设置页**：插件声明了设置页的，详情页有「打开插件的设置页」，打开的是插件 App 自己的页面，设置也存在插件里，本 App 看不到。只有「可用」的插件才有这个入口。
- **插件更新、卸载后不用手动刷新**：插件页开着时，你装上、更新、卸载插件，页面会自动重新核对证书和能力：
  - 普通更新：仍可用，之前的连接测试结果作废；
  - 新版本多申请了能力：回到待批准，要你重新核对，不会自动扩大批准；
  - 换了签名证书：已拒绝；
  - 卸载后装回同一证书的包：直接恢复可用。
  插件页没开的时候，下次打开时会重新核对一遍。
- 批准确认框开着的时候插件被更新了，点「批准」会提示「确认期间插件有变化」、不批准——你核对的已经不是现在这个版本了。
- 插件由你自己安装和卸载，本 App 不下载、不安装任何插件。插件是独立的 App，有它自己的权限，本 App 管不住它自己联网。
- 插件内部出错时，只是这一次操作失败，报错写「插件出错：…」，App 和别的会话照常。（以前插件抛一个意外的错误，整个 App 会闪退，模拟器上实测过，已修。）

| 状态 | 意思 | 怎么办 |
|---|---|---|
| 可用 | 已批准，签名和上次核对的一致 | — |
| 待批准 | 新发现的插件 | 核对证书后批准，或者不管它 |
| 已拒绝 | 冒用自带插件的名字、自称是自带的、换了签名证书，等等，原因写在条目上 | 换了签名的：确认是作者正常换证书，就撤销旧批准再重新核对 |
| 不兼容 | 插件要的接口版本这个 App 没有（比如新版本把 API major 改了） | 装回兼容的版本，或等 App 升级 |
| 已停用 | 你手动停用了 | 点「启用」，不用重新批准 |
| 已卸载 | 之前批准过，现在手机上没这个 App 了 | 装回同一证书的包会直接恢复 |

**某个插件 App 没出现**：页面底部「某个应用没出现在这里？」填它的包名点「检查」，会告诉你原因（没装、没声明插件接口、描述文件有问题等）。

- 用 Android 调试证书签名的插件只有开发构建的 App 认；正式构建一律拒收。
- 用多张证书共同签名的插件暂时批准不了。

### 用 Mosh 连接

Mosh 是给不稳定网络设计的终端协议：会话走 UDP，由 Mosh 自己负责重传和接续。**只在模拟器上测过**；
网络切换、锁屏后台这些 Mosh 最该派上用场的情况，本 App 里还没测（见 [第 18 节](#18-还没有的功能)）。

**第一次用：**

1. 服务器上装 mosh（Debian/Ubuntu：`sudo apt install mosh`）。服务器和中间的防火墙要放行 UDP 60001–60999，
   或者你在主机里填的那几个端口（第 3 步）。
2. 手机上装 Mosh 插件 APK，到「设置 → 插件（实验）」核对证书、批准（见上面）。
3. 新建或编辑主机：最上面协议选 **Mosh**。用户名、SSH 端口、密码或私钥照常填——Mosh 要先用 SSH 登录一次。
   「连接路径」只能是**直连**。服务器只放行了某几个 UDP 端口时，填「Mosh UDP 端口范围」，比如 `60001` 或 `60001:60010`。
4. 保存，在保险库里点这台主机「连接」。等待页依次写：
   「正在核对本机的 Mosh 插件」→「SSH 握手、核对指纹、登录」→「第 1 段 SSH：…正在启动 mosh-server」→「第 2 段 UDP：SSH 已断开，Mosh 插件正在直连 IP:端口」。
   模拟器上从点连接到出提示符约 1.3 秒。

**和 SSH 标签不一样的地方：**

- **两段走的是两条路。** SSH 只用来在服务器上启动 mosh-server、拿到这次会话的端口和一次性密钥，拿到就断开；
  之后终端全走 UDP，从手机直接发到刚才 SSH 实际连上的那个 IP。所以「SSH 能连上」不代表 Mosh 能通，UDP 被拦了 Mosh 一样连不上。
- **只能直连。** 选了代理、跳板机（包括 TailSocks 这种手机上的 SOCKS5）的 Mosh 主机，编辑器不让保存；从桌面端同步来的，
  点连接时直接报错，**什么都没发**：没连服务器、没启动 mosh-server，也不会改成直连绕过你选的路线。要经代理，就把协议改回 SSH（想断线后接着用，配合 tmux）。
- 插件只拿到这次会话的 IP、端口、一次性密钥；你的密码、私钥、代理口令它都拿不到。
- 没有「测试连接」按钮：它只测得了 SSH 那一段，给 Mosh 主机一个「通过」反而误导。
- Mosh 标签没有文件（SFTP）、性能监控、端口转发、系统管理：这几样都要借 SSH 连接，而 Mosh 的 SSH 用完就断了。
- 终端引擎跟着「设置 → 外观与终端」走，和 SSH 标签一样；中文输入法、语音输入的情况见 [第 8 节](#8-终端引擎实验)。
- **会话结束不自动重连，也不重发断开前的输入。** 标签留着，终端里用红字写明为什么结束；再连就从保险库重新点连接——
  那是服务器上新起的一个 mosh-server，不是原来那个会话。
- 关 Mosh 标签：服务器上这次的 mosh-server 和里面的 shell 一起退出（模拟器上实测约 0.3 秒后远端就没了）。
- 在插件详情页点「连接测试」，会断开 Mosh 插件正在跑的所有会话（它要重新握手）。有 Mosh 标签开着时别点。

**连不上、断了：**

| 看到的 | 意思 | 怎么办 |
|---|---|---|
| Mosh 只能直连，这台主机的连接路径是：… | 这台主机配了代理或跳板 | 改成直连，或者协议改回 SSH |
| 没有装 Mosh 插件 / Mosh 插件还没批准 / 被停用了 | 本机插件的问题，还没连服务器 | 到「设置 → 插件（实验）」处理 |
| 主机指纹没有通过校验 / 登录被拒绝 | SSH 那一段的问题，和普通 SSH 一样 | 见 [第 5 节](#5-服务器指纹)、[第 6 节](#6-连接中连接失败)。指纹没过时连登录信息都没发 |
| 远端没有安装 mosh-server | 服务器上没装 mosh | 请管理员装。本 App 不会替你装，也不会用 sudo |
| 远端没有可用的 UTF-8 语言环境 | 服务器缺 UTF-8 locale | 在服务器上 `locale-gen en_US.UTF-8` 之类 |
| 终端里：mosh did not make a successful connection to IP:端口，下面红字「mosh-client 没能正常收尾（退出码 1）」 | UDP 到不了服务器（模拟器上约 20 秒后出现） | 服务器、防火墙放行那个 UDP 端口；只放行了几个端口的，在主机里填「Mosh UDP 端口范围」 |
| 终端里：Mosh 插件进程没了 | 插件被系统或手动结束 | 从保险库重新连接。服务器上可能留着旧的 mosh-server（它会一直等客户端回来），`pkill mosh-server` 清掉 |

## 18. 还没有的功能

| 功能 | 现状 |
|---|---|
| Tailscale SSH 走官方 Tailscale 的 check | 没走过（没有账号）。[第 14 节](#14-tailscale-ssh用-tailscale-身份登录) 的功能只在本机仿制的服务器和自建控制面 Headscale 上验过 |
| Mosh | 能连了（[用 Mosh 连接](#用-mosh-连接)），只在模拟器上测过；只能直连。网络切换、锁屏后台时会话能不能接着用、真机上的表现都还没测 |
| 新终端引擎（Ghostty） | 能在设置里选（实验），默认仍是原来的；还没迁移完的地方见 [第 8 节](#8-终端引擎实验) |
| 应用锁、生物识别 | 没有，要不要加还没定 |
| UU 远程 | 只做了 Android；真实的 UU 远程只在没登录的状态下试过，登录之后的绑定和远控还没走过 |
| RustDesk | 只做了 Android，只能把 ID 交给手机上的 RustDesk 去连，画面不在本 App 里；真实 RustDesk 1.4.9 只试过连一个不存在的 ID，还没真连上过一台电脑 |
| iOS | 只在 Android 上测过；插件、UU 远程、RustDesk 只支持 Android |
| tmux 快捷按钮（切窗口、分屏之类） | 没有，在终端里用前缀键操作；面板只管看、附着、新建、结束和单个会话的鼠标开关 |

## 19. 和原版 Netcatty 不一样的地方

从原版换过来，这几处会让你觉得「怎么不行了」：

| 原版 | 这里 | 为什么 |
|---|---|---|
| 代理配置无效时会悄悄直连 | 一律报错 | 你选代理多半就是不想暴露真实出口 |
| 跳板机上配的代理，经它连接时也会套用 | 报错，要求把代理设在目标主机上 | 一条路线只有一个入口，看得清走的是哪 |
| 指纹变了能点「确认更新」直接连 | 拦下，只能删旧指纹后重新核对 | 防止一点就把冒充者当成自己的服务器 |
| 导出文件含明文密码和私钥 | 不含 | 导出文件常被随手传、随手存 |
| 导入直接整库替换、不提示 | 先说明会删什么，默认合并 | 替换会连同凭据删掉本机独有的主机，删了找不回 |
| 跨服务器传文件自动先试直传 | 先问你选哪种 | 直传不走你的代理和跳板，要你知情 |
| 编辑器里选一次跳板机就崩（开发版红屏） | 修好了 | — |
| AI、云同步、检查更新开着 | 默认关、界面上看不到 | 没授权前不发网络请求 |
| 没有 Tailscale 设备目录 | 能读设备列表、批量导入为主机 | 只读，导入不连接、不开 VPN |
| 没有 UU 远程联动 | 能在主机上绑定 UU 远程里的 Windows/Mac 并发起远控 | 远控在 UU 里进行；本 App 只写 UU 报告了什么，从不说「已连接」 |
| 没有 RustDesk 联动 | 能给主机填 RustDesk ID，点一下交给手机上的 RustDesk 去连 | 远控在 RustDesk 里进行；RustDesk 不回报，本 App 只写「已交给」 |
| 服务器一个密码私钥都不要就放行（none 认证），照样连上 | 普通 SSH 下断开并提示 | 开着 Tailscale SSH 的机器就是这样被悄悄用 tailnet 身份登录的，你却以为用的是密码 |
| 没有 Tailscale SSH 设置 | 编辑器里明确选「Tailscale SSH」才用，只发 none，check 在浏览器里做 | 用哪种身份登录要你自己定，不按地址猜 |
| 没有独立插件 | 「设置 → 插件（实验）」能接单独安装的插件 App，每次调用都互相核对签名 | 插件代码不进本 App；换签、冒名的一律拒绝 |
| 横屏弹着键盘时，快捷键栏照常全部展开，终端被挤得一行都不剩，服务器却还以为有 5 行 | 快捷键栏收成一行，端口转发、系统管理这些按钮收进行尾「…」，标签条也暂时收起 | 至少留几行终端能看（见 [第 9 节](#9-快捷键栏键盘与分屏)） |
| 分屏时快捷键栏总发给当前标签，按下的 Ctrl 可能落到你没在看的那一格 | 点哪一格就发给哪一格，那一格有描边 | 两格都能打字，按键去哪要看得见 |
| tmux 面板按名字附着、结束，附着时顺手打开鼠标；会话列表在 tmux 2.4–3.5a 上一直是空的 | 按编号附着、结束，先核对还是不是原来那个；附着不改任何设置；列表正常 | 按名字操作会落到名字相近的别的会话上：`work` 不在时，结束的是 `workshop` |
| 包名 `app.netcatty.mobile` | 包名 `top.xdwa.xwshun` | 两个能装在同一台手机上，数据互不影响 |
