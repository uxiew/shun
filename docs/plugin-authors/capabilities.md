# 能力一览：插件能做什么、做不到什么

> 对应插件 API **1.0**（2026-10-07）。宿主的插件 API 版本在「设置 → 插件（实验）」最底下；不是 1.0 时，先看这页有没有跟着改。

动手之前先读这页：你想做的东西宿主用不用得上、能做到哪一步，在这里就能判断，不用写完装上才发现。

## 能力（描述符的 `capabilities`）

「宿主现在用不用」三种说法：**可用**（宿主会调用第三方插件的这项能力）、**只能声明**（描述符里能写、能批准，但宿主哪儿都不调用）、**只给内置**（第三方写了直接「已拒绝」）。

| 能力 | 能做什么 | 宿主现在用不用 | 拿它能做出什么插件 | 以后打开时会怎样 |
|---|---|---|---|---|
| `terminal-session` | 提供一个终端会话：宿主给你一条字节流，你读用户的输入、写终端要显示的东西；宿主告诉你尺寸变化、什么时候关 | **可用**。用户在主机编辑器里把协议选成「插件」、选你的插件，就能从主机列表开你的标签；插件详情页的「会话测试」给你自己核对用。宿主不给你任何主机数据，连哪里由你的设置页决定 | 宿主没内置的终端协议或连接方式：私有协议的设备控制台、串口转网络、别的远程终端协议（插件自己联网）、本地演示用的小 shell | 以后可能在新的 minor 里加「目标地址（不含口令）」这类字段，让用户在宿主里填地址、交给插件；没加之前，地址只能在你的设置页里填 |
| `device-catalog` | 提供一份设备列表（来源、名字、地址），像宿主内置的 Tailscale 设备目录 | **只能声明**。只有宿主内置的 `builtin.tailscale` 在用 | 现在做不出用户看得到的东西 | 要宿主在新的 minor 里给第三方目录开入口、定好接口（现在 AIDL 里没有列设备的方法）。到时候按 compatibility.md 的 minor 规则协商 |
| `remote-desktop-external` | 用户点了之后，拉起别的远控 App | **只能声明**。宿主里的 UU 远程、RustDesk 调用是宿主内置的适配器，不是插件 APK | 现在做不出 | 同上，要新接口 |
| `remote-desktop-surface` | 在宿主的标签里内嵌远控画面（插件持有连接、宿主给它一块画布） | **只能声明**，宿主没有任何实现 | 现在做不出 | 要宿主先做出画面接口（规划中，没排期） |
| `route` | 决定流量怎么走：直连、SOCKS 代理、跳板机 | **只给内置**。第三方声明直接「已拒绝」 | — | 不会开：交出路由就等于交出「代理或跳板失败时绝不偷偷直连」这条底线 |

声明了「只能声明」的能力：批准框和详情页会照实列出来，用户批准的范围包括它们；宿主不会调用它们。自查命令（README 第 4 步）会提醒你。
以后新版本多申请能力，用户要重新批准（compatibility.md），所以用不上的能力别先写着。

## 权限（描述符的 `permissions`）

集合是封闭的，就这 5 项。宿主给不了的权限不会出现在这里：没有保险库、私钥、密码、token、执行命令、读文件、剪贴板。

| 权限 | 宿主界面上的名字 | 意思 | 宿主现在用不用 |
|---|---|---|---|
| `own-session-input-output` | 本会话的输入输出 | 插件收得到它自己会话里用户敲的每个键、写得出终端画面 | 终端插件写它。宿主现在只在批准框、详情页显示，不写不会被拒，但用户看不出你要收发会话数据 |
| `own-session-ephemeral-secret` | 本会话的临时凭据 | 宿主经 SSH 为这一次会话拿到的一次性材料（Mosh 的 key） | **只给 Mosh 插件**：宿主只把它交给 pluginId 为 `xwshun.mosh`、证书是登记那张的插件。别的插件写了什么都拿不到，「会话测试」也不给开，还会让用户以为你要凭据 |
| `user-initiated-external-launch` | 由你点击后打开外部 App | 配 `remote-desktop-external` | 只能声明 |
| `own-provider-state` | 插件自己的状态 | 插件自己保存的东西（设置之类） | 只能声明。插件的设置本来就存在插件自己的存储里，不需要宿主授权 |
| `device-catalog-read` | 读设备目录 | 配 `device-catalog` | 只能声明 |

## 插件做不到什么、为什么

| 做不到 | 为什么 |
|---|---|
| **往终端页上画界面**（按钮、弹窗、侧栏） | 宿主不加载插件的任何界面代码（不下载 Dart、JS 界面，也不把插件的 View 嵌进来）。插件代码放进宿主的界面里跑，就等于拿到了宿主的权限。你能给的是字节流里的终端序列（颜色、光标、全屏程序那一套），和你自己 App 里的设置页（宿主详情页能打开它） |
| **往别的会话里打字、读别的会话** | 每个会话一条单独的字节流，句柄、代次和调用方绑在一起，拿着别人的句柄调不动（contract.md 第 5 节）。一个插件能往 SSH 标签里打字，就能在用户的服务器上执行命令 |
| **改粘贴、链接、按键的规则** | 粘贴预览、打开链接前的确认、快捷键栏、按键面板都是宿主的，插件只收到用户确认之后发出的字节。这些是防止远端和插件诱导用户的关口，交给插件就没用了。你写进输出里的「改剪贴板」「发通知」「打开网址」这类终端序列，宿主同样一概不执行 |
| **拿保险库、私钥、密码、别的主机、剪贴板** | 接口里根本没有这些方法，权限集合里也没有。插件是第三方代码、有自己的联网权限，拿到了就管不住它发到哪 |
| **执行命令**（在手机上或在服务器上） | 没有执行命令的接口。Mosh 那次在服务器上启动 mosh-server，是宿主写死的固定命令，不是插件给的。任意执行命令就是任意代码执行 |
| **让宿主替你联网、走宿主配的代理或跳板** | 插件自己联网，宿主管不住它的网络；描述符的 `supportedRoutes` 只是你的声明，不是防火墙。用户在宿主里配的代理、跳板对你的插件不起作用 |
| **被宿主自动拉起、在后台常驻** | 宿主只在用户点了之后才绑定你的服务；批准之前、停用之后都不启动你的代码 |
| **被宿主下载、安装、更新** | 宿主不下载、不安装任何插件，用户自己装。要更新就发新 APK |
| **在 iOS 上跑** | 插件机制只有 Android |

## 值不值得做

- **值得**：你手上有个东西能产出终端字节流（某个协议、某台设备的控制台、一个本地程序），想让它出现在 xwshun 的终端里，并且接受「插件自己联网、自己存设置」。
- **先别做**：你想改宿主的界面或交互、想用宿主存的主机和凭据、想在 SSH 会话里加功能、想做设备目录或远控——这些现在的接口给不了，做了也装不进去。
