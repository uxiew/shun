# 版本、升级和兼容

> 对应插件 API **1.0**（2026-10-07）。宿主的插件 API 版本在「设置 → 插件（实验）」最底下；不是 1.0 时，先看这页有没有跟着改。

## 三种版本号

宿主详情页三种都显示，别弄混：

| 版本号 | 在哪写 | 管什么 |
|---|---|---|
| 插件 API `apiMajor.apiMinor` | 描述符 | 你按哪一版接口写的。宿主现在是 **1.0** |
| 插件版本 `version` | 描述符，`x.y.z` | 给用户看的版本，详情页「插件自称的版本」 |
| 安装包版本 `versionName`（`versionCode`） | `app/build.gradle.kts` | 系统认的版本，详情页「安装包版本：0.1.0（1）」。两者对不上用户看得出来，建议保持一致 |

## 插件 API 的规则

- **major 不同就不兼容。** 描述符 `apiMajor` 不是 1，插件页显示「不兼容：API major 2 不兼容（宿主 1）」，不能批准、不能用。
- **minor 只追加。** 新 minor 只会加能力或在 AIDL 接口**末尾**加方法，已有方法的含义和顺序不变。
- 你的 `apiMinor` 比宿主新：宿主不认识的能力名记为「忽略、不可调用」，插件整体照样能用（自查命令会提醒）。
- 你的 `apiMinor` 不比宿主新，却写了宿主不认识的能力：「不兼容：未知能力：…」。
- 不认识的**权限**一律不兼容，不分 minor：宿主给不了的权限，插件就不会按它的预期工作。
- AIDL 接口以后加的方法，旧插件不认识：**调到时 Binder 不报错**，void 方法看着像成功了，有返回值的拿到 null 或 0
  （生成的代理代码不看调用结果，X12 读代码得出，没在设备上构造过）。所以新方法只能在双方都声明了够新的 minor 时才调，
  宿主和插件都别靠「调用失败」来发现对方不支持。
- v1.0 的接口里已经有 `openMoshSession`，所以现在所有插件都要实现它（不做 Mosh 就拒绝，见 contract.md）。

**插件这边怎么协商**：宿主在 `handshake(hostApiMajor, hostApiMinor, …)` 里告诉你它的版本。你需要某个 minor 才有的东西时：

- 宿主够新：用；
- 宿主太旧：要么不用那部分（降级），要么在握手里抛 `IllegalStateException`，话里写清楚要哪个版本。

样例演示了后一种：`./gradlew assembleRelease -PminHostMinor=1` 编出来的插件要求宿主 1.1，装到现在的 1.0 宿主上，
「连接测试」显示「连接失败：插件不接受宿主的 API 版本：本插件要求宿主 API 1.1 及以上，宿主是 1.0」（模拟器实测）。

## 发新版本时宿主怎么判

系统报告插件更新后，宿主整体重新核对一遍，不沿用旧判定（插件页开着时自动，没开着时下次打开时）：

| 你改了什么 | 用户那边 |
|---|---|
| 只改实现，描述符的能力不变 | 仍「可用」，不用重新批准；之前的连接断开（系统已经换掉旧进程） |
| 描述符多申请了能力 | 回到「待批准」，用户核对后重新批准，不会自动扩大 |
| 描述符多申请了权限 | **现在仍「可用」，不会回到待批准**：批准只绑能力、没绑权限，是宿主的已知缺口（计划在 X11 补）。别依赖它，加权限时提醒用户去看详情页 |
| `apiMajor` 变了 | 「不兼容」 |
| 换了签名密钥 | 系统不让覆盖安装；用户卸载后装新包，宿主判「已拒绝（换签）」，要撤销旧批准再重新核对 |
| `versionCode` 没加大 | 系统拒绝覆盖安装（`INSTALL_FAILED_VERSION_DOWNGRADE`）；版本号相同可以覆盖 |

## 签名密钥

- **一个插件一把密钥，一直用下去。** 宿主只认系统读出的**当前**签名证书，不认 Android 的签名轮换历史：你轮换密钥，宿主一样当成「换签」，用户要重新核对。
- 多张证书共同签名的插件暂时批准不了。
- 用 Android 调试证书签的插件只有开发版宿主认（仍要批准），正式版宿主一律拒收。

## 宿主的证书会变

插件里写死了信任哪张宿主证书（`xwshunHostSha256`），所以宿主换证书时插件要重新构建：

| 宿主 | 证书 |
|---|---|
| 某台电脑上编的 debug 包 | 那台电脑的 Android 调试证书。项目这台 Mac 上是 `499ff3abf2d0aeb386ce3b30da1c3a0fa3566d5d89b042bf279c0773f79d500f`；**换一台电脑编就不同** |
| 正式版 | 还没有：正式签名、应用名称、分发方式都等项目所有者定。到时候插件要信任正式证书（可以和 debug 证书逗号隔开一起写） |

## Android 版本和 ABI

| 项 | 情况 |
|---|---|
| 平台 | 只有 Android。iOS 没有这套插件机制 |
| 最低版本 | Android 7.0（API 24），和宿主一样。样例 `minSdk = 24` |
| 编译目标 | `compileSdk`、`targetSdk` 36 |
| ABI | 宿主只出 arm64-v8a。纯 Java 的插件（比如样例）不带原生库，跟着宿主能装的设备走；带原生库的插件至少要有 arm64-v8a，而且 `.so` 要按 16 KiB 对齐（新手机用 16 KiB 内存页，没对齐会加载失败），参考 `plugins/mosh` |
| 原生代码 | 只能随 APK 打包，由系统安装时解出。不要下载后执行，Android 10 起 App 也不能执行自己可写目录里的文件 |
