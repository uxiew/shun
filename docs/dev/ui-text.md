# 界面文字怎么写

改界面上的字之前看这份。说白了就一句：**页面上只放「这是什么」和「现在怎样」，「为什么」和「会怎样」点开才看。**

所有者 2026-10-24 定的：界面字太多，用功能提示代替常驻说明，细节交给项目文档。

## 怎么做

| 要写的东西 | 放哪里 | 例子 |
|---|---|---|
| 控件是什么 | 标题，尽量 8 个字以内 | 「敏感页面允许截屏」 |
| 现在是什么状态、选了什么 | 副标题，短词不要句子 | 「Tokyo Night」「未安装」「直连」 |
| 这个功能干嘛、为什么这样、有什么坑 | 标题旁的 ⓘ（`HintButton`），最多 3 句 | 滑动翻页在没开 mouse 的 tmux 里会翻出历史命令 |
| 原理、完整步骤、排错 | [使用手册](../user/README.md)，ⓘ 里只写结论 | 指纹变了怎么核对、怎么删旧指纹 |
| 动手那一刻必须知道的风险 | 确认框，不常驻页面 | 删了不能撤销、要往服务器发命令 |
| 出错了 | 出错的地方，一句：错在哪 + 怎么改 | 「必填」「端口要在 1–65535」 |

再加几条：

- **用户没动过就不报错。** 新建表单一打开就标红，等于骂人。点过保存之后才显示，改对了马上消失。
- **空状态只要一句标题 + 一个按钮。**
- **状态别和标题重复。** SSH 卡片写「可用 · SSH 终端」等于没写；正常可用就不写，只在不正常时写「未安装」。
- **实现细节不上界面。** Keystore、SHA-256、FLAG_SECURE、UID 这类词写手册和 [security.md](security.md)。
- **不能操作的卡片不要。** 只是告诉用户「我们很安全」的行，并进分组标题的 ⓘ。

## 硬上限

所有者 2026-10-31 定：UI 不要堆砌文字描述。`test/ui_rules_test.dart` 会查，超了测试失败，报出文件、行号和原文。

| 位置 | 最多 | 例子 |
|---|---|---|
| 输入框下面的提示（`helperText`） | 16 个汉字 | 「已加密保存，不能查看」 |
| 列表行的副标题（`subtitle`） | 16 个汉字 | 「到编辑器里重填密码或私钥」 |
| 页面上一段字（`LText`、`Text`、`catalogLine`） | 30 个汉字 | 「代理口令是明文发给代理的，SSH 保护不了。」 |

- 只数汉字，英文、数字、变量不算。
- 不算的地方：确认框（`AlertDialog`）、`SnackBar`、`Tooltip`、ⓘ 里的字，都是点了才看到或者只闪一下。
- 测试看不到的：先放进变量、经 `localized()` 拼出来的句子。这些靠自觉，按同样的上限写。

超了别改上限，按顺序问：

1. 用户不看这句会出错吗？不会就删掉，写进手册。
2. 只在动手那一刻要知道？放确认框。
3. 想了解才需要？放 ⓘ。
4. 确实要常驻又短不下来？写进测试文件末尾的 `_longTextAllowed`，注明原因。现在这张单子是空的。

## 表单间隔

上下相邻的输入框之间写 `const FormGap()`（`widgets/form_gap.dart`，20dp），别自己写 `SizedBox`。浮动标签往上占约 8dp，所以 12dp 看着还是挤；以前各页从 0 到 24 都有，所有者说的「不好看」就是这个。写错了 `test/ui_rules_test.dart` 会报出来。

## 用哪个组件

都在 `lib/presentation/widgets/hint.dart`：

- `HintButton(title:, message:)`：单独一个 ⓘ。点按区 48dp，读屏读作「「X」说明」。
- `HintTitle(title, hint:)`：标题 + ⓘ，给 `ListTile.title`、分组标题用。
- `HintSwitchTile(title:, hint:, value:, onChanged:)`：带 ⓘ 的开关行，外观和 `SwitchListTile` 一样。

**别把 ⓘ 塞进 `SwitchListTile`、`CheckboxListTile`。** 它们用 `MergeSemantics` 把整行合成一个读屏节点，
ⓘ 看得见、手指点得到，但 TalkBack 用户永远打不开它。开关用 `HintSwitchTile`，`test/hint_test.dart` 查了读屏上是两个节点。

## 改字时要连带改的

1. **英文**：新中文句子在 `lib/presentation/localization/translations_en.dart` 补英文，删掉的旧句子把英文也删了。
   多语言目前暂停（plan/v3/STATUS.md 10-24 那条）：补一条能让下面的测试过的英文就行，不用斟酌措辞、不用看英文排版。
   漏补会让 `test/localization_coverage_test.dart` 失败，报出文件、行号、原文和现在翻出来的样子。
   键怎么写，按运行时拿到的整句写：
   - **多行拼起来的句子，键写整句**：`'第一行，' '第二行。'` 运行时是一个字符串，逐行写两条键对不上。
   - **带变量的，键和英文都照抄源码里的变量**：源码 `'删除 ${entry.name}？'`，就写
     `r'删除 ${entry.name}？': r'Delete ${entry.name}?'`。运行时按模板对：中文部分逐字对上，
     变量处什么都行，值原样填进英文里同名的变量，英文里的语序可以和中文不同。
     有 `\n` 这类转义的别用 `r'…'`（raw 里的 `\n` 是两个字符，对不上换行），改写成 `'…\n\${error.message}'`。
   - 值里有中文又翻不出来时（用户起的中文主机名，或者模板太宽，比如「经$proxy」对上了「经代理连接失败」），
     这条模板不算对上，退回片段表。所以中文主机名所在的句子，英文界面仍可能半中半英。
   - 写进终端的提示（`terminal.showNotice`）不经过翻译，英文界面也是中文，测试里先排除了，见测试文件末尾。
   以前这个测试按行用正则找字面量，上面几种都查不出来，英文表里也就攒了一批逐行切开的键、
   `"topLeft' => '左上"` 这种怪键；10-24 改成按整句查以后清掉了，英文界面这些地方以前显示的是中文或
   「正in 切 to …」这样的半中半英。
2. **测试和设备脚本**：先 `grep -rF '原文' test integration_test tool`。有些脚本靠原文判断结果，
   比如发布检查看「这次运行建过的终端：N」——改了它 `tool/release-smoke.sh` 就过不了，看着像引擎没起来。
3. **使用手册**：从页面上挪走的说明，确认手册对应一节有；没有就补上。
   手册里写「点 X 旁边的 ⓘ」时，按钮和标题要对得上。
